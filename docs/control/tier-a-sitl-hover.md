## 3. ★★ 主结论：控制参考的棘轮（`u_ref` = 上一帧解）

### 3.1 现象

第 6 场（修复前）逐帧日志里 `u[3]`（偏航角速率指令）**单调上爬**：`0 ⟹ +4.696 rad/s`，EKF 帧机头累计转了 **13.6 圈**；位置那几条判据（高度、振荡、漂移）**全是 ✅** —— 因为位置参考是锚死的，机头自转在位置上只表现为小幅漂移。票面验收项"稳定悬停、无持续振荡"就是被这一条**实质挡住**的。

### 3.2 机理：`R·(u − u_ref)` 里的正反馈

代价的控制项罚的是**相对 `u_ref` 的偏差**（M6）。原来的 `u_ref` 取"上一帧解铺满时域"⟹

```
解出一点偏 → 下一帧的参考量跟着偏 → 偏差项不再罚它 → 再解出一点更偏的
```

这是一条**正反馈**，不是"参数没调好"。`offline-ocp.md` §4.4 离线就记过它：**静态参考 + 缺省 `u_ref`，`ω_y` 连解 12 次从 0.3225 爬到 1.3487 rad/s，"单调上爬、不收敛"**。

### 3.3 证据链：三处独立读数指向同一条

| 处 | 读数 | 出处 |
|---|---|---|
| 离线（ticket 04） | 状态钉死时 `ω_y` 连解 12 次爬到 1.3487 rad/s | `offline-ocp.md` §4.4 |
| 台架（ticket 09，零 ROS） | 给一条 `hold_offset_x = 10 m` 的任务，**第 9 拍**控制参考就爬到 `[11.80 N, 3.84, 0.0005, −0.0006]` —— 推力先撞 `T_max`、横滚撞 3.84 rad/s，**而偏航那一路在纯 +x 任务里也开始漏** | `test_垂直偏置不跟着解爬`（**旧名** `…解析前馈_不跟着解爬`，2026-09-29 被 20 号票改名；日志列 `u_ref0`） |
| SITL 闭环（真 PX4） | `u[3]` 爬到 +4.696 rad/s、13.6 圈 | 第 6 场 |

★ 台架那条是**最快的读数**（10 秒量级），而且它把"棘轮"从"只有飞了才知道"变成了**一条单测**。

### 3.4 落地：`hold_feedforward`，以及为什么它不算"悄悄退回悬停前馈"

`ocp.py` 里有一句硬规矩："`prediction=False` 时**必须**显式传 `u_ref` ……**不能**悄悄退回悬停前馈。"这句禁的是 `solve()` 的**缺省**路径静默退化（调用方忘了传就偷偷换成悬停配平，于是 M6 的持续角速率场景被无声压掉）。

本票走的是 M6 §3.2 的**第二行**——"调用方给的前馈（轨迹的解析前馈）"：

```python
# nmpc/node_core.py
def hold_feedforward(params, N):   # (N, NU)
    return np.tile([params.t_hover, 0.0, 0.0, 0.0], (N, 1))
```

我们的参考是**静止锚点**，它的解析前馈**就是** `[T_hover, 0, 0, 0]`（"参考自己就是模型的一条解"）—— 一行不差，而且是**显式**给的。判据直接取定义：把 `u_ref` 喂给模型，参考点不动（`test_保持前馈是参考自己的平衡点_也就是解析前馈的定义`，RK4 走一步仍等于它自己）。

⚠️ **将来接运动参考**（Phase 4 的轨迹）时，这个函数要按那条参考**自己的导数**算（加速度/角速度前馈），`hold_reference` 也要一起换；否则 M6 §3.3 的实测（持续角速率被压成 0）会原样复发。

### 4.1 代价分不清"参考机头"与它的镜像（解析 + 实测）

参考实现抄来的四元数段权重是 `(0.0, 0.1, 0.1, 0.1)` —— 那个 `qw = 0` `offline-ocp.md` §2 就标注过"照抄来的 …… 是'绕圈/自旋参考能不能跟住'的一个已知限制来源"。后果是精确的：

```
yaw_quat(ψ)     = [ cos(ψ/2), 0, 0, sin(ψ/2)]
yaw_quat(2π − ψ) = [−cos(ψ/2), 0, 0, sin(ψ/2)]     ← 只有 w 差一个符号
```

`w` **不被罚** ⟹ **代价在"参考机头"与"它的镜像"之间完全不区分**。实测（`test_the_cost_cannot_tell_the_reference_heading_from_its_mirror`，纯代价函数，无求解器）：

| 预测姿态 | 代价 |
|---|---|
| 与参考一致 | `0.000000` |
| **镜像机头**（相差 `2π − 2ψ` = 3.236 rad ≈ 185°） | **`0.000000`** |
| 同一条镜像轨迹、把 `qw` 罚成 0.1 | `9.528`（= `0.1 · (2cos(ψ/2))² · N`，ψ=1.618 的解析值，实测吻合；ticket 16 的默认已把它落地） |

⟹ "偏航误差"在代价里几乎**没有梯度**，回正力只能靠 `(q_x, q_y, q_z)` 那三项里的一点耦合给出来，比 `R_yaw = 5e2` 小四个量级。

### 4.2 收敛解下，偏航通道是**死的**（实测）

同一台机、同一条悬停参考、`u_ref` = 解析前馈，把求解**迭代到收敛**（20 次；在线是 1 次）：

| 状态误差 | 解出的 `ω_z` |
|---|---|
| 无误差 | `0.000000` |
| 纯偏航 **0.15 rad** | `−0.000007` |
| 纯偏航 **0.40 rad**（23°） | `−0.000019` |
| 纯倾斜 0.08 rad（roll 或 pitch） | `0.000000` |

⟹ 一个 **23° 的机头误差**只换来 `2×10⁻⁵ rad/s` 的角速率指令：按这个速度要 **20000 s** 才转回来。这就是"机头保持"只能靠"没人推它"的原因（第 8 场其实**没有**主动修机头，只是它也没漂）。

> ⚠️ 以上是 **A 档权重（`qw=0`）** 下的读数。ticket 16 之后默认权重已改，这一列数字**不再代表当前默认**，
> 但"偏航是死通道"这条结论**没被改掉**：同一探针（纯 0.4 rad 机头误差、迭代到收敛）在 landed 权重下
> 是 **`3.9e-4 rad/s`**（旧 A 组 `2e-5`，见 §4.4 的 ☠️）—— **仍在 1000 s 量级**，只是比原来快 20 倍。

### 4.3 在线（1 次迭代）时的倾斜→偏航泄漏，且**依赖 warm start**

同一条探针，只迭代 1 次（在线口径）：

| 状态误差 | 解出的 `u[3]` |
|---|---|
| 纯 roll **0.08 rad** | **−0.018378** |
| 纯 pitch 0.08 rad | `0.000000` |
| 纯偏航 0.15 / 0.40 rad | `−0.001117` / `−0.000022` |

★ 两点必须一起说清楚：
1. **这是单次迭代的产物**（收敛后它是 0）⟹ 它**不是**"模型错了"，而是 RTI 第一次迭代还没走到代价的谷底。
2. **它是 warm-start 相关的**：同一个误差、不同的迭代点会给出不同的读数（roll 与 pitch 的不对称就是这个原因 —— 探针里前一个用例的迭代点会被后一个继承）。这恰恰是第 3 节那条正反馈能把它**放大成 runaway** 的原因：一个 0.08 rad 的滚转误差在 1 次迭代下就交出 `0.018 rad/s`，而棘轮会把它**攒起来**。

⟹ **结论：把 §3 的棘轮拆掉之后，这条泄漏不再累积**（第 8 场机头全程 0.010 rad 即证）；但只要 `qw = 0` 还在，"机头被扰动之后回不来"这件事就一直在。

> ⚠️ 同为 **A 档权重（`qw=0`）** 下的读数；ticket 16 之后默认已改（见表下与 §4.4）。

## 5. D6：实测最坏求解耗时 ⟹ 频率

### 5.1 三场读数，以及**测量必须在空机上**

| 场 | 机器状态 | 冷启动（第 0 拍） | **稳态最坏** | 按稳态阶梯 |
|---|---|---|---|---|
| 6 | 空机 | 13.396 ms | 7.436 ms | 100 Hz |
| 7 | ⚠️ **机上同时跑着 pytest 与探针** | 10.590 ms | **11.297 ms** | 50 Hz |
| 8 | 空机 | 15.956 ms | **3.995 ms** | **100 Hz** |

★ 第 7 场是**我自己压出来的**：同一个二进制、同一条参考，只因为机上多了几个进程，稳态最坏就从 4 ms 涨到 11.3 ms。**这条比数字本身更重要**：D6 不是"这台机器能跑多快"的常数，而是"**在什么负载下**能跑多快"—— Phase 4 定实机频率时必须把 Jetson 上还跑着什么算进去。

### 5.2 冷启动落在 `warmup` 闸门里（硬判据）

第 0 拍是 acados 第一次进内存的一次性开销（本页 10.6–16.0 ms，**不是持续负载**）。判据不是"它多大"，而是"**它砸在哪一拍上**"：

- 第 0 拍 `fallback == "warmup"`（`warmup_cycles = 5` 拍）⟹ 那几拍**不发指令** ⟹ 冷启动的尾巴落在闸门里 ✅（第 7、8 场都过）。
- 这条**过不了**的话，D6 只能按全集最坏降档 —— 而那是被一次性开销决定的，不是被持续负载决定的。

### 5.3 结论

> **D6 = 100 Hz**（空机稳态最坏 **3.995 ms** ≤ 10 ms，余量 2.5×）。
> 附带条件两条：① 冷启动 15.956 ms 必须继续落在 `warmup` 闸门里（有专门判据 ⑦ 盯着）；② **机上别跑别的东西** —— 多几个进程就会把它推到 11.3 ms（50 Hz 档）。

逐拍间隔是另一个读数：第 8 场 p50 10.005 ms / p99 11.099 ms / 最坏 82.153 ms ⟹ 请求 100 Hz、实发 **99.8 Hz**。

## 7. 归因：票面那三条**盖不住**真实原因

票面写的是"若本档失败：归因到**模型 / 符号映射 / 中间件**三者之一"，并预先记了一句"**本轮证实这三条盖不住真实原因**"。实测下来正是如此 —— 逐条排除：

| 候选 | 结论 | 一手依据 |
|---|---|---|
| **模型** | 排除 | 同一台机、同一条参考，在**无 ROS 的闭环**里能悬停（推力 10.10→7.3575 N、位置误差→0、倾斜瞬态 0.09 rad，20 s）；运动学两条（`skew_symmetric` 右乘约定、`f_expl`）已逐行核过 |
| **符号映射** | 排除 | ⑨a 残差 `+0.202 rad`（那一场真值转了 −7.734 rad）、⑨b 中位数 `−0.031 rad` ⟹ 方向与换算都对 |
| **中间件** | 排除 | DUT 发帧 99.8 Hz、OFFBOARD 进得去、`age_*` 齐全、地板闸门没关过 |
| **代价 / 前馈（票面之外）** | ★ **真凶** | §3（棘轮 = 放大器，可在台架 10 秒内复现）+ §4（`qw = 0` 的镜像井 = 底层限制） |

**这一条要如实记下来**：本票在"三条之外"找到了原因，而且那两处**都是我们自己的约定**（一个在 `mpc_node`，一个在 `ocp` 的权重里）。

## 9. 本页能证明 / 不能证明

**能**：
- 在 z0 同构 SITL 上，节点能把飞机稳定悬停在 **EKF 帧的 1 m**（±0.15 m），**无持续振荡**（末段峰峰值 0.072 m），**机头不转**（全程 0.010 rad）。
- **真 PX4** 上的符号映射与换算都**方向正确** —— ★ 依据是**第 5 场**（飞机真在转：真值
  `−7.734 rad` vs 指令 `+7.936 rad`，反了会给出 −15.7）与 ⑨b（换算，第 8 场中位数
  `−0.082 rad`）；⚠️ **不是**第 8 场那条 ⑨a —— 那一场 `|∫u[3]dt| = 0.002 rad`，判据
  **没有判别力**（见 §6 的 ⚠️⚠️）。
- **D6 = 100 Hz**（空机稳态最坏 3.995 ms），且冷启动落在 `warmup` 闸门里。
- 自转 runaway 的**机理**：控制参考的棘轮（正反馈）+ `qw = 0` 的镜像井（无回正力）—— 两者**均已修**：棘轮在 `mpc_node`（`hold_feedforward`），镜像井按 **ticket 16** 在**默认权重**上把 `qw` 从 0 改成 0.1（`qatt` 同时 0.1→2.0；解析可复核，镜像代价实测见 `test_ocp_cost_ref.py`；☠️ 同票曾把 `R_yaw` 降到 50、当天撤回；闭环那两列的复现状态见 §4.4 的 ⚠️）。

**不能**（**别越界引用**）：
- **不能说"控制器把飞机稳在真值 1 m"**：判据③判在 EKF 帧，而真值帧的抬升在 0.66–0.99 m 之间**逐场漂**（那部分是这台 SITL 的估计器误差：助航自反馈、0.34–1.0 m 量级）。要判"真值 1 m"得另有真值助航的档位，本档没有。
- **不能说偏航通道"能用"**：★ 本页实测（§4.2）是 **A 档权重（`qw=0`）** 下的读数，那时它是**死的**（23° 误差 ⟹ `2×10⁻⁵ rad/s`）。ticket 16 已在**默认权重**上拆掉这个结构的一半（镜像井消掉：`qw=0.1`、`qatt=2.0`；`R_yaw` 不动），但那 20 倍只是把 23° 误差的稳态 `ω_z` 从 `2e-5` 抬到 `3.9e-4 rad/s` —— **仍要 ~1000 s**，"改权重 ⟹ 机头真能回来"**不成立**，而"权重够不够"**只有 A 档 SITL 复飞能回答**（ticket 16 验收项 3 **未飞**；该票 2026-10-09 已按操作者裁定收口为 `done`，"机头回不来"的结论由 [ticket 25](../../.scratch/phase2/issues/25-yaw-channel-authority.md) 给出）。第 8 场机头没漂，是"没人推它"，不是"它修回来了"。
- **不能说 100 Hz 是无条件安全的**：第 7 场（机上多跑几个进程）稳态最坏就是 11.297 ms（⟹ 50 Hz 档）。D6 附带"机上别跑别的东西"这个条件。
- **不能把这个被控对象上的频率数字直接搬到实机**：SIH 的动力学比实机"干净"，Phase 4 必须重测（本页给的是**方法**与数量级）。

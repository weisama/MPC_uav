## 0. 先读这一段：三个"一句话"

1. **`ω` 不是状态**（10 状态，不是 13）。姿态运动学直接吃角速率输入 —— 即"内环完美跟踪"假设。
   这是**刻意的工程化简**（参考实现已被实飞验证），升级到 13 状态的方向与 `Sun2022`/`Foehn2022`
   一致，但不是本阶段的事（§2.1）。
2. **单次 RTI 迭代的解不是"最优解"**，是"从上一帧迭代点走一步"。⟹ 第一帧必须热身、
   测试必须分开"首帧"与"稳态"（§4.1）—— 这条是本票最能误导人的地方。
3. **`SQP_RTI` 下的三条原厂读数不可信**（残差恒为 0、`alpha` 直接抛异常、`get_cost()` 与返回轨迹
   的代价差 96 倍）⟹ 健康度改用自算量（§4.3）。
4. **缺省 `u_ref`（上一帧解平移一拍）在静态参考下不收敛**：`+x 0.5 m` 时 ω_y 连解 12 次
   从 0.32 爬到 **1.35 rad/s**（§4.4）。在线能不能走缺省这条路，只有 SITL 能回答。

## 2. 求解器配置（求解器照抄参考实现；**代价权重是 z0 自己的**）

`SQP_RTI` + `PARTIAL_CONDENSING_HPIPM` + `GAUSS_NEWTON` + `ERK`（4 级 3 步）、**每控制周期一次迭代**、
`N = 50` / `Tf = 1.0 s`（内部步长 20 ms）—— 这一层照抄参考实现。代价 = `NONLINEAR_LS`，`y = [x; u]`：

`q_diag = [1e1 ×6, 0.1, 2.0, 2.0, 2.0]`、`q_e_diag = [3e2 ×3, 1e2 ×3, 0 ×4]`、
`r_diag = [1e1, 5e2, 5e2, 5e2]`（M1–M4/M6 只动下面 §3 那几处；权重见下）。

★★ **2026-09-29（ticket 16，操作者裁定）**：**与参考实现不同的只剩 `q_diag` 的四元数段**
—— 参考实现是 `(0.0, 0.1, 0.1, 0.1)`、z0 改为 `(0.1, 2.0, 2.0, 2.0)`；`r_diag` 三轴仍同为 `5e2`。

### 3.1 推力上限是怎么导出的（自洽性是一条硬约束）

`t_max = m·g / hover_thrust` —— **只有 `hover_thrust` 是自由量**。理由：PX4 的 offboard 分支对
`thrust_body` **不做任何悬停油门重标定、原样透传**（第一手：`MulticopterRateControl.cpp:182`），
所以"模型里的 `hover_thrust`"与"归一化常数 `1/T_max`"**描述同一个物理量**；
两者不一致就是一个**静默的推力增益错误**。回填口 = [ticket 10](../../.scratch/phase2/issues/10-param-measure-backfill.md)
（P1 出数后**只改 `hover_thrust` 一个字段**，`t_max` 自动跟着变）。

⚠️ 它与 PX4 参数 `MPC_THR_HOVER`（写的是 0.5）**不是一回事**，别混。

### 3.2 `u_ref` 的取法（M6 的约定，写死在这里，不留实现时临时定）

| 调用方式 | `u_ref` 取什么 | 用在哪 |
|---|---|---|
| `solve(x0, x_ref)` | **上一帧解平移一拍**（末尾重复）；本实例第一次调用用悬停前馈 `[T_hover,0,0,0]` | 在线闭环的缺省路径 |
| `solve(x0, x_ref, u_ref)` | 调用方给的前馈（轨迹的解析前馈，或上一帧解） | 节点有参考轨迹时走这条 |
| `solve(..., prediction=False)` | **必须显式给** —— 不读轨迹就没有"上一帧解"，缺省时**报错**而不是悄悄退回悬停前馈 | 只要第一拍、省一次读回的快速路径 |

最后一行是**刻意选的严格**：悄悄退回悬停前馈会让 `u_ref` 永远停在 `[T_hover,0,0,0]`，
持续角速率照样被压 —— 那就是 M6 要修的病换了个壳（静默失败）。

### 3.3 M6 的可判定形式（同一参考、两组 `u_ref`）

偏航以 4.0 rad/s 匀速转，参考本身就是这条轨迹（读数 = ticket 16 落地权重下重算）：

| `u_ref` | 解出的 `ω_z` | 含义 |
|---|---|---|
| 前馈（`ω_z = 4.0`） | **4.0000** | 跟住了 |
| `0`（参考实现的口径：`yref` 控制段全填 0） | **0.0014** | 持续角速率被强烈抑制（只是 4.0 的 0.035%），但**不再是恰好 0** |

参考实现把 `yref` 的控制段全填 0 ⟹ 等价于罚 `‖ω‖²` ⟹ 一切需要**持续**角速率的场景
（绕圈、定点自旋）都会被系统性拉向零。这条对照就是"改对了"的判据，两条都在
`test_ocp_cost_ref.py` 里。

⚠️ **`u_ref = 0` 那一格的残值变过两次，别引混**（同一用例、同一 `u_ref=0`、只换权重）：
`qw=0, qatt=0.1, R_yaw=5e2`（旧 A）⟹ **0.000070**；同日撤回的 `R_yaw=50` ⟹ **0.013925**；
现在落地的一组（`qw=0.1, qatt=2.0, R_yaw=5e2`）⟹ **0.001397**。
⟹ 抬这个残值的主力是 **`qatt`（姿态矢量部 ×20）**，`R_yaw` 那一项把它又放大了一个量级。
判据（`abs(ω_z) < 0.05`）三档都成立，且都 ≪ 4.0 ⟹"持续角速率被压制"这个结论不变。
⚠️ 但它**不等于**"偏航通道已经好用"：纯 0.4 rad 机头误差下的稳态 `ωz` 只有 3.9e-4 rad/s
（见 [`tier-a-sitl-hover.md`](tier-a-sitl-hover.md) §4 的复算）—— 镜像井修掉了，**回正权威仍然弱**。

## 4. 三条实测出来的行为（都会误导人，所以单列）

### 4.1 单次 RTI 迭代：首帧不能用，稳态有偏置

实测（目标 +x 10 m，全新实例）：

| 第几次 solve | `ω_y` | `F` |
|---|---|---|
| 第 0 次 | **0.0000** | 7.8111 ← 跟悬停一模一样，纯初始迭代点 |
| 第 1 次 | 3.8400（打满） | 7.8111 |
| 第 2–11 次 | 3.8400 | 0 → 7.92 → 2.43 → 8.66 → … → 11.47（**一直在晃**） |

两个后果，别踩：

1. **节点侧不能信第一拍**（在线时上一帧的解就是起点，所以闭环从第二个周期起才有意义 ——
   但"要不要丢弃/限制第一拍"归 ticket 06/07 定，本票只给证据）。
2. **测试必须先热身**（`test/conftest.py` 的 `solve_warm`，10 次）。拿第 0 次的结果去断言，
   测到的是 acados 的出厂初值，不是我们的模型/代价/约束。

**还有一个稳态偏置**：悬停参考 + `u_ref = 0` 时 `F` 停在 **7.8111 N**（比 `m·g = 7.3575` 高 6.16 %），
连解 12 次不动。它不是冷启动 —— `SQP_RTI` 单步迭代的解是**迭代映射的不动点**，不是最优解。
`u_ref = 0` 把代价谷底挪到"零推力"，稳态就带着这个偏置。所以测试里那条断言给的是**松带宽**
（≤10 %）而不是"精确等于"；要精确配平就走**前馈一致**的那条（实测精确 `7.3575`，代价 ~1e-31）。

### 4.2 约束打满时，只有角速率立刻贴住

实测 +x 10 m：`ω_y` **第 1 次就贴住 3.84 并保持**，而 `F` 一直在晃（上表）。
所以测试只断言"角速率饱和 + 不越界"，**不断言推力收敛** —— 后者本来就不成立。

★ 顺带纠正一处想当然（原 `phase2-implementation.md` §4 S3 的表写的"目标 +x 10 m ⟹ F 打满 T_max"）：

| 目标 | `ω_y` | `F` |
|---|---|---|
| `[10, 0, 0]`（纯水平远） | 3.8400 | **11.4044** ← **没**顶到上限（11.8003） |
| `[10, 0, 5]` / `[10, 0, 10]`（又远又高） | 3.8400 | **11.8003** ← 顶住 |
| `[0, 0, 10]`（只要高度） | 0.0378 | 11.8003 ← 顶住 |
| `[0, 0, −5]`（要下降） | 0 | **0** ← 落到非负下界 |

纯水平只需倾斜、垂直分量仍≈悬停，所以**不会**顶推力上限。文档那一行已按实测改写。

### 4.3 `SQP_RTI` 下三条原厂读数不可信（都有源码/实测双证据）

| 读数 | 实测 | 旁证 / 怎么办 |
|---|---|---|
| `get_stats("residuals")` | 恒为**全 0** | 不跑 `eval_cost` 就没人填它；本包改用自算的 `u_bound_violation` / `quat_norm_drift` |
| `get_stats("alpha")` | 抛 `ValueError: alpha values are not available for SQP_RTI` | 不读 |
| `solver.get_cost()` | 同一次求解：读数 **516.07**，按代价定义重算 **49501.7**（**96 倍**）；单看第一步就已 1220.25 ⟹ 也不是"只算了某一段" | `ocp_nlp_get_cost_value_from_submodules`（`ocp_nlp_common.c:3908`）在 `ocp_nlp_sqp_rti.c` 里**没有调用点**。本包**自己算** `info.cost`，`info.cost_acados` 只把原样读数留证 |

代价自算的实现是 `OcpConfig.cost`，被一条**朴素双重循环**独立复核过（`test_ocp_cost_ref.py`）。
实测代价：**median 0.067 / mean 0.073 / max 0.409 ms**（2026-09-28，绑核 cpu4，1000 次，
`x_ref` 用 +x 0.5 m 的常数参考）—— 相对于 3.9 ms 的周期可忽略。

`quat_norm_drift` 的实测量级（模型没有 `|q| = 1` 的约束）：ω 打满 3.84 rad/s 持续 1 s 时
**1.0e-08**；悬停 1.8e-15；`step_rk4` 以 20 ms 步长连续滚 30 s 才到 6.7e-08。
⟹ 正常时它就该接近 0，**涨起来才是异常**（轨迹发散）。它**不进** `degraded`（是模型精度的指示灯）。

### 4.4 ★ 缺省 `u_ref` 在**静态参考**下不收敛（在线必读）

§3.2 写的缺省约定是"上一帧解平移一拍"。把状态**钉死**在悬停、参考恒定偏 +x 0.5 m，
**不给** `u_ref`，连解 12 次（实测 2026-09-28）：

| 第几次 | 0 | 1 | 2 | 3 | 5 | 8 | 11 |
|---|---|---|---|---|---|---|---|
| `ω_y` | 0.0000 | 0.3225 | 0.5085 | 0.6598 | 0.9035 | 1.1667 | **1.3487** |
| `F` | 7.3575 | 7.3575 | 7.2199 | 7.0638 | 6.8396 | 6.7965 | 7.0191 |

**单调上爬、不收敛**（对照：同一条参考给 `u_ref = 0`，第 2 次起就稳在 +0.3239）。
机理：`u_ref` = 上一帧的解 ⟹ 它对**自己的前馈**构成正反馈 —— 解出一点倾斜，下一帧的参考量
就多认一点倾斜。第 0 次的 0 不是"稳态为 0"，那只是初始迭代点（§4.1）。

⚠️ **这不等于"在线会发散"，别越界引用**：本用例把状态钉死，误差永远不消；闭环里状态会动、
误差会减，反馈会自己收敛。**"在线能不能走缺省这条路"只有 SITL 闭环能回答** —— 归 ticket 06/07，
并按 ticket 11 复核。

✅ **2026-09-28 闭环答案（ticket 09，SITL 真 PX4，z0 同构被控对象）：在线走缺省 = 会 runaway。**
三处一致的证据链：① 本节离线表（`ω_y` 0.3225 → 1.3487）；② `mpc_node` 的假 PX4 夹具
（纯 +x 任务，第 9 拍控制参考就爬到 `[11.80 N, 3.84, 0.0005, −0.0006]` —— 推力那一路先撞
`T_max`，**偏航那一路也开始漏**）；③ SITL 真闭环（`u[3]` 爬到 **+4.696 rad/s**、机头累计
**13.6 圈**）。机理不是"缺省本身不稳定"，而是**闭环里出现了外生的小姿态扰动**（真被控对象 +
EKF 的倾斜失配），棘轮把它**单调放大**。⟹ **在线节点改成喂参考自己的解析前馈**

## 5. 最坏耗时（P3 ⟹ D6）

命令与前提：

```bash
export ACADOS_SOURCE_DIR=$HOME/acados
export LD_LIBRARY_PATH=$ACADOS_SOURCE_DIR/lib:$LD_LIBRARY_PATH
python3 -m nmpc.timing --runs 1000 --cpu 4
```

**表 = 其中一轮**（2026-09-28，`load1 = 1.34 / 6 核`）：

| 列 | 管什么 | min | median | p99 | **max** |
|---|---|---|---|---|---|
| 整周期**墙钟** | **能不能闭环**（D6 问的是这个） | 3.607 | 3.945 | 4.675 | **56.143 ms** ⚠️ |
| **acados 自报** `time_tot` | **求解器有没有退化** | 2.394 | **2.682** | 3.423 | **3.447 ms** |

**三轮复测，本页与 `README.md` 引用的数都从这张表取**（同一命令，同一天）：

| 轮 | acados 自报 max | 墙钟 median | 墙钟 max |
|---|---|---|---|
| ①（上表） | 3.447 ms | 3.945 | **56.143** |
| ② | **3.584 ms** | 3.914 | 54.083 |
| ③ | 3.447 ms | 3.945 | — |

⟹ **凡"3.58 ms"处指三轮里的最大值 3.584，凡"3.4 ms"处指本轮上表值** —— 两者说的是同一件
事（求解器最坏 3.4–3.6 ms），此前没有写清是哪一轮，现补此表。

**两列必须分开看，理由是实测的**：墙钟那个 56 ms 的尖峰，**同一拍的 acados 自报只有 3.4 ms** ——
差出来的 52.7 ms 是这段 Python 被调度出去过（1000 次里 **1 次**）。它不是求解开销。

**两条前提，缺了读数就是假的**（都是第一手）：

1. **绑核**（`--cpu 4`）：实测中位数 −29 %、最大值 −33 %。
2. **机器空载**：本机有并行会话，别人一编译（PX4 SITL 之类），同一命令的 max 从 4.4 ms
   变成 23.4 ms，判定行会翻成"100 Hz 不够"的**假**结论。脚本自己报 `load1` 并在有负载时打失真标记。

**⟹ D6 判定**：按 `phase2-implementation.md` §3.1 的线，**判的是"求解器"那一列**
（最坏 ≤10 ms 保 100 Hz）：**纯求解 3.4–3.6 ms ⟹ 保 100 Hz**，余量 2.8×；
整周期 median 3.9 ms / p99 4.7 ms。

⚠️ **这条判定不覆盖墙钟那一列，别把话说满**：D6 的规则原文是"最坏 > 20 ms 就停下优化"，
而**墙钟 max = 54–56 ms 恰好越线**。之所以仍判"保 100 Hz"，是因为那 52 ms 是**被调度出去**、
不是求解开销（同拍自报 3.4 ms）——**这是一个有理由的例外，不是一个满足了的判据**。
所以下面这条遗留条件不是免责声明，是**未完成的验收项**。

⚠️ **遗留条件（不许掩盖）**：整周期墙钟出现过 1/1000 次的 52–56 ms 抢占。要真的闭环在 100 Hz 上，
**节点侧得处理这个尾**（绑核 / 线程优先级 —— 归 ticket 06/07 定，本票只给数据）。
把这两列合成一个数就会得出错误结论：合成数的读法要么"停下优化"（不必要），要么
"没问题"（掩盖了尾延迟）。

★ 本票量的是**离线**（无 ROS、无 SITL、无话题收发）。SITL 闭环下的**整周期**（含订阅/发布、
状态转换、日志）尚未测 ⟹ 该项留给 seam 3（ticket 11）复核（★ **2026-09-29 已复核，见下**）。
★ **2026-09-29 复核（ticket 11）**：SITL 闭环 100 Hz 下，逐拍**求解耗时**稳态最坏 **5.652 ms**、实发 **99.5–99.6 Hz**（p50 10.0 ms、p99 11.4–11.9 ms）；**整周期墙钟没有单独分项**。见 [`phase2-implementation.md`](phase2-implementation.md) §5 与 [`tier-b-sitl-seam3.md`](tier-b-sitl-seam3.md) §9。

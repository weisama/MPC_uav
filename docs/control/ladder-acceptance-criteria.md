## 0. 这一页怎么读

**为什么必须先写定**：一台刚飞完的机器 + 一个想继续往下走的我，是最不适合做"这级算不算过"这个
判断的组合。判据在**转桨之前**就是死的，之后的观测只能往里填数，不能改线。

三条读法：

1. **每一级的每一个阈值都是一个数**。出现"稳定"、"正常"、"看着还行"就是写漏了。
2. **每一级的"过不了"都指向五条归因环之一**（§3）。写"再调调参数"等于没写。
3. ★★ **口径先于阈值**。阶梯 4 的线来自 (A) 级的实飞读数，而"A 级的读数"这个词只有
   在**口径写死**之后才是一个数 —— 见 §2。口径变了，线就变了。

**本表管不到什么**（写在最前面，免得它被当成一份不该有的保证）：
它管**怎么判**，不管**怎么飞**。起链、起录、装桨、报备、现场"还能不能继续飞"的裁定，
全是操作者手上的活（票 09 / 10 的 `ready-for-human` 理由就是这一条）。

**冻结的边界** = 本页 §1–§5 的所有阈值。**参数**的冻结边界在
[`first-flight-config.md`](first-flight-config.md) §0，两者不重叠。

### 1.1 阶梯 1 —— 拆桨，目视电机转速差方向

**为什么这一级最便宜也最不可跳过**：符号错误在天上表现为「**直接朝错的方向加速**」，
在这里表现为「某个电机转速差方向不对」。前者摔机，后者只是多拧一次桨。
★ 用一句话概括它的地位：**(C) 级是一条全新的控制通路 —— 它的增益符号必须先量出来**，
而这一级就是那条"量符号"的实验（票 09 的原话是"归因到符号映射表并修正后，本级的判据从头重新跑一遍"）。

**程序**：用 [`offboard_smoke.py`](../../src/nmpc/nmpc/offboard_smoke.py)（**没有模型、没有代价、没有约束**
—— 它错了就只可能是中间件、符号或归一化错），桨叶全部拆掉，
逐轴逐符号各给一段，`--phases` 的第三段是**悬停推力的倍数**（不是归一化推力），第四段是 **FLU** 角速率：

```bash
# 每一轴分别给 + 与 −，各 3 s；推力取 1.0（= 悬停倍率），让转速差叠在一个明确的基准上。
# ★ 四个字段是**一个** argv（名字:时长:悬停倍数:ωx,ωy,ωz），中间不能有空格：
ros2 run nmpc offboard_smoke.py \
  --phases roll+:3:1.0:+1.0,0,0 --phases roll-:3:1.0:-1.0,0,0
# y / z 两轴同理，一次只动一根轴
```

**角速率幅值取 `±1.0 rad/s`**（本表定稿值）。理由：桨拆掉之后**安全不再是约束**，
唯一约束是**可观测性** —— 1.0 rad/s（57 °/s）远在飞控自己的上限之内
（`docs/assets/z0.params` 现读：`MC_ROLLRATE_MAX = MC_PITCHRATE_MAX = 220 °/s`、
`MC_YAWRATE_MAX = 360 °/s`），在悬停油门上叠出的转速差肉眼可辨，
而飞机因为没桨不会有任何位移。

**预期方向（`ω` 是 FLU，逐条从第一手推出）**：

| 操作者发的 `ω_flu` | smoke 节点实际发出的 PX4 字段（[`sign-map.md`](sign-map.md) §2） | **物理预期：哪两个加速、哪两个减速** |
|---|---|---|
| `(+, 0, 0)` | `roll_rate = +` | **左侧**（前左 + 后左）**加速**，右侧（前右 + 后右）减速 |
| `(0, +, 0)` | `pitch_rate = −` | **后侧**（左后 + 右后）**加速**，前侧（左前 + 右前）减速 |
| `(0, 0, +)` | `yaw_rate = −` | **对角 {前左, 后右} 加速**，对角 {前右, 后左} 减速 |

**这三行是怎么来的**（每一行都能自己复算，不是"看着对"）：

- **转子在哪**：`docs/assets/z0.params` 现读（`CA_AIRFRAME = 0` 多旋翼、`CA_ROTOR_COUNT = 4`）——
  `CA_ROTOR0_PX/PY = +0.15/+0.15`、`1 = −/−`、`2 = +/−`、`3 = −/+`，
  `CA_ROTORn_AZ = −1.0`（推力沿机体 −z ⟹ 机体轴是 FRD，x 前 / y 右）。
  ⟹ 0 = **前右**、1 = **后左**、2 = **前左**、3 = **后右**。
  ⚠️ 位置数值 `0.15` 与真值 `±0.0537401` 差 **2.79×**，但那是**纯均匀缩放**、分配器会约掉
  （F3），**角标与角点的对应关系不受影响**。
- **升降/俯仰**：`τ = r × F`，`r = (PX, PY, 0)`、`F = (0, 0, −T)` ⟹
  `τ_x = −PY·T`、`τ_y = +PX·T`。
  `ω_x > 0` = **右沉**（左翼抬）⟹ 要 `τ_x > 0` ⟹ **抬 `PY < 0` 侧**（左）；
  `ω_y > 0` = **低头 / 机头下俯** ⟹ 要 `τ_y < 0` ⟹ **抬 `PX < 0` 侧**（后）。
  换成 PX4 字段（`roll_rate = +ω_x`、`pitch_rate = −ω_y`，见 §2）就是：
  `roll_rate > 0` ⟹ 抬 `PY < 0` 侧（= 上表第 1 行）、
  `pitch_rate > 0` ⟹ 抬 `PX > 0` 侧（= 上表第 2 行）。
- **偏航**：`CA_ROTOR0/1_KM = +0.05`（`2/3 = −0.05`），PX4 的定义是
  **`Torque = KM × Thrust`，正值 = CCW**（`~/refs/px4-v1.14.3-build/src/modules/control_allocator/module.yaml:207-221`，
  第一手）⟹ `τ_z = Σ KMᵢ·Tᵢ`。配 `yaw_rate < 0` 得"`KM = −` 的那一对加速" = **{前左, 后右}**。
- **FLU → PX4 字段**取自 [`sign-map.md`](sign-map.md) §2 的权威表，本页**不另推一遍**。

⚠️ **一处必须在现场落实的不确定**：PX4 的输出序号 → 物理接口的映射由
`PWM_MAIN_FUNC1..4 = 103, 102, 101, 104` 定（[`params-changes.md`](../reference/params-changes.md) **D7**，是**刻意改过的非默认电机序**），
而 D7 自己就写着"**仍需现场确认"物理口→机体角"的完整映射**"。⟹ 上表是**按角点**写的
（前左 / 前右 / 后左 / 后右），现场要确认的正是"哪个角是哪个物理口"。
**这一步不通过就停** —— 它属于"符号映射"这条归因环，不属于"接线随便试试"。

**停止规则**：任一轴任一符号与上表不符 ⟹ **停，不进下一级**；修完符号映射表之后
**本级的六段从头重新跑一遍**（不是"改完接着往下走"—— 改完之后其余五段的有效性也一并作废了）。

### 1.2 阶梯 2 —— 系绳 + 离地 20 cm，开环只给悬停推力

**驱动方式**：开环（`offboard_smoke.py`，`ω = 0`，不给任何轨迹）。仍不接 MPC（模型预测控制）节点 ——
本级的目的是把**推力这一条通路**单独量出来。

| # | 判据 | 阈值 | 不过 ⟹ 归因到 |
|---|---|---|---|
| **①** | **方向** | `thrust_scale = 1.0` 段 **3 s 内离地**（高度 > 0.05 m） | 符号映射 / 归一化 / 推力偏低 |
| **②** | **量级（夹逼）** | **先 `1.05` 再 `0.95`，各 1.0 s**：`1.05` 段 `Δh ≥ +0.03 m`、`0.95` 段 `Δh ≤ −0.03 m` | 悬停油门标定（[ticket 02](../../.scratch/phase4/issues/02-hover-thrust-backfill.md)） |
| **③** | **无异常振荡** | 全程**角速度 RMS ≤ 1.0 rad/s** | 角速率增益 |
| **④** | **不砸地** | 全程高度 ≥ 0，且系绳限位 ≤ 0.20 m | — |

**一段到底的跑法**（`--mass` 必须填**称出来的全重**，不是默认值）：

```bash
ros2 run nmpc offboard_smoke.py --mass <全重kg> \
  --phases lift:3:1.0:0,0,0 --phases up:1.0:1.05:0,0,0 --phases down:1.0:0.95:0,0,0
```

**记法**：令 **`κ = 我们发的推力 ÷ 真正悬停所需的推力`**（`thrust_scale = 1.0` 时）。
`κ = 1` 是标定完美；上面三条判据合起来放行的是 **`κ ∈ [1, 1.046]`**（怎么来的见下）。

**为什么用"夹逼"而不是直接比高度**：开环悬停没有反馈，推力偏差会被**二次积分**
（`Δh = ½(κ·scale − 1)·g·t²`）。⟹ 在 20 cm 的系绳里，
`|κ − 1| = 1%` 只够飘 **2.0 s**、`0.1%` 才够 6.4 s。
**用"能稳多久"当判据等于在判一个小数点后第四位**，而夹逼把它换成一个**符号比较**。

★ **段长定 1.0 s，是算出来的，不是拍的**：`|κ−1| = 5%` 时竖直加速度 0.49 m/s²，
从 20 cm 起 **0.90 s 就触地** —— 所以"每段 2 s"在 20 cm 里**物理上做不到**。
**顺序也有理由**：先 `1.05`（上飘，系绳兜着，不会撞地）再 `0.95`（下坠，一触地就切走、
该段作废重来）。

★ **放行带的两个边界都是算出来的**（`t = 1.0 s`、`g = 9.81`、下限 `|Δh| ≥ 0.03 m`）：

- **上界 1.046** 来自 `0.95` 段：`0.95κ ≤ 1 − 2×0.03/9.81 = 0.99388` ⟹ `κ ≤ 1.046`；
- **下界 1.000** 来自判据 ①（离地）：`κ ≥ 1`。

★★ **下界为什么卡在 1，而不是对称的 0.958**：因为**"离地"这条方向判据在物理上是单边的** ——
推力朝下时飞机**不会穿到地下**，它只是不起来。所以"高度"这个观测分得开 `κ = −1` 与 `κ = +1`，
但分不开 `κ = 0.98` 与 `κ = 1.00`。**这是物理决定的，不是本表选保守**。
（`0.958` 是 `1.05` 段单独给的下界，被 ① 覆盖掉了；写在这里是为了让边界可复算。）

★ **① 不过时的分诊**（把"符号错"和"推力偏低"分开，这一步别省）：

| 现象 | 判 |
|---|---|
| `1.0` 段不起飞 **且** `1.05` 段也不上飘 | **符号 / 归一化错** —— 停，回 §5.2 的 **R1** |
| `1.0` 段不起飞 **但** `1.05` 段上飘（只差一点点） | **推力偏低**（`κ` 略 < 1）—— 归**推力标定**，不是符号错 |

★ **精度到这儿就够，这是刻意的**：更细的定标归**阶梯 3** —— 那里有反馈、能开长窗口，
而这里一旦偏了就打到系绳。**别在开环这级加时间窗去凑精度。**

★★ **"悬停倍数"乘的是什么，必须先说清 —— 否则这条判据永远不会红**：
`offboard_smoke.py` 里那个基准是 **`hover_n = mass × g`**，`mass` 来自 `--mass`
（[`commands.py`](../../src/nmpc/nmpc/commands.py) 的 `hover_force_n`，默认 **0.75 kg** ⟹ **7.3575 N**）。
⟹ `thrust_scale = 1.0` 的含义是"**我们认为**需要 7.3575 N 才悬停"，
**不是"飞控会正好悬停"**。`κ − 1` 就是这句话的误差，来源有三处、全都归"推力标定"：

1. **`--mass` ≠ 真实全重**（换电池、加桨罩、线缆）—— 这一条要求**现场把称出来的全重填进 `--mass`**；
2. **归一的基准** `--t-max`（默认 11.8 N，config 页 **N4** 的 `f_max`）；
3. **飞控把 `thrust_body` 变成电机转速那条映射**（config 页 F6 的 `MPC_THR_HOVER`，
   状态是 ⬜ **待写入**、**人的动作**）。

⚠️ 第 3 条是**起飞前的先决条件**：F6 没写下去就做阶梯 2，测的是"两个错叠在一起"。
把这三条按 §6 的记录格式写进"条件"栏 —— 判据 ① ② 给出的 `κ` 是**三者之和**，
归属哪一条要看这三条各自改过什么（**不许就地调增益**）。

**③ 的对照量级**（第一手，出处 [`tools/tau-analysis/README.md`](../../tools/tau-analysis/README.md) 的「读分段」节）：
z0 上「飞机只是被人挪动」的一段角速度 RMS 是 **0.005 rad/s**、真实飞行的一段是 **0.36 rad/s**。
⟹ **1.0 rad/s 是"明显在抖"的量级，不是"在飞"的量级**，用它区分"异常振荡"与"正常机动"。

**④ 的 20 cm** 是 spec 定的系绳高度，不是本表算出来的。系绳**只限上界**：
下界（高度 ≥ 0）是"没砸地"，不是"没下沉一点"。

### 1.3 阶梯 3 —— 系绳闭环悬停 30 s

**驱动方式**：`mpc_node.py` 闭环，`reference_source = hold`（悬停锚点，不依赖上游轨迹），
按 config 页 §2 的参数（`tau_s = 0` 起步、`rate_hz = 100`）。

| # | 判据 | 阈值 | 不过 ⟹ 归因到 |
|---|---|---|---|
| **①** | **水平** | `AUTO/TRACK` 窗内水平误差**均值 ≤ 0.15 m**（Phase 1 §5.3 的 15 cm 线；见下方的⚠️） | 角速率增益 / τ |
| **②** | **不持续漂移** | 末 **10 s** 水平位移 ≤ **0.20 m**（= 漂移率 ≤ 0.02 m/s） | 悬停油门标定 / 稳态偏差 |
| **③** | **高度带** | 窗内 `\|e_z\|` 均值 ≤ **0.10 m**、最大 ≤ **0.20 m** | 悬停油门标定 |
| **④** | **求解无持续退化** | 最坏求解耗时 **≤ 10 ms**（config 页 N1 的保 100 Hz 线）；求解失败**不出现连续 ≥ `FALLBACK_HOLD_FRAMES`(=10) 拍**；失败总占比 ≤ **1%** | 求解退化 |
| **⑤** | **没被 PX4 接管** | 全程 `nav_state = OFFBOARD(14)` 且 `arming_state = ARMED(2)`，**一次都不掉出** | 断流 / 心跳（`heartbeat_always`） |
| **⑥** | **τ 对比并冻结** | 从 `0` 改到**另一个值**，用**一个可观测的差异**定它；取值与来源（哪次飞行、哪个相关峰）写进记录 | τ / 频率 |

**①②③ 的分工**：① 是"跟得准不准"（水平），③ 是"高度定得准不准"，
② 专门抓**单调漂移** —— 均值好看但一直在往一个方向走，是推力标定的特征，不是增益的特征。
★ 稳态偏差与增益振荡的**分诊**：漂移是一阶的（误差对时间单调），振荡是二阶的（误差对时间交替）。

⚠️ **0.15 m 这条线的出处要说清**：它是 Phase 1 §5.3 的定点判据，但那一版**是目测的、没量数**
—— [`phase1-implementation.md`](phase1-implementation.md) 自己在那一行标着"**目测，未量数**"，
并在下面警告"**别把这四条勾当成数字证据**"。⟹ 它**在本表之前不是一条有数的线**。
把它变成有数的线是**本票的工作**：第 2 节的 (A) 级实测给出 0.051 / 0.105 m，
两趟都在 0.15 m 之内 ⟹ 这条线**不是纸面上的**，但它到现在才第一次有证据。
（顺带一条口径差：`hover_pos_tol_m = 0.10` 是 **`control` 节点判稳的容差**
（`src/control/config/control.yaml`，稳定判据 = 位置 < 0.10 m ∧ |v| < 0.10 m/s 持续 2 s），
**比验收线更严**，这是刻意的。）

**⑥ 的两条硬纪律**（票 10 原话）：
- **τ 定稿后冻结**，自由飞阶段不再改 —— **过补偿比不补偿更危险**（外推是拿速度往前搬初值，
  搬多了直接变成过冲），依据 [`phase2-implementation.md`](phase2-implementation.md) §4 的 **D9**。
- **出现振荡 → 先怀疑 τ 与频率，再怀疑 `Q`/`R` 比例**。归因写下来，**不许顺手调权重**。

### 1.4 阶梯 4 —— 自由飞三条轨迹

**三条轨迹与 Phase 1 逐字相同**（spec US 26）：1 m 原地悬停 60 s / 1 m 正方形 / 1 m 八字
（★ 2026-10-08 由 0.5 m 放大到 1.0 m）。**两边必须飞同一条参考** —— 这是"同口径"的前提。

每条轨迹**一条相对线**（判据 A），悬停**另加一条绝对线**（判据 B）；此外**四条共同**。

## 2. (A) 级同口径基线 —— 阶梯 4 的线从哪来

### 2.1 口径（可执行定义）

| 量 | 定义 |
|---|---|
| **窗口** | `/control/state` 里最长的一段 **`AUTO/TRACK`**，取首拍到末拍 |
| **实际** | `/mocap/pose_enu` |
| **指令（口径 a）** | `/mavros/setpoint_raw/local` —— (A) 级（PX4 内置级联 PID） |
| **指令（口径 c）** | `/mpc/reference` —— (C) 级，本仓 MPC（模型预测控制）节点 |
| **误差** | `e(t) = p_实际(t) − p_指令(t)`；水平 = `hypot(e_x, e_y)`，垂直 = **带符号**的 `e_z` |
| **重采样** | 两侧插值到**同一个** 50 Hz 网格 |

三点容易搞错、且**错了不报错**的地方（全文见工具 README 的「踩过的坑」）：

1. `/traj/reference` **不是**绝对量（相对轨迹原点，悬停时恒为 0）⟹ **不能**拿它当 (A) 侧指令。
   (A) 侧的绝对指令是 `/mavros/setpoint_raw/local`。
2. `/mpc/reference` **是**绝对量：`mpc_node.py` 的「轨迹原点取在锚点上」（`reference_abs = 锚点 + p_rel`），
   锚点是动捕 ENU 帧里的测量 ⟹ **两侧零点相同**，可以直接相减。
3. (A) 侧 `coordinate_frame` 标注是 `FRAME_LOCAL_NED(1)`，但**数值是 ENU**（第一手：同一时刻
   动捕 z = +1.011、setpoint z = +1.012）⟹ **谁照标注把 z 取反，`e_z` 会从毫米级变成 2 m 级**，
   而 x/y 一切正常。工具里有 `DATUM_GATE_M = 2.0` 的闸门拦这一条。

### 2.3 取哪一趟、为什么这么取（操作者 2026-10-09 裁定）

**取值规则：同一场景多次飞行时，取较差的那一趟。**
⟹ 悬停取 **0.1049 / 0.1610**（10-08），不取 09-29 的 0.0506 / 0.1114。
正方形与八字各只有一趟（10-08）。

**为什么"较差"而不是"较好"**：线的作用是**判"有没有变好"**。取较好那趟会把线压到
一次偶然飞得好的水平上，让本该被记下来的退步看起来"还是过了"。
取较差那趟的代价是线偏松 —— 这个代价**由悬停那条绝对线补回来**（下面）。

⚠️ **必须一起写下来的事实：同一场景两次飞行差 2 倍**。1 m 悬停 09-29 = 0.0506、
10-08 = 0.1049，且**分段看不是起机瞬态** —— 09-29 全程 0.043–0.068、10-08 全程 0.084–0.122，
是**常驻偏差**。⟹ **单次飞行的数当不了基线**，这条离散度本身就是这条线的不确定度。
**别把 0.1049 读成"(A) 级的固有精度"** —— 它是一次飞行的读数，不是一次测量。

**★ 为什么相对线之外还必须有绝对线**：(A) 级在三条轨迹上的 0.57–0.59 m **不是稳态偏差**。
成因已查清（对齐诊断 + 分段 + 路径长度）：

- **起机爬升 ~1 s**：指令立刻以 0.5 m/s 走，实际速度在前 ~1 s 只有 0.01–0.10 m/s；
- **稳态速度亏损**：正方形窗内**实际路径 2.889 m 对参考 3.976 m（比 0.727）** —— 全程少走 **27%**；
  起机那 ~1 s（按上一条 0.01–0.10 m/s 对指令 0.5 m/s）**最多**解释其中的 ~11 个百分点
  （1 s × ~0.45 m/s ÷ 3.976 m），**剩下的 ~16% 只能归稳态亏损**；
  ★ 这个比是**判"走慢了"的**：纯滞后不会让它小于 1（只是晚到），所以这是一条独立的、可复算的证据，
  不是起机那 1 s 能全解释掉的量；
- **极值处幅值压缩**：包络对参考的比值 —— 0.5 m 八字 **0.754 × 0.378**（对参考 1.000×0.500）、
  1 m 八字 **0.970 × 0.887**（对参考 2.000×1.000）。
  ⚠️ **y 那一轴对窗口边界很敏感**（八字 y 的极值恰在窗口边缘，而窗口两端各有一拍 1 Hz 的不确定度）：
  [`bag/README.md`](../../bag/README.md) 用 6.15 s 的窗口记的是 0.265（比值 0.53），
  本工具用 6.08 s 记的是 0.189（0.378）—— x 轴两处一致（0.750 对 0.754）。
  ⟹ **比值的方向可信，小数点后一位不可信**，写记录时按量级写。
- ★ **压缩随轨迹尺寸变小而变严重**：两条八字的**速度上限是同一个**
  （`src/traj/config/traj.yaml` 的 `max_speed_ms: 0.5`，全局一个值；放大尺寸时"弧长匀速"⟹ 限速不变），
  而 y 包络 0.5 m 只剩 **38%**、1 m 还剩 **89%** ⟹ 小轨迹的角速度更高。
  这是"带宽不够"而不是"某个尺寸特殊"的旁证。

用**纯时移**（等效滞后 1.3–1.4 s）把前两项吸收掉之后，残差降到 **0.08–0.11 m**。
⟹ **相对线测的主要是"谁滞后少"，不是"谁跟得准"**，而 (C) 级有 ~50 ms 延迟、不会慢起机
—— 它**几乎必然**通过 0.57 m 这条线。所以：

- **悬停那条补上绝对线**（均值 ≤ 0.15 m 且最大 ≤ 0.30 m）：悬停没有"跟不上"的余地，
  这条线测的是货真价实的定点精度，且 **Phase 1 §5.3 本来就在用 15 cm**
  （出处与"它原来是目测的"见 §1.3 的 ⚠️），(A) 级两趟实测 0.051 / 0.105 说明它**不是一条纸面上的线**。
- **最大 ≤ 0.30 m** 是补"均值好看但偶尔甩出去"那一档：均值那半边 (A) 两趟都过，
  最大值那半边 (A) 两趟是 0.111 / 0.161，取 0.30 留了余量。
  ⚠️ **不能按 0.15 m 卡最大值** —— 那比 (A) 级自己（10-08 的 0.161）还紧，线就变成了"必须远超 PID"。

**★ 时间对齐后的残差是记录项，不是验收项**（操作者裁定）。
但**它必须记下来**：如果 (C) 级过了相对线、而它的对齐后残差**明显大于** (A) 级的 0.08–0.11 m，
那说明"过了线、但没真的跟得更准" —— **这是要写进结论的一句话，不是一个 ❌**。

## 3. 五条归因环 —— "过不了"往哪里指

票面点名了五条。**每一条都必须有一个"看得见它"的读数** ——
否则归因就是事后编故事（★ 这是本表存在的另一个理由：
仿真里不存在的静默失败，特征读数也必须先写下来，飞完才认得出来）。

| 环 | 特征读数（第一手可观测） | 它会让哪条判据红 |
|---|---|---|
| **符号映射** | 飞机**朝反方向**加速 / 电机转速差方向反 / `thrust_body` 符号写反（全速砸地 / 电机不起转） | 阶梯 1 全部、阶梯 2 ① |
| **推力标定** | `e_z` **对时间单调同号**（缓慢上飘或下坠）；悬停油门偏置；阶梯 2 的 `κ ≠ 1` | 阶梯 2 ①（偏低）、阶梯 2 ②、阶梯 3 ②③ |
| **角速率增益** | 角速度 RMS 超线、**交替**的高频振荡 | 阶梯 2 ③、阶梯 3 ①⑥ |
| **延迟 τ** | 相位滞后、低阻尼振荡；**τ 从 0 加档之后变差**（过补偿） | 阶梯 3 ①⑥ |
| **求解退化** | `solve_fail` 计数 / 连续失败帧数 / 最坏求解耗时贴线 | 阶梯 3 ④ |

**分诊口诀**（把"振荡"与"漂移"分开，这是最容易混的一对）：
**误差对时间单调 ⟹ 一阶的（推力标定）；误差对时间交替 ⟹ 二阶的（增益或延迟）。**
两者同时在场时，**先定 τ**（票 10 的纪律：先怀疑 τ 与频率，再怀疑 `Q`/`R`）。

## 4. 与 Phase 2 SITL 判据的逐条对应

| ④ | 注入求解失败 | **分层**：标称 ✅（+0.038 m）／`mass+30` ❌（+0.325 → −0.004，触地） | 阶梯 3 ④（求解退化）+ 阶梯 4 ③（回退路径） | SITL 的失配是**参数化的一次性 ±30%**；实机的失配是**电池在负载下随时间漂的电压跌落** —— 同一个数、**不是同一件事**。★ SITL 那条 ❌ 已经把"兜底在失配下会失效"记下来了，**实机的回退 (A) 级就是它的对策** |

在实机上**逐个变成量出来的数**。

## 5. 停飞与回退

### 5.1 哪级不过就不进下一级

**无条件成立**：本表四级**逐级卡**，任一级不过 ⟹ **不进下一级**，就地按 §3 归因、
写完记录（"**未达标 + 实际数值**"，**不写"基本通过"**）、修完**从头重跑本级**。

**★ 从头的含义**：修完任何一环之后，**本级已跑过的段全部作废**。
理由很具体：阶梯 1 改一次符号映射，另外五段的方向预期就换了一次坐标系；
"改完接着往下走"等于拿两套约定的读数拼一个结论。

### 5.2 什么情况下**直接回退 (A) 级，而不是再试一次**

这一档专门留给"**再试一次会以不可控的方式扩大风险**"的情形。**命中任一条 ⟹ 立刻回退**：

| # | 情形（第一手可观测） | 为什么是回退而不是重试 |
|---|---|---|
| **R1** | 飞机**朝反方向**加速 / 触地 / 系绳被拉满后仍在加速 | 这是**符号或归一化**错。重试 = 再摔一次，而且**不会有新信息**（同一份指令只会给同一个方向） |
| **R2** | `nav_state` 掉出 `OFFBOARD` 后飞机**没有**落到 Position 模式的可控回落（`COM_OBL_RC_ACT = 0`，即 [params-changes](../reference/params-changes.md) 的 **D3**），或掉出后姿态持续发散 | 说明**回退路径本身**不在预期状态，此时"再试一次"是在赌下一次回落会好 |
| **R3** | 任一时刻 **触发了 ticket 08 的兜底**（连丢 `FALLBACK_HOLD_FRAMES` = 10 拍）**且**飞机未稳住 | 兜底已经用掉一次；[`phase2/11`](../../.scratch/phase2/issues/11-sitl-tier-b-seam3.md) 的判据④ 记过"兜底在失配下会失效"，没有第二次可指望 |
| **R4** | 求解失败占比 > **10%**，或最坏求解耗时 > **20 ms** | config 页 N1 的验收线：> 20 ms ⟹ **停下优化**。带着这条线飞等于让环周期变成一个未知量 |
| **R5** | 系绳有可见损伤 / 电池单体 < 3.5 V / 任一电机异味或高温 | 硬件状态变了，**这一级的判据不再适用于这架机** |

★ 与 §5.1 的分工：**§5.1 管"没过判据"**（有信息、可以修、修完重跑）；
**§5.2 管"不能再试"**（没信息、或有硬件/兜底上的不可逆代价）。
**R1 是最常被误判成"再试一次"的一条** —— 方向错**不产生新信息**，这是把它单列的理由。

**回退 (A) 级这个动作本身**用 [ticket 08](../../.scratch/phase4/issues/08-safety-paths-and-fallback-drill.md)
演练过的那个操作，**不是出事时才想起来的应急手段**（spec US 20）。

## 6. 现场要填的记录格式

每一级、每一次飞行都写一行，**只有"条件 + 数值"**，不写形容词：

```
级 | 日期时间 | 包名 | 条件（固化参数 / τ / 频率 / 风 / 电池） | 判据 | 实测值 | 过/不过 | 不过⟹归因环
```

**"过"要能指到本表的具体判据编号，"不过"要写实际数值**（票 09/10 共同项的原话）。
`/tmp` 里的东西**过不了重启**（ext4 根盘 + tmpfiles 的 `D /tmp`）⟹
**一手证据与跑场输入当场落仓库**。

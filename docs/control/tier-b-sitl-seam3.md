## 1. B 档是什么：接线、夹具、被控对象

### 1.1 与 A 档的三处差异

| 环节 | A 档（ticket 09） | **B 档（本票）** |
|---|---|---|
| 状态源 | `/fmu/out/vehicle_local_position` + `vehicle_attitude`（**EKF**） | `/mocap/pose_enu`（**由 SITL 真值 ⊕ 包里量出来的噪声/延迟合成**，§3） |
| 判据判在哪一帧 | EKF 帧（节点只看得到 EKF） | **SITL 真值帧**（操作者裁定，§1.3） |
| 被控对象 | z0 标称 | z0 **刻意失配 +30% 质量**（`z0-mass+30.param`，§1.4） |

指令面两档相同：`VehicleRatesSetpoint`（机体系推力 + 三轴角速率）⟹ **PX4 保留角速率环与混控**。

### 1.2 为什么状态的 ENU 约定在这一档会咬人

`state_source=mocap` 走的是 `/mocap/pose_enu`，**ENU / FLU（z 向上为正）**；A 档走的是 PX4 话题，
**NED / FRD（z 向下为正）**。两套约定的换算**只有一处**（`nmpc/node_core.py` 的 `px4_pose_to_enu`），
夹具与判据层都走它 —— 这样"被测的是什么"才谈得上。

⚠️ 判据层自己也要认方向，而这里踩过一次坑：A 档那把公用尺子 `verify_tier_a_hover.segments()`
判"起飞"是按 **NED** 写的（第一帧 `z < liftoff_cross`）。B 档真值来自 DDS 真值帧、是 **ENU**
（第一帧 `z > liftoff_cross`），**不传方向就是静默取反** —— 在 ENU 下 `z < 0.15` 取到的是
**第一帧地面**，于是 `liftoff_t` 记成 0、`climb` 恒等于"开场头 5 s"。B 档真值从回放启动就开始录、
**起飞在 OFFBOARD 之后好几秒**，所以这个取反会给出一个**假的**"真值高度没升上去"❌。
修法是给 `segments()` 加一个**加法式**参数 `rising=False`（默认值 = A 档逐字不变），
B 档传 `rising=True`；两条都有单测钉着
（`test_起飞晚于五秒也认得出来_ENU要传rising`、`test_A档的判法一字未改_默认仍是NED`）。

### 1.3 ★ 判据判在 SITL 真值帧（操作者 2026-09-29 裁定）

A 档的判据只能判在 EKF 帧，因为节点只看得到 EKF，而**这台 SITL 的 EKF 助航是自反馈**
（`sensor_baro_sim` / `sensor_gps_sim` 喂的是 EKF 自己的输出 ⟹ 高度自带 0.34–1.0 m 量级偏差、
逐场漂；源码行号见 [`sitl-z0-plant.md`](sitl-z0-plant.md)）。B 档把真值桥上了 DDS（§2），
所以判据直接读真值帧 —— 这一档量的是**"真值 1 m"**。

★ 代价必须写清楚：**B 档的 0.15 m 与 A 档的 0.15 m 不是同一把尺子**。A 档那个 0.15 m 判在 EKF 帧
（所以要引 A 档的读数时必须带"EKF 帧"这个限定），B 档这个判在真值帧（与 PX4 的估计器完全无关）。
**两个数字不能并排引用。**

### 1.4 被控对象：z0 同构 + 刻意失配 ±30%

票面把"**错参数也能飞稳**"本身写成判据的一部分 ⟹ 主场景用 `--mismatch mass+30`，即
`z0.param` 的 `SIH_MASS` 从 `0.75` 抬到 **`0.975`**（`SIH_T_MAX` 不动，仍 `2.95` N × 4 = 11.8 N）：

| 量 | `z0.param`（标称） | `z0-mass+30.param`（失配） |
|---|---|---|
| `SIH_MASS` [kg] | 0.75 | **0.975** |
| `m·g` [N] | 7.3575 | **9.5648** |
| `4·SIH_T_MAX` [N] | 11.8 | 11.8 |
| 悬停归一化推力 `m·g/(4·T_max)` | **0.62352** | **0.81057** |

矩阵里同时跑 `--mismatch none`（标称）当**归因对照** —— 判据④ 尤其需要它，理由见 §8。
其余失配轴（thrust / inertia / tau / rate）属于 [12 号票的扫描](../../.scratch/phase2/issues/12-mismatch-sweep.md)，
本票**不代扫**。

## 2. 前置：把 SIH 真值桥到 DDS（fork 上唯一的一处改动）

B 档的"动捕"要从 SITL 真值合成，而 SITL 里**唯一不是估计器算出来**的位置/姿态就是
`vehicle_local_position_groundtruth` / `vehicle_attitude_groundtruth`
（`sih.cpp:495-564` 直接发刚体积分出来的 `_p_I`）。这两条**默认不在** DDS 的发布表里。

它自己会改 yaml + 增量重编 + 重装机型，且幂等）：

```
diff   src/modules/uxrce_dds_client/dds_topics.yaml | 4 ++++     ← 全部改动，只有这一个文件
```

```diff

     type: px4_msgs::msg::VehicleAttitude
+  - topic: /fmu/out/vehicle_attitude_groundtruth
+    type: px4_msgs::msg::VehicleAttitude
```

★ 为什么只加 yaml 就够：`type` 只是**序列化器**的名字，而 `vehicle_local_position_groundtruth` 是
`VehicleLocalPosition.msg` 的 `# TOPICS` 别名（`msg/VehicleLocalPosition.msg:75`，姿态同理
`VehicleAttitude.msg:11`）⟹ **ROS 侧收到的消息类型就是 `px4_msgs/msg/VehicleLocalPosition`**，
不需要 px4_msgs 里有任何 Groundtruth 变体（它没有，也不需要）。

⚠️ 三条后果，用之前必须知道：
1. 改的是**钉住基线的树** ⟹ 它现在与 `v1.14.3` 差这一处（只多两条 DDS 发布，**不动动力学**），

2. 重编会清掉 build 目录里的**运行期机型文件** ⟹ 脚本编完会自己重跑 `install_z0_airframe.sh`。
3. **回退**：`git -C ~/refs/px4-v1.14.3-build checkout -- src/modules/uxrce_dds_client/dds_topics.yaml` 再重编。

★ 为什么**不能**拿 `/fmu/out/vehicle_local_position`（EKF）顶替真值：那等于把估计器的偏差记到
控制器账上，且这台 SITL 的估计器偏差**逐场漂**（§1.3）。

## 3. 回放夹具：**包当参考 + 噪声/延迟模型**（操作者 2026-09-29 裁定）

### 3.1 裁定与它避开的那条死路

票面要"输入为 Phase 1 实飞的动捕 rosbag 回放"，字面直译是**把录好的帧直接放到 `/mocap/pose_enu` 上**。
操作者裁定为 **"包当参考 + 噪声/延迟模型"**，原因是字面读法会**断开反馈**：

```
字面读法：/mocap/pose_enu ← 录好的帧          ⟹ MPC 对着一段既定轨迹使劲，
                                               SITL 里的飞机怎么动它看不见
裁定读法：/mocap/pose_enu ← 本场真值(t−D) ⊕ 包里量出来的噪声
                                               ⟹ 闭环没断，包里出的是"这台动捕的脾气"
```

断开反馈的直接后果是票面的判据③（注入 50 ms 延迟后仍稳定）**失去意义** —— 一个看不见飞机
的控制器，"稳不稳"无从谈起。

### 3.2 夹具长什么样

[`tools/px4-sitl/mocap_replay.py`](../../tools/px4-sitl/mocap_replay.py) 把 §3.3 的模型文件变成
`/mocap/pose_enu`：**每帧取当场的 SITL 真值、回退 D 毫秒、叠上模型里的噪声**，
发帧节奏取包里那一串**真实间隔**（不是"均匀 100 Hz"）。`--extra-delay-ms` 是在这条流上
**再叠**一层人为延迟 —— 判据③ 就是靠它。

模型的量取与它自己的单测在 [`mocap_model.py`](../../tools/px4-sitl/mocap_model.py) /
[`test_mocap_model.py`](../../tools/px4-sitl/test_mocap_model.py)。

1. **σ 取的是"飞行残差"与"静态基线"的逐轴较大者** —— 也就是**飞行残差主导**（0.164 mm vs

## 4. ☠☠ 航电口径：`hover_thrust` 差 3.92×（本票必须先说的一条）

**这是本票开工后第一个撞上的坑，不弄清它，后面每一场都在量参数域错误。**

| 出处 | 值 | 含义 |
|---|---|---|
| `nmpc/params.py`（ticket 10 回填后） | **0.1589** | 真机满电口径 |
| SITL 机型自己推的 | **0.6235** | `4 × SIH_T_MAX = 11.8 N`，`m·g/11.8 = 0.75·9.81/11.8` |
| A 档实飞量到的 | **0.6233** | 末段 PX4 解出的电机均值 ⟹ 总推力（`tier-a-sitl-hover.md:214`） |

`thrust_body_z = -thrust_n / t_max`（`sign_map.py:69`）而 `t_max = m·g / hover_thrust`
⟹ 用 0.1589 时**模型的控制效能高估 3.92 倍**。实测后果（由 [12 号票的会话] 在 09:26 量到）：
A 档用节点默认参数**根本没离地** —— 真值 `z` 全程 `+0.0002 m`，末段电机均值 0.2625 ⟹
总推力 **3.098 N < m·g = 7.355 N**。

**本票的口径（操作者 2026-09-29 裁定「用 0.6235」）**：B 档逐场显式传
`--hover-thrust 0.6235`（= 与 SITL 被控对象对得上的那个值），**`params.py` 一个字不动**
（操作者：「11 补、10 不动」）。这个 3.92× 单独记账，记在
[11 号票的 Comments](../../.scratch/phase2/issues/11-sitl-tier-b-seam3.md) 里 ——
包括 `params.py` 里那段**自相矛盾的 docstring**（它同时写着真机口径与 SITL 口径）。

### 5.1 归因：F0 与 F1 只差被控对象这一件事

两场的**代码、配置、种子、`--hover-thrust 0.6235`、`--hold-s 15` 全同**，唯一自变量是
`--mismatch none` / `mass+30`。F0 悬停在 +0.0016 m、F1 悬停在 −0.6406 m ⟹
这 0.642 m 记在**质量失配**头上，**不记在控制器逻辑头上**。

机理（**推断**；依据附后）：模型 `m = 0.75 kg`，被控对象 `0.975 kg`（+30 %）。

- 模型按**自己的**质量给出的悬停推力 = `0.75 × 9.81 = 7.3575 N` —— 这是**实测**的，不是推的：
  F0 的 dump 里 `u_ref0[0] = 7.3575`，与 `t_max × hover_thrust = 11.8 × 0.6235 = 7.357` 同值。
- 被控对象实际需要 `0.975 × 9.81 = 9.5648 N` ⟹ **推力缺口 2.207 N**。
- 垂直通道**没有积分作用** ⟹ 缺口不会被慢慢"修掉"，只能靠**位置误差**去换一个成比例的额外推力
  ⟹ 稳态停在一个高度偏差上。由这一场反解等效增益：`2.207 N ÷ 0.6406 m ≈ 3.4 N/m`。

★ 这条推断是**可证伪**的，而且本票另有两条独立读数支持它：

1. **同一失配 + 50 ms 延迟（F2）把垂直均值压到 −0.6405 m** —— 与 F1 只差 **0.1 mm**。
   缺口那一份与延迟无关，与「缺口 ÷ 增益」这个口径一致（详见 §7）。
2. **F0（口径对得上）的垂直均值 +0.0016 m** —— 同一套代码在**没有这个缺口**时高度钉得住
   ⟹ 不是「垂直通道天生坏」。

### 5.2 这一条判了什么、没判什么

- **判了**：从地面起飞到 1 m 悬停这**一个**工况的稳态精度与稳定性。
- **没判**：能不能跟一条**会动的**轨迹走（那是判据②·轨迹2 的题目，见 §6）——所以
  「B 档闭环飞得稳」这句话在本票里**只覆盖定点悬停**。
  ★ 判据②·轨迹1（原地悬停那条）判的正是本条的**定性**面（跑完 + 不撞地 + 不失控），
  它 ✅ 不给本条加分：**精度**那件事只有这一条管。
- ★ F3 / F4 的判据① 记 **⏭️ 判不了**（`counts=False`）：那两场的**正常帧总长只有 6.99 s < 8 s**

  拿它判等于把爬升算成稳态误差 —— 实测窗口内高度区间 F3 `[−0.000, +0.556]`（峰峰值 0.556 m）、
  F4 `[−0.000, +1.507]`（峰峰值 **1.507 m**），那 4.3 倍的"误差"其实是爬升。
  **这两场的求解耗时与兜底读数照用，但它们的高度数字不许被引作悬停精度。**

| 场 | 被控对象 | ④-A 阶梯走没走 | ④-B 兜底后保持住了吗 |
|---|---|---|---|
| **F3** | `mass+30` | ✅ | ❌ **从 +0.325 m 掉到 −0.004 m（触地）** |
| **F4** | `none` | ✅ | ✅ **+0.991 → +1.038 m**（末段误差 +0.038 m，界 ±0.35） |

### 8.1 ④-A ✅（两场都过）：阶梯真的按设计走了，且**结构上不可伪造**

F3/F4 的逐帧日志里档位分布是 `{warmup: 5, normal: 700, hold: 10, hover: 830/829}`，
迁移顺序 `warmup → normal → hold → hover` 可检索；`hold` **恰好 10 拍**
（= `fallback_hold_frames` 默认值）、`hover` 段 830 拍（8.36 s）。悬停帧的 `thrust_body_z`
实测 **恒等于 −0.6235**，这正是 [mpc_node.py:405](../../src/nmpc/nmpc/mpc_node.py#L405) 那条
固定安全帧的字面值 ⟹ 逻辑上不可能是别的东西凑出来的。

### 8.2 ④-B：**标称口径下达标，票面要求的口径下未达标**

**F4（口径对得上）**：切入 `hover` 后 1925 点，高度 +0.991 → **+1.038 m**，全程区间
[+0.991, +1.067] m，末段误差 **+0.038 m**（界 ±0.35）。**兜底把飞机稳稳托住了。**

**F3（`mass+30`）**：切入 `hover` 后 1973 点，高度 +0.325 → **−0.004 m**，
全程区间 [−0.004, +0.325] m ⟹ **落回地面**。末段垂直速度 ≈ 0 —— 不是震荡摔下来的，
是**匀速沉下去**的。

**机理（本次最有信息的一条）**：兜底的实现是**发一条推力固定的安全帧**
（`thrust_body_z ≡ −hover_thrust`）。这条帧的推力是模型按**自己的**参数算的：
`0.6235 × 11.8 = 7.3575 N`；而被控对象（`mass+30`）需要 `0.975 × 9.81 = 9.5648 N`
⟹ 固定悬停帧只给出了所需的 **0.769 倍** ⟹ 预测净加速度 **2.264 m/s² 向下**
（F3 的实测下降与之相符）。

★★ 所以：**「兜底 = 发一条固定推力的安全帧」这个设计，以『模型里的 `hover_thrust` 是对的』为前提。**
票面要求的 ±30 % 参数失配**恰好打破了这个前提**。这不是兜底代码写错了，而是它的**适用边界**：
**兜底能对付「求解器抽风」，对付不了「模型与被控对象之间的口径差」。**

⚠️ 反向提示：本票的 `hover_thrust` 是被操作者裁定**显式传 `0.6235`** 才对齐的（§4）。
真机上若照现在的 `params.py`（0.1589）起节点，这个前提**在起点就不成立** —— 见 §10 第 5 条。

## 9. 求解耗时（D6 结论行）与实时性

**必须空机量**（[§5.1 的教训](tier-a-sitl-hover.md)：同一台机器上多几个进程，这个数会从 4 ms 抬到 11.3 ms）。

## 10. 能证明什么 / 不能证明什么

**能证明的**

1. **B 档整条链在 SITL 里真的闭合了**：真值 → 回放夹具（照抄真实包的成簇节奏 + 噪声/延迟模型）
   → `/mocap/pose_enu` → **唯一一处**换算 → MPC（模型预测控制）→ 姿态设定值 → PX4 SIH。
   五场**都真的解锁、都真的进 OFFBOARD、都真的离地**（起飞后 5 s 内 z > +0.4 m，五场皆 ✅）。
2. **姿态换算在真值帧上被独立量到**：`⓪b` 判 DUT 报出的姿态与同一时刻真值之差，
   五场中位数 **0.00007°–0.026°**（界 10°）。这一条是本票自己栽过的坑（wxyz / xyzw 写反，见
   §3 与票面 Comments），现在有仪器盯着。
3. **判据③ 通过**：总延迟 55.34 ms 下飞机照样稳、没触地（§7）。
4. **判据④-A 通过**：M5 阶梯在日志里可检索，`hold` 恰好 10 拍、悬停帧推力恒等于 −`hover_thrust`。
5. **兜底的适用边界**（§8.2）：口径对得上时 +0.038 m；口径差 30 % 时兜底把飞机交还重力。
   这是个**有结论**的负面结果，不是"没测出来"。
6. **最坏稳态求解耗时 5.652 ms**（空机、aarch64 Orin NX 6 核，条件见 §9）。

**不能证明的**

1. **「z0 上能飞稳」这句话本票没有证出来**：判据① **未达标**（垂直 −0.6406 m；
   ⚠️ 那是**原 `F1`** 的读数 —— 操作者的裁定 1 是「判据① 认 `F0c`/`F1c` 作证据」，两处别混）、
   判据②·轨迹2 **还没飞**（§6.4）。
   水平通道好（0.0112 m）**不等于**整条判据过 —— 别把 §5 表格第一列当结论用。
2. **被控对象是 SIH 机型，不是 z0 真机**。票面把它当"z0 同构 + 刻意失配"，但**真机上有没有这套偏差、
   多大**，本票量不到。
3. **失配只扫了 `mass ±30 %` 一档**（票面点名的）⟹ 不知道"多大失配会真的发散"，
   也不知道别的参数（`t_max` / 阻力 / 角速率上限）失配会怎样 —— 那是
   [12 号票的参数扫描](../../.scratch/phase2/issues/12-mismatch-sweep.md)的题目。
4. **单次飞行、单一种子**：夹具的 `--seed` 默认 `20260929`，五场**都没有覆盖它** ⟹ 没有重复性统计，
   p99 这类尾部数字只有一场支撑。⚠️ 归档里**没有**记下这个种子（`params` 只记了 ROS 参数，
   没有 harness 的 argv）⟹ 复现得靠 `run_matrix.sh` 的默认值。
5. ⚠️ **`hover_thrust` 的 3.92× 口径差是被"绕过去"的，不是被修好的**：本票逐场显式传
   `--hover-thrust 0.6235`，`params.py` **一个字没动**（操作者裁定「11 补、10 不动」）。
   ⟹ 真机上照现在的 `params.py`（0.1589）起节点，仍然会重现 A 档那个"**根本不离地**"
   （总推力 3.098 N < m·g = 7.355 N）。这条记在 [11 号票的 Comments](../../.scratch/phase2/issues/11-sitl-tier-b-seam3.md)。
6. **判据③ 只注入了一路延迟、只有 50 ms**；动捕包那个"一阵一阵来"的**成簇节奏**
   （§3.3：p50 0.98 ms、mean 5.28 ms、785 个 > 20 ms 的洞）虽被夹具照抄，但**没有被放大压测**。

## 0. 怎么读这一页

**"冻结"的定义**（票面原话）：从本票之后到阶梯 4 结束，**每一级只有一个新变量**
（阶梯本身引入的那一个除外）。任何"顺手调的"参数都是**无法归因的变量**。

★ **冻结的边界**（不说清这条，"冻结了"就是句空话）——本页管的是：
① §1 点名的那几项；② [`params-changes.md`](../reference/params-changes.md) **§D 的反向清单**（D1–D12）；
③ §2 的节点参数。飞控上还有 900 多条参数**不在本票范围**：动它们按"引入一个新变量"处理，
要带理由、归属与记录（§4）。

**证据等级**（票面要求"明确区分第一手 vs 推断"）：

| 标记 | 含义 |
|---|---|
| **第一手** | 读源码 / 读导出文件 / 本地实测得到，能给出路径或命令 |
| **引数** | 文献或厂商标称的数，**我们没量过**（例：电池能供出多少推力） |
| **推断** | 由第一手事实推出来的判断（例：分配器会约掉均匀缩放） |
| **待写入** | 值已定但**还没落进飞控** —— 只有这一类需要**人的动作** |

★ 两条硬纪律：**能从数据现算的就别抄**（本页读数一律带出处，别把它当数表用）；
**状态词要带可核的锚**（"已落地" / "待写入"后面一律跟文件行号或命令）。

**编号**：沿用 Phase 2 那套**逐条编号 + 理由 + 出处**的写法（`phase2-implementation.md` 的 `M*` 就是它），
但**不重号** —— `M1`–`M5` 属于那两份文档自己，本仓库里 `M4` 只能指一件事。
本页用 `F*`（飞控）/ `N*`（节点）/ `K*`（代码）三个前缀各自从 1 排。

### F6 明细：`MPC_THR_HOVER` 到底影响什么（第一手读 PX4 `v1.14.3` 源码，2026-10-09）

⚠️ **先破除一条流传的机理**（本页原写、`params-changes.md` §C1 也这么写：**"只改一处 = 静默的推力增益错误，
指令下去飞机不动"**）——**在 (C) 级这条路上不成立**。第一手：

- `MulticopterRateControl.cpp:182` 把 offboard 的 `thrust_body` **原样**赋给 `_thrust_setpoint`，
  再原样抄进 `vehicle_thrust_setpoint.xyz`（`:229`）发给分配器（`:254`）；
- 全库命中表（`git grep -n 'MPC_THR_HOVER\|_param_mpc_thr_hover' src/modules/`）里
  **`mc_rate_control/` 一个文件都没有** ⟹ 飞控的 `MPC_THR_HOVER` **不缩放**我们发出去的推力。

`thrust_body` 那种"1.0 = 满量程"的线性含义只由分配器的 `THR_MDL_FAC` 曲线决定（C5），
**与 `MPC_THR_HOVER` 无关**。那还有 **`MC_BAT_SCALE_EN`** 会把我们的推力与力矩**乘**上一个电池电压系数
（`MulticopterRateControl.cpp:236-250`：`vehicle_thrust_setpoint.xyz[i] *= battery_status.scale`）——
★ **那才是 (C) 级真正的静默推力增益**，而它已经被冻结在 `0`（F2 ⟹ 整块跳过）。两条别搞混。

**那 `MPC_THR_HOVER` 写错会伤到什么？** 命中表就是下面四处，逐条第一手：

| 消费者 | 用它做什么 | 写错的后果 |
|---|---|---|
| `mc_pos_control`（`PositionControl.cpp:210`） | accel→thrust 的**增益** | 只在 **Position 模式**里起作用 —— 而那正是**打杆接管 / offboard 失效时的回落模式**（`COM_OBL_RC_ACT = 0`，D3）。稳态有积分项兜着，伤的是**过渡与权威** |
| `mc_hover_thrust_estimator`（`MulticopterHoverThrustEstimator.cpp:72/90/92`） | EKF 的**初值**与**可行盒** `[MPC_THR_HOVER − HTE_THR_RANGE, MPC_THR_HOVER + HTE_THR_RANGE]` | ★★ **最硬的一条**：`MPC_THR_HOVER = 0.5` ＋ `HTE_THR_RANGE = 0.2` ⟹ 盒 = **[0.3, 0.7]**，而真值 ≈ `0.1589` ⟹ **真值在盒外**，估计器**结构上就到不了**（会贴在盒底 `0.3` ≈ 1.89 × 真值）。写成 `0.1589` ⟹ 盒 = `[0, 0.3589]` ✓ |
| `MulticopterLandDetector.cpp`（`:79`/`:81`/`:92`/`:101-110`/`:217-218`） | **着陆判据的参考悬停油门** | ★ 它拿**我们发出去的 `thrust_body`**（`:92`：`_vehicle_thrust_setpoint_throttle = -vehicle_thrust_setpoint.xyz[2]`）去比 `sys_low_throttle = MPC_THR_MIN + (hoverThrottle − MPC_THR_MIN)·thr_pct_hover`。⚠️ **`hoverThrottle` 不等于参数本身**：`MPC_USE_HTE = 1`（`z0.params:636`）时 `:101-110` 在 `hte.valid` 的每一刻把它换成**估计值**（而估计值被夹在 `[MPC_THR_HOVER ∓ HTE_THR_RANGE] = [0.3, 0.7]` 里），`:217` 的 `thr_pct_hover = valid ? 0.6 : 0.3` **与它同一支在切换** ⟹ 阈值**随分支有三个值**，不是一个。`MPC_THR_MIN = 0.12`（`z0.params:630`）⟹ **现值（`MPC_THR_HOVER = 0.5`）阈值 ≥ `0.228`**（`0.12 + 0.18×0.6` = 估计值贴盒底 `0.300` 那一支；HTE 未生效那一支 `0.234`、还要更高），而稳态悬停时我们发出去的 `thrust_body` **≈ `0.222`**（**引数**：phase2 §3.3.5 ⑥c 的实测读数，本票**没有**重测；它随负载/电池漂，是**读数**不是常数）⟹ **`0.228 > 0.222`，稳态悬停就落在"低油门"这一侧**；写成 `0.1589` 之后阈值 **≤ `0.181`** ✓ 落在**下面**。★ 三个值的完整表、"余量很薄"的限定、以及"现值下 HTE 估计值**整段贴在下限**"这条实测，都在 [`phase2-implementation.md`](phase2-implementation.md) **§3.3.5 ⑥c**（`:712-716`）—— 本页只摘结论与前提，算式以那边为准 |

### N1 明细：100 Hz 是怎么定的

| 读数 | 值 | 出处 |
|---|---|---|
| 纯求解 max（1000 次，绑核，三轮取最大） | **3.58 ms** | [`offline-ocp.md`](offline-ocp.md) §5 |
| **闭环**空机稳态最坏（z0 同构 SITL，真 PX4） | **3.995 ms** ⟹ 保 100 Hz（余量 2.5×） | [`tier-a-sitl-hover.md`](tier-a-sitl-hover.md) §5 |
| 同一份二进制、**机上多跑几个进程** | **11.297 ms** ⟹ 50 Hz 档 | 同上 §5.1 |
| 整周期墙钟的 1/1000 次抢占 | **52–56 ms**（同拍求解只用 3.4 ms） | [`phase2-implementation.md`](phase2-implementation.md) 的 D6 行 |

**验收线（沿用 Phase 2，本身就是复测判据）**：**≤10 ms ⟹ 保 100 Hz；10–20 ms ⟹ 降 50 Hz；>20 ms ⟹ 停下优化。**

★ 冻结的是 **100 Hz**，附带**两个前提**，都要在首飞当天当场核：
① **机上不跑别的东西** —— 那 11.297 ms 不是求解变慢，是 CPU 被抢；
② **墙钟尾延迟另有主人**（绑核/定优先级，ticket `07`/`10`）—— 100 Hz 在有人编译的 Jetson 上是**假的**。
⟹ **起飞前复测一次**（§5 ④），落在 10–20 ms 就按档降 50 Hz，**别带着"本票冻结了 100"这句话硬飞**。

### N2 明细：为什么 τ 的起始值是 0

- τ 的**量级**是实测的：z0 上动捕 → 飞控端到端 **≈ 50 ms**（主口径点估计 +49.2 ms，
  [`mocap-setup.md`](../reference/mocap-setup.md) §6.3；量测全文 ticket [`phase4/03`](../../.scratch/phase4/issues/03-latency-tau-from-logs.md)）。
- 但**实飞起始值取 `0`**（= 不补偿），依据是 Phase 2 的裁定"**过补偿比不补偿更危险**"
  （[`phase2-implementation.md`](phase2-implementation.md) §4 的 **D9**）——
  外推是拿速度**往前搬**初值，搬多了等于告诉求解器"飞机已经走在前面了"，而那会直接变成过冲。
- 加档的时机归 ticket [`phase4/10`](../../.scratch/phase4/issues/10-ladder-closed-loop-and-free-flight.md)，
  ⟹ **本票不引入"τ 该取多少"这个第二变量**。
- ☠️ **一个只有跑过才知道的坑**：本票之前，`τ = 0` 被节点自己的参数校验拦掉 ⟹ **冻结值在飞机上起不来**
  （第一手症状 `启动失败：参数 tau_s 要是正的有限数，收到 0.0`、`returncode=2`、一帧都不发 ——
  与"参数名写错/话题没通"在现场**分不开**）。已在 §3 的 `K1`/`K2`/`K3` 修掉。
  教训：**"改一个参数就行"这句话本身要跑过一次才算数。**

### N3 明细：延迟补偿的形式 —— 确认为"一行"，且没夹带别的东西

**形式**：`x + v·τ`，只外推**位置**，速度与姿态原样带走
（`src/nmpc/nmpc/node_core.py:444` 的 `extrapolate_state`，τ=0 时退化成恒等）。
不做完整延迟补偿 —— 加速要再差分一次，噪声会把外推变成抖动放大器，而 τ 只有 50 ms 量级，
省下的高阶项远小于噪声。

★★ **两件必须分清楚的事**（这条正是"没夹带"的判据）：

| 东西 | 在哪 | 是不是延迟补偿 |
|---|---|---|
| 状态外推 `x + v·τ` | `extrapolate_state`（喂给求解器的**初值**） | **是**，唯一的延迟补偿 |
| 参考的时域推进 `p_ref(t_k) = 锚点 + p_rel + v·(k·dt_s)` | `traj_reference`（`node_core.py:558`） | **不是** —— 它是**参考自洽**：无阻力模型里"匀速直线 + 水平姿态 + `F = m·g`"本身就是模型的一条精确解，而"位置按 `v·t` 走"正是让 `f(x_ref, u_ref) = ẋ_ref` 成立的那一项 |

⚠️ 两者混在一起时，外推就变成"把目标也搬走"，修正量会恰好抵消掉（`extrapolate_state` 的 docstring
明写"外推的是**初值**，参考点**不外推**"）。⟹ 首飞冻结的就是**这一行**，`N2` 取 0 时它恒等，
**形式仍然保留**（加档只改一个数，不改结构）。

### N4 明细：推重比复核 —— `t_max` 与 `f_max` 是两个量，别再合回去

| 量 | 值 | 是什么 | 依据 |
|---|---|---|---|
| `t_max` | **46.3027 N** | **归一化**常数（`F → thrust_body` 的分母） | `= m·g / hover_thrust = 7.3575 / 0.1589`，**按电机满量程**（悬停工况量出来的） |
| `f_max` | **11.8 N** | **`F` 的上限**（OCP 的 `ubu[0]`） | **按电池**：Mooch 实测 15 A 的持续放电能力（**引数**，不是我们量的） |

- 两者 2026-09-29 之前是**同一个** `T_max`，回填 `hover_thrust` 时把 `F` 上限顺手抬了 **3.92×** 而测试全绿
  （[`phase2-implementation.md`](phase2-implementation.md) §3.3.3）。⟹ 冻结纪律：**改任何一个之前先问
  "我在改的是归一化，还是上限"**（`src/nmpc/nmpc/params.py` 的模块 docstring 有 ★★ 块）。
- **真实可用推重比**：**1.60**（电池 Mooch 实测 15 A / 333 W / ≈1198 g）/ **2.54**（厂商标称 30 A / 666 W / 1902 g）
  —— 两者都是**引数**级证据（[`hardware.md`](../reference/hardware.md) §6.2）。归一化满量程那个 `46.30 N`
  对应的 T/W = **6.29**，那是**电机**能力，**不是**这台飞机能用的。
- ⟹ 冻结的结论不是"一个数"，是**一条设计约束**：**参考轨迹的加速度指令必须按 T/W ≈ 1.60 设计**。
  文献里 20 m/s 级机动飞行通常要 4–6 的裕度（[`hardware.md`](../reference/hardware.md) §6.2 末），
  这台飞机**没有**那个裕度 ⟹ 别指望竞速级机动，抗扰与跟踪仍然做得好。

## 4. 冻结纪律

1. **每一级只有一个新变量**（阶梯本身引入的那一个除外）。"顺手调的"参数 = 无法归因的变量。
2. **改动要能指到某一级的判据**：新参数改动写进本页（新编号）＋
   [`params-changes.md`](../reference/params-changes.md) §J 的对应行，理由必须是**某一阶梯的判据**，
   而不是"感觉这样更好"。
3. **现场临时改参数也要记**：时间 / 参数 / 旧值 / 新值 / 理由。飞控参数写下去就**留在飞机上**
   （§五 坑 4），每次写都要能回退。
4. **第一手 vs 推断必须标**（§0 的表）。后来者要能一眼看出哪些能信、哪些要复核。
5. **状态词带锚**；**能从数据现算的就现算**（别在本页之外的地方复制这里的读数）。
6. ⛔ 两条**反向纪律**：**别照 PX4 默认值改回去**（§D 那批是刻意配的）；
   **别在没确认前改 `EKF2_EV_POS_*`**（F4，双计偏移）。

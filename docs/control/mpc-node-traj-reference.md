## 0. 三个"一句话"

1. **`reference_source` 与 `state_source` 正交**（两个 `if`，不是一个 `else`）：
   `state_source` 说的是"**测量**从哪来"，`reference_source` 说的是"**目标点**从哪来"。
   默认 `hold` ⟹ **不给参数就不改变任何现有行为**。
2. **目标点 = 锚点 + 参考给的相对量**，锚点仍是闸门第一次打开那一拍的测量。
   加原点这件事发生在**下游这一侧**，与 Phase 1 把 `traj_origin` 定在 `control` 里是同构的（§2）。
3. **本票交付的是能力 + 夹具级的证据，不是"三条轨迹在 SITL 里飞完了"** ——
   真机/SITL 飞那三条轨迹仍然是 [ticket 11](../../.scratch/phase2/issues/11-sitl-tier-b-seam3.md)
   的 §S5 判据②（操作者裁定，2026-09-30）。⛔ 本页**没有任何一条飞行读数**。

### 1.1 掩码：**必须真的读**（`type_mask` 置 1 = 忽略该字段）

`node_core` 里的七位常量是**逐位对着真消息类抄的**（`IGNORE_PX/PY/PZ = 1/2/4`、
`IGNORE_VX/VY/VZ = 8/16/32`、`IGNORE_YAW = 1024`），
`test_mpc_node.py::test_掩码常量与_mavros_msgs_逐位相同` 会拿真类再对一遍。

`traj_node.cpp` 的默认掩码 `2496` = `IGNORE_AFX|IGNORE_AFY|IGNORE_AFZ|IGNORE_YAW_RATE`
⟹ **位置、速度、yaw 三样都有效**；加速度与 `yaw_rate` 那几位被忽略，
上游把被忽略的字段留成了 0（`traj_node.cpp:325`）。

⚠️ **"读了一个被忽略的字段"在这条话题上几乎不报错**：默认掩码下位置位全是 0、而位置字段里放的
又正好是真值，所以"把 `type_mask` 全按有效读"在这一档**看不出来**。真正能分辨的是速度那一类：
速度被忽略时字段里是 0，照着读就是"参考速度 0"，而**"速度 0"与"没有速度"在参考这一侧是两个意思**
——前者说"它就停在这儿"，后者说"不知道"（后者该由锚点/上一帧参考兜）。

⟹ 逐轴的 `None`（= 掩码说忽略）在 `traj_reference` 里的落点是：**位置轴保持锚点、速度轴取 0**。
这与 MAVLink 的语义一致（忽略某一轴 = 不对那一轴提要求）。

⚠️ **被忽略轴上的非有限值不算坏帧**（那一轴本来就不该读）；**有效轴上**的非有限值算坏帧
—— 与 `_measure_mocap` 对动捕帧的取向一致（一帧里出现 NaN ⟹ 这一拍不发，而不是"把这一轴当忽略"）。

### 1.2 ★ 夹具保真度的一处修正：`FakeTraj` 原先**漏发了 `velocity`**

第一手（2026-09-30）：真身 `publish_reference`（`traj_node.cpp:311-329`）填的是
`position` + `velocity` + `yaw`，而本仓的 `FakeTraj` 原先把 `velocity` **整个漏了**（三格恒为 0）。

- 对只看位置的消费者（Phase 1 的 `control`）**不可见**；
- 对 Phase 2 的 MPC（模型预测控制）**不是**不可见 —— 时域外推要拿参考自己的速度（§3），
  漏掉它 = 每一条轨迹都被当成"停在那儿"，且**完全不报错**。

⟹ `FakeTraj.__init__` 补了 `velocity_fn`（默认仍发 0，旧用例不受影响）。
这条与 `FakeMavros` 的"QoS 抄错只会永远收不到"是同一类教训：**夹具的"漏"比夹具的"错"更难查**。

## 2. 目标点的口径：锚点 + 参考给的相对量

```
x_ref 的位置 = 锚点(闸门第一次打开那一拍的测量) + p_rel
```

**锚点不是动捕原点**，它沿用 `hold` 档已有的那条口径（ticket 09）。★ 这与 Phase 1 同构，
不是类比：Phase 1 的 `traj_origin` 就是 `control` 在 HOVER 判稳那一刻记的**自己当前位置**
（`phase1-implementation.md` §3.3 第一手表），理由是"**偏移被自动吸收 —— 在同一个坐标系里以当前点为 0 发指令**"。
Phase 2 的锚点是同一件事：`traj` 只知道相对量，**加原点发生在下游这一侧**。

⚠️ **已知限制**（写死在票面口径里，留给实飞确认或推翻）：`p_rel` 给的是**形状**，
绝对落点由"闸门打开时飞机在哪"决定 ⟹ 与"按动捕原点摆好的绝对轨迹"差一个**常值平移**。
起飞点摆得离轨迹起点越近，这个平移越小。

## 3. ★★ 时域外推：`p_ref(t_k) = 锚点 + p_rel + v_ref·(k·dt)`

参考在时域上**按它自己的速度线性外推**，而不是零阶保持。**这不是锦上添花**：

本仓的模型**没有阻力**（`v̇ = R(q)·[0,0,F]/m + g`），所以
"匀速直线 + 水平姿态 + `F = m·g`"**本身就是模型的一条精确解**，
而"位置按 `v·t` 走"正是让 `f(x_ref, u_ref) = ẋ_ref` 成立的那**一项**。

⟹ 对当前这一族参考（`/traj/reference` 只给位置与速度；加速度那几位在掩码里被忽略），
[`hold_feedforward`](../../src/nmpc/nmpc/node_core.py) **一个字都不用改**
—— 它在 `u_ref` 里填的 `[m·g, 0, 0, 0]` 对这条参考族仍然是精确的解析前馈。
（`hold_feedforward` 的尾注里那条 ⚠️ 已被这条 ☠️ **订正**取代，但**订正的是"当前这一族"**：
一旦参考要带**持续加速度**或**持续角速率**，那张表立刻作废，那时换的是**参考族**
（连同外推项），不只是 `u_ref`。）

☠️ **零阶保持（位置钉在当拍参考上、速度却填 `v`）会得到一个自相矛盾的参考**：
代价要它停在原地、速度项又要它以 `v` 前进。而它在话题面上**照样是一串正常的角速率**。
判据：`test_node_core.py::test_轨迹参考是模型的一条精确解`（拿模型的动力学往前推）。
（变异测试确认过：把它改成零阶保持，3 条用例当场变红。）

`dt` 取的是 `OfflineOcp.dt = tf/N = 1.0/50 = 0.02 s` —— **与求解器同一个口径**。
它由节点在构造 `NodeCore` 时以**必填参数**传进去（不给默认值）：
步长写错是一种**静默**的错误（外推项整体缩放，参考仍然"看上去正常"）。

## 4. ★ 参考断流：**冻结**，不是停发

`StopConfig.traj_stream_gap_s`（默认 **0.5 s**）：参考龄超过它就进冻结态 ——
**位置守住最后那一点、速度归零、外推停掉**。

依据是 Phase 1 已有的裁定："**缺一帧参考就保持上一个目标，不回退到原点**"
（`phase1-implementation.md` §3.3）。"停发"会是另一条路（交给兜底阶梯），那是 ticket 07 的地盘，
**本票不碰**。

### 4.1 ★★ 名字对着 Phase 1 抄，以及**为什么只有一级**

Phase 1 的 `control` 有**两级**（`src/control/README.md:119`）：

| 级 | 参数 | 阈值 | 后果 |
|---|---|---|---|
| 1 | `traj_stream_gap_s` | 0.5 s | **保持上一个目标** + 重发一次 `/traj/start` |
| 2 | `traj_timeout_s` | 3.0 s | `degrade=traj_timeout`（放弃这一趟） |

本节点做的是**第一级**，参数名就用第一级的名字。
☠️ **本参数一度叫 `traj_timeout_s`** —— 同一个名字在两栈里指**两个不同的阈值、两种不同的后果**
（0.5 s 守住 vs 3.0 s 放弃），现场照文档读数会**读错一档**，所以改掉。

⚠️ **本节点没有第二级**：冻住之后就**一直守着**，直到别的停机条件（离开 OFFBOARD / 掉 armed /
状态源超时）把闸门关上。理由是**本节点不是任务状态机** —— 它不认识"这一趟"是什么；
"任务放弃"归 `control`（Phase 1）那一侧。

☠️ **只冻位置不冻速度是错的**：那样外推项 `v_ref·(k·dt)` 会继续把参考往前推，
参考自己飞走、飞机照着追 —— 一个**不会报错**的漂移源。
判据：`test_node_core.py::test_参考超时冻结_位置守住速度归零`
与 `test_mpc_node.py::test_参考断流之后冻结_而不是停发`（后者在话题面上断言三件事：
setpoint 照发、`ref_frozen` 为真且 `x_ref0_v` 归零、目标点守住）。

## 5. 参数与小闸门

| 参数 | 默认 | 说明 |
|---|---|---|
| `reference_source` | `hold` | `hold` \| `traj`；不认识的取值**启动即退** |
| `traj_stream_gap_s` | `0.5` | 参考**断流**多久进冻结（只在 `traj` 档被读）；名字抄 Phase 1 的第一级，见 §4.1 |
| `hold_offset_{x,y,z}` | `0` | **只在 `hold` 档被读**；`traj` 档下必须全 0，否则启动即退 |

★ 为什么 `traj` 档**拒绝**非 0 的 `hold_offset`：那时目标点已经是"锚点 + 相对量"，
再叠一个平移既不是轨迹的一部分、也不是锚点的一部分，而症状是"**整条轨迹偏了一截**"
—— 看着像轨迹算错了。切档时忘掉 `hold_offset_z` 是最自然的操作失误（A 档悬停那几场里它一直是非 0 的），
所以让它**当场拒**。

新增的闸门理由（`cycle()` 的 `no_traj_reference`）：轨迹档下**一帧有效参考都没到过** ⟹ 关闸门、不发 setpoint。
它与 `not_armed` / `no_mocap` 在"发了没有"这一层长得一样，而根因完全不同
⟹ 理由必须进日志（`test_mpc_node.py::test_没有参考时闸门不开_理由是_no_traj_reference`）。
⚠️ 这一条与"冻结"是**两个**状态：前者是"从来没收到过"，后者是"收到过、现在旧了"。

## 8. 本页能证明 / 不能证明

**能证明**（夹具级）：参考真的接进了 `cycle()`（目标点 = 锚点 + 相对量，速度那三格真的读了）、
外推族是模型的精确解、掩码逐轴生效、条件订阅在话题边界上成立、
断流冻结是"发着指令的冻结"而不是"交给兜底"、没参考时闸门关着且理由指得出。

**不能证明**：

- **飞起来之后的任何事** —— 跟踪误差、超调、"三条轨迹不撞地不失控"。那几条要真飞机/SITL，
  归 [ticket 11](../../.scratch/phase2/issues/11-sitl-tier-b-seam3.md) 的 §S5 判据②。
- **绝对落点对不对** —— `p_rel` 给形状，绝对落点由"闸门打开时飞机在哪"决定（§2 的已知限制）。
- **`traj` 侧的轨迹数学**（限速、三条几何、`traj_origin`）—— 那是 `src/traj` 自己的正确性，
  由 `test_traj.cpp` 测；本票只测**接口**。

### 8.1 ★★ ticket ⚠️ #2 的落点：**A 档那几条判据在 traj 档哪些失效、要怎么换**

票面 ⚠️ #2 写的"判据要跟着换"指的是 [`tools/px4-sitl/verify_tier_a_hover.py`](../../tools/px4-sitl/verify_tier_a_hover.py)
里那张判据表（③④⑦⑨…）。它们**锚在 `hold_offset` 与"悬停段末 3 s"**上，而 traj 档下目标点
**本来就在动** ⟹ 逐条点名，免得后来人直接拿 A 档那张表去判一场轨迹飞行：

| 判据 | 原判法 | traj 档下 | 怎么办 |
|---|---|---|---|
| ③ 悬停高度 1 m ± 0.15 | `x0[2]` 的末段 3 s 均值 | ☠️ **失效** —— 高度由 `锚点 + p_rel.z` 决定，没有"1 m"这个目标 | 改成**对参考的误差**：`x0[:3] − x_ref0` 的末段均值/分位 |

| ④ 无持续振荡（峰峰值 / 穿均值频率） | 高度绝对量的峰峰值 | ⚠️ **半失效** —— 量的应是**误差**的振荡，而不是绝对高度 | 换成误差序列的同两个统计量 |
| ⑦ 冷启动砸在哪一拍（`warmup` 闸门） | 第 0 拍的 `solve_ms` 落在哪档 | ✅ **不变** —— 它与参考从哪来无关 | 照用 |
| ⑨ 偏航方向 / 换算 | 真值累计转角 vs 指令；机头换算 | ✅ **不变**（但要在**参考带 yaw** 的场次上重跑一遍别名闸门） | 照用 + 重跑 |

⛔ **这件事本票没有做**（本票没有任何飞行读数）：上表只是把"哪几条要换、换成什么"写清楚，
**换判据这件事本身归 [ticket 11](../../.scratch/phase2/issues/11-sitl-tier-b-seam3.md) 的 §S5 判据②**。

## 9. 台架纪律（本票踩到的）

- **别把"订阅者数"当成只有自己在动**：domain 73 是全机台架公用的（`pytest_support.py` 硬拒 domain 0，
  默认 73）。★ 方向是好的：这类污染只会让断言**变红**、不会假绿（除非正向那条写成 `>= 1`），

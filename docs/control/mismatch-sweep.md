## 1. 本张测什么、不测什么

### 1.1 测的是"被控对象与控制器内部模型之间的失配"

被控对象是 SITL 里的 z0 同构机（SIH 刚体 + 一阶电机），控制器是**真 PX4 上的 100 Hz MPC（模型预测控制）节点**。
扫描的做法是：**只动被控对象的一个物理量（±30 %），控制器里的模型参数一个字不改**，
看闭环还稳不稳、稳态误差变化多少、求解耗时是否变化。

这也正是 ticket 08 留那五个旋钮的理由（[`sitl-z0-plant.md` §5](sitl-z0-plant.md)）：
"开关是刻意留的，不是顺手加的"。

### 1.2 不测什么（**这些不在本页的结论射程内**）

| 不测 | 为什么 |
|---|---|
| **模型结构误差** | 本页只扫**参数**。模型里"内环是瞬时的"（角速率是**指令**、不是力矩/惯量的产物，`model.py:182` 的 `q̇ = ½ ω⊗q`）这条**假设**若错，它不是 ±30 % 的参数问题，本页**照不出来** |
| **sim-to-real gap** | 推力曲线（`THR_MDL_FAC`）、电池跌落、动捕时延 —— 三项在本阶段**未被覆盖**，见 §5 |
| **抗风 / 外扰** | SIH 里没有风。本页的"稳定"是**无外扰**下的稳定 |
| **多参数同时失配** | 单参数才答得了"从哪个参数先退化"；两个一起动就分不出是谁（同 [`sitl-z0-plant.md` §5.1](sitl-z0-plant.md) 的理由） |

★ **本页一律不出现"模型验证过"这种话** —— 扫的是"错多少还稳"，不是"模型对不对"。

## 2. 夹具：失配怎么造、怎么证明它真的造出来了

### 2.1 五个旋钮与"模型里有没有对应物"

控制器模型的参数只有三个（[`src/nmpc/nmpc/params.py`](../../src/nmpc/nmpc/params.py) 的 `Z0Params`）：
`mass`、`hover_thrust`（⟹ 归一化常数 `t_max`）、三轴角速率上限。
★ **模型里没有转动惯量、没有作动器滞后** —— 这不是遗漏，是设计
（[`mpc-roadmap.md:73`](mpc-roadmap.md)："不需要电机模型"）。
所以五个旋钮分成**性质不同的两类**，后面读结论时必须分开：

| 旋钮 | 动的参数（`plant_spec.KNOBS`） | 模型里有对应物吗 | 失配的物理含义 |
|---|---|---|---|
| `mass` | `SIH_MASS` | **有**：`Z0Params.mass` | 模型质量错了。★ 注意它**同时**把被控对象的悬停工作点搬走（`hover_thrust_真 = m·g/(4·T_max)`），而模型的悬停点不动 ⟹ 这是**双重**失配（力的大小 + 悬停点） |
| `thrust` | `SIH_T_MAX`、`SIH_Q_MAX` | **有**：`t_max = m·g/hover_thrust` | 推力系数错了 ⟹ 归一化常数错 ⟹ 每个 `thrust_body` 都带一个乘性增益误差。`SIH_Q_MAX` 跟着动是**为了让偏航/推力比不变**（只改推力总量，不碰偏航通道） |
| `inertia` | `SIH_IXX`、`SIH_IYY`、`SIH_IZZ` | **没有** | 模型假设内环瞬时 ⟹ 惯量只通过**内环（PX4 角速率环）**起作用。它测的是"内环在不同惯量上还能不能把 ω 跟上"，不是"模型参数错了" |
| `tau` | `SIH_T_TAU` | **没有**（模型假设 ω 零延迟） | 作动器一阶滞后（`sih.cpp:293-294`）。★ `0.05` 是 **SIH 默认值、未辨识**（ticket 08 U3）⟹ `z0-tau±30` 读作"相对一个占位值 ±30 %"，**不能**读作"辨识误差 ±30 %" |
| `rate` | `MC_ROLLRATE_P`、`MC_PITCHRATE_P`、`MC_YAWRATE_P` | **没有**（但它是"内环瞬时"假设的直接破坏者） | **控制器侧**（其余四个都是被控对象侧）：速率环 P 增益同比例 ±30 %，即内环闭环带宽的失配。★ 票面原词"内环时间常数"指的就是**这一个**（裁定见 [`sitl-z0-plant.md` §5.4](sitl-z0-plant.md) 与 [`12-mismatch-sweep.md:10`](../../.scratch/phase2/issues/12-mismatch-sweep.md) 的改词说明） |

**变体表 = `z0` + 5 旋钮 × 2 方向 = 11 个**。`z0-thrcurve`（`THR_MDL_FAC`）**不是扫描项** ——
它已在模型生成时被刻意取 `0`（[`sitl-z0-plant.md` §5.2](sitl-z0-plant.md)），把它混进 ±30 % 会让边界那句话多出一个不属于它的点。

### 2.2 ★ 前提：必须先解决"悬停推力口径"，否则量到的是参数域错误、不是失配

### 2.3 每场都要证明"它真的跑在那一档机型上"

整张票的结论都挂在一个前提上：这一场真的换了被控对象。
所以每场跑完都**从 PX4 读回 10 个参数**并与 `plant_spec` 的期望值逐条比对：

- 10 项 = **5 个旋钮的全部参数名**（`SIH_MASS` / `SIH_T_MAX` / `SIH_Q_MAX` / `SIH_IXX` / `SIH_IYY` / `SIH_IZZ` / `SIH_T_TAU` / `MC_ROLLRATE_P` / `MC_PITCHRATE_P` / `MC_YAWRATE_P`）；
- 这一并给出一条**单参数隔离**的证据：**除本场旋钮之外的那几项，读数必须与标称一致**；
- 容差用 [`verify_z0_plant.py`](../../tools/px4-sitl/verify_z0_plant.py) 的同一对常数（`PARAM_TOL_ABS` / `PARAM_TOL_REL`），不另定一套。

落盘在 `obs["sweep"]` 块里（`readback` / `overlay_check` / `overlay_sha256` / `hover_thrust_*` / `loadavg` / `nproc`），
汇总表里逐场印一列。**覆盖层没生效的场次在表里被标出来**，不静默计入结论。

⚠️ **这一条查的是"飞机有没有按 spec 加载"，不是"spec 本身对不对"**（`ros-ws-72` 2026-09-29 提出，本张回码核实）：
期望值那一侧是 `mismatch_sweep.expected_params()` → `verify_z0_plant.expected_params()` →
`plant_spec.all_variants()` / `ROWS`，**与生成 `.param` 的同一个真源** ⟹ 改 `plant_spec.py` 时
**期望值与产物同步变**（这正是"单一真源"要的效果，但**不要把它读成一份独立测量**）。
所以判据⑤ 能抓的是"覆盖层没生效 / 多动了别的参数"（**观测**那侧来自飞起来的 PX4 的 `param show`），
**抓不到**"spec 里某个旋钮缩错了参数名" —— 后者由 `test_旋钮动的参数名来自_plant_spec_不另抄一份`
这条单测守着（不另抄一份是本条的纪律）。

|---|---|---|

### 2.5 对照组与重复性

- **对照 = `z0` 档**（参数完全一致），跑 **3 场**，用来给出**这台仪器自己的散度量级**。
  ★ 只有 1 场基准时，"±0.01 m 的差"分不清是失配的功劳还是重复性 ⟹ 汇总器在这种情况下会**显式警告**，不硬给结论。
- **每个失配档先跑 1 场**；从表里读出**边界附近的档**（判据开始挂、或读数明显离开基准散度带）之后再补重复，
  以区分"真的退化"与"这一场抖了"。
- 逐读数与基准比差时给的是**逐读数差值**（不是一句"正常"），基准侧同时给中位数与**跨度**。
- ★ **"谁先退化"另有一张排序表**（`rank_degradation()`）：判据挂没挂是一根**固定的绝对线**，
  而"哪个参数先开始变差"要问在**两个都还过线的档之间** —— 那里绝对线给不出答案。
  所以排序用的尺子是**基准自己重复几场的散度带**：
  `x = |读数 − 基准中位数| ÷ (基准跨度 / 2)`（无量纲，故米/弧度/毫秒可并排）。
  三条**拒绝**规则写在同一处代码里，不许绕过：
  ① 基准只有 1 场、或基准重复场读数一模一样（跨度 = 0）⟹ **整页不给倍数**（那种情况下任何差都是"无穷倍"，印出来会让人以为"一碰就散"）；
  ② **发散**的档不参与排序，单列在最前（它不是"更严重的退化"，是另一个类别）；
  ③ **求解耗时不进排序** —— 它对机器负载敏感（空机 3.995 ms vs 机上跑 pytest 11.297 ms），进排序会把"机器忙了一下"读成"这个参数让求解变慢了"。它照旧印在表里（D6 那一列）。

#### 2.7.1 ★★ 第一版"身份探针"在说假话（2026-09-29 10:14 自查抓到并修掉）

## 4. 结论：稳到哪儿、谁先退化

按票面句式填（**句式一字未改**，只填数与档位）：

**1. 在 ±30 % 的什么范围内仍稳定**

`inertia±30`、`tau±30`、`rate±30`（三个旋钮 × 两个符号，**共 6 场**）在 6 场里
全部满足 [ticket 09 的 A 档验收判据]（该判层所在的 **EKF 帧**上，判据③ 的抬升量
0.956–1.005 m vs 基准中位数 0.978 m，**与中位数最多差 0.027 m**（六场自身跨度 0.048 m），落在**基准自己的散度带** ±0.019 m 的
同一量级内）且未触发 §2.4 的任一发散规则；**边界从 `mass` / `thrust` 开始**
（现象：判据③ ❌ —— **抬升读数**离开基准散度带 **25–34 倍**；而判据③ 真正量的那个
**稳态误差** `e_z = 抬升 − 1.0 m` 是 −0.658 / +0.587 / +0.453 m
（界的 **3.0–4.4 倍**；`thrust-30` 的 −0.855 m 另计，为界的 5.7 倍））。
其中 **`thrust-30` 更早就没了**：那一场**根本没起飞**（判据② ❌，真值高度全程 0），
按 §2.4 归入**发散**，不是"偏差大一点"。

**2. 谁先退化**

**必须分两类说**（理由 §2.1）—— 这两类的"退化"根本不是一件事：

- **模型里有对应物的那两个（`mass` / `thrust`）**：按"读数离开基准散度带的倍数"排序是
  **`mass`（33.76× / 32.35×）> `thrust`（25.22×，且 `thrust-30` 直接发散）**。
  机理是**工作点**：模型算出的悬停前馈与被控对象所需不符，而竖向上没有积分作用，
  只能拿偏差去换 ⟹ 稳态偏差 `Δz = −ΔF/k`。
- **模型里没有、只打在内环上的三个（`inertia` / `tau` / `rate`）**：
  **本实验条件下探不到边界** —— 判层所在帧上与基准中位数的差 ≤ 0.027 m，与基准自己的重复性同量级
  （§3.2 里那 3.5–7.7 倍来自**真值帧**，已证与本帧不可比 ⟹ **弃用**）。
  ★ **"探不到"有两种含义，这里必须说清是哪种**：
  它**不是**"这三个参数不重要"，而是 **±30 % 这个幅度在这台同构被控对象上不足以把
  A 档判据推过线**；**再大没测**（要测就得改 [ticket 08](../../.scratch/phase2/issues/08-sitl-z0-airframe.md)
  的 `MISMATCH_PCT`，本张不擅自改别人的夹具，理由与那条可证伪预测见 §附.1）。
  ⚠️ 而且它们的读数**确实在动**（`z0-thrust+30` 那一列的 `drift_ekf` 0.32、`tau±30` 0.27/0.69
  都高于基准中位数 0.162）—— 但**基准自己的 `drift_ekf` 跨度就有 0.795**（§3.1 表注 2）
  ⟹ 那条读数**分辨不出**这个量级，不能当退化证据。

**3. 本页能给出的"量化的边界"（这是票面要的那张图，比"挂/不挂"有用）**

从 `mass±30` / `thrust±30` 四个独立点反推垂直通道等效刚度（`render_gain()` 印的）：

| 变体 | 旋钮 | ΔF（**算**：按**控制器口径** `4·SIH_T_MAX(z0)`=11.80 N，N） | Δz（**量**：相对基准中位数，m） | k = −ΔF/Δz（N/m） |
|---|---|---|---|---|
| `z0-mass+30` | `mass` | +2.206 | -0.636 | **3.47** |
| `z0-mass-30` | `mass` | -2.206 | +0.609 | **3.62** |
| `z0-thrust+30` | `thrust` | -1.697 | +0.475 | **3.57** |
| `z0-thrust-30` | `thrust` | +3.152 | — | —（没起飞，不给 k） |

★ **表头那两个加粗词是这条结论的命门**：`ΔF` 是**算出来的**（机型口径 `m·g/(4·T_max)`），
`Δz` 才是**量出来的**。⟹ 表里那三个"所需补偿力"**不是**本页的实测发现，
不能拿去与别处用同一个式子算的数"互为旁证"（见 §7 的 ☠️）。**量出来的只有 `Δz` 与 `k`。**

★★ **`ΔF` 用的是哪一档口径，必须写死，否则这表能被算出第二个数**（2026-09-29 复核补）：
`ΔF` 一律换算到**控制器信的那个口径** `4·SIH_T_MAX(z0)` = **11.80 N**（本页 13 场全部按
`--hover-thrust auto` 飞，节点信的就是这个），**不是**本场被控对象的口径。
两者在 `thrust±30` 上**差 1.3 倍**：同一档 `thrust+30`，按控制器口径 `ΔF = −1.697 N`（本表用的），
按**本场**被控对象口径（`4×3.835 = 15.34 N`）则是 **−2.207 N** ⟹ 同一个 `Δz` 会反推出
**4.65 N/m** 而不是 3.57。
**为什么选控制器口径**：`k` 是**位置环的增益**，而位置环把"高度误差"映射成力用的是**它自己**的
力标定（N → 归一化指令，除以 11.80）⟹ 只有用控制器口径，三个档的 `k` 才是**同一个增益**（跨度 4.3 %）；
换成被控对象口径，`thrust+30` 会跳到 4.65（跨度 ≈ 30 %）—— 那才是把两台标定混进一个数里。
★ 这条是并行会话一句"标称 vs 本场 overlay 的错法会蔓延"引出来的自查结果：**结论没变**，
但口径不写死，这个数**可以被合法地算出两套**。
中位数 **k = 3.57 N/m**（ekf 帧，推力口径 11.80 N、悬停 7.355 N）
⟹ 判据③ 的 ±0.15 m 相当于**悬停口径最多错 ±7.3 %**（±0.536 N）。

★ 三个点给出 3.47 / 3.62 / 3.57（**跨度 4.3 %**）⟹ "线性弹簧"这个模型站得住，
这四个数**不是**四个独立的巧合。需要补偿的力：**`mass+30` 要 +2.21 N、`thrust-30` 要 +3.15 N**
—— 是悬停推力（7.36 N）的 **30 % / 43 %**。（这正是 [ticket 20](../../.scratch/phase2/issues/20-vertical-channel-mismatch-offset.md)
要的"积分起点该从哪儿夹"的那个量，见 §7。）

## 7. Phase 3 四项前置测量的覆盖检查

§4 的结论是**最敏感的那一类 = `mass` / `thrust`**。要点是这两者**不是"模型的一个系数"这么简单**：
它们合起来决定**悬停工作点**（前馈推力 = `m·g`，而模型把它写成 `max_thrust · hover_caliber`），
而竖向上**没有积分作用**去吸收工作点误差 ⟹ 工作点错多少，就稳态偏多少。

⟹ 于是问题变成：**"悬停工作点"这项，在 P1–P4 里吗？**

| 前置测量 | 覆盖本页最敏感的那一类吗 |
|---|---|
| P1 四个电机的实际位置 | ❌ 不覆盖（这是分配器几何，本页扫不到它 —— 见 §1.2） |
| **P2 悬停油门** | ✅ **正是它**。P2 的回填同时改 PX4 `MPC_THR_HOVER` 与 MPC（模型预测控制）模型，改的**就是本页 `mass`/`thrust` 那两个旋钮影响到的同一个工作点** |
| P3 动捕↔IMU 外参 | ❌ 不覆盖；且 A 档不用动捕（§5 第三行） |
| P4 端到端延迟 `τ` | ❌ 不覆盖，且**不是同一个量** —— P4 是**状态输入**延迟，本页 `tau` 是**作动器**一阶滞后（§5 第三行已划线） |

**结论：最敏感的那一类（悬停工作点）已经在四项里（P2）⟹ 本张不请求加测。**
而且**要求可以量化**，写给 P2 执行时当验收尺用（数从 §3.1 的 `k` 那一节来）：

- A 档判据③是 **±0.15 m**；本页实测竖向等效刚度 `k = 3.57 N/m`（§4 第三块）
  ⟹ 反推：**悬停口径必须准到 ±7.3 %**（对 7.355 N 的悬停推力即 **±0.536 N**）。
- P2 现有回填手段（[ticket 10](../../.scratch/phase2/issues/10-param-measure-backfill.md) 已做的静止段推力反算）
  的**实际重复精度 ≈ ±0.09 %**（同一份日志两段独立反算之差）
  ⟹ 比要求**宽 ~80 倍**。**P2 不需要加严，也不需要加测。**

★ **另外三个旋钮（`inertia` / `tau` / `rate`）不在 P1–P4 里**，但 §4 显示它们**没有让任何判据退化**
（绝对效应 ≤ 数厘米，且落在基准散度带同一量级）⟹ **按票面规则，不请求加测**。
这一条要**明说它是"本实验条件下不足以撑起一次新测量"，不是"这三个量在真机上不重要"**：
本页是**仿真结论**（§5），真机上 `tau` 与 `rate` 会因为电机/桨的个体差异而不同，
那属于**上真机时**该量的项，不是 Phase 3 的前置测量项。

### 附.8 ☠️ 加密档第一场就死在**夹具的取数器**上：`field()` 把半截窗口里的 `-` 当成一个数

这一条与失配结论无关，但**它卡住了整批**，且是**共用夹具**的缺陷，所以完整记下来。

**症状**：加密档第一场飞了 55 s 后整场作废，`rc=1`、所有读数 `—`：

```
verify_tier_a_hover.py:731 tick() → :198 sampler.poll() → :129 parse_stream
  → verify_offboard_smoke.py:422 field()
ValueError: could not convert string to float: '-'
```

（行号是**崩时**的：`field()` 修前在 `:422`、修后在 `:432`；`ts_age_s` 的取值正则现在 `:443`。
直接按 `:422` 去 grep 会找不到 —— 那是 traceback 的历史行号。）

**根因不是"值不合法"，是"窗口"**。`px4_console.text_since(mark)` 渲染的是 `_raw[mark:]` 这个
**字节窗口**，而窗口的**两端**都可以落在**一个数值的中间**（尾部就是"当时已到达的字节末端"）。
旧正则 `^\s*{name}:\s*(-?[0-9.eE+-]+)` 的字符类**本身含 `-` / `e` / `E` / `.` / `+`**，
`+` 只要**一个字符**就满足 ⟹ 窗口在 `-0.01408` 的负号后断掉时，它匹配到 `-` 并 `float('-')` 抛。

**第一手复现（不启 SITL，纯离线）**：取 `/tmp/verify_tier_a_console.log` 里一个**真块**（块 #32）的**全部前缀**，
逐个喂旧正则 ⟹ **4 处**抛、值**全是 `'-'`**（`x` / `z` / `vx` / `vz` 各一处）。
**旁证"崩的不是日志文本"**：同一份日志按那 7 个字段名逐行扫，**一行都不坏**；
且全文 182 个真值表头重放 `parse_stream` **只出 2 行**（正常应远多于此）⟹
那份 `text()` 全文**不是**当时喂进去的字节窗口。

**修法**（`verify_offboard_smoke.py`）：数值改成 `-?(?:\d+\.?\d*|\.\d+)(?:[eE][+-]?\d+)?`
——**至少一个数字**；取不到一律 `None`、**绝不抛**。实测**只影响原本会抛的输入**：

| 输入 | 旧 | 新 |
|---|---|---|
| `z: 0.00016` / `x: -0.00023` / `vz: -1.2e-3` / `z: .5` / `z: 5.` | 同左 | **不变** |
| `timestamp: 23576000 (0.000000 seconds ago)` | `23576000.0` | **不变** |
| `z: -` / `z: e` | **抛 `ValueError`** | `None` |
| `z: nan` | `None` | `None` |

**修法生效**：加密档第一场 **rc=0、68 s**（原来 55 s 就死），该场真值 70 个采样**一列 `None` 都没有**
⟹ 这次修复没有把这一场的数据弄差。

#### ⚠️ 这个修法**没关掉**的就是它旁边那条：**静默截短**

`-0.01408` 被窗口切成 `-0.0140`，**仍然匹配**新正则（它只要求"至少一个数字"）⟹
返回一个**合法但错**的值。**这次只把"抛"变成 `None`，没有把"截短"变成正确**
（旧字符类在 `-0.0140` 上同样匹配、同样给错值 ⟹ 这条分支**既没被引入、也没被扩大**，只是**没关掉**）。

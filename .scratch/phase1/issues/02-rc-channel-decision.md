# 02: 决定遥控通道分配 —— 开始 / 急停 / 解锁

Status: done
Type: grilling

**What to build:** 一张**写死的决定**：开始信号用哪个通道、急停用哪个通道、两者**是否复用同一通道**、以及**解锁走遥控器还是程序**。

这是 spec 里**唯一一处刻意不在 spec 层解决的设计决定**（Q19），点名交给 ticket 化步骤产出。它必须在 Phase 1 实施到 FSM 的**「开始信号」之前** resolved —— 否则安全机制缺一条腿。

**已固定的约束（不可协商）：**
- 急停/开始信号**不得**与 PX4 模式开关（`RC_MAP_FLTMODE`）共用通道 —— 否则按下去会同时切换 PX4 飞行模式，把我们踢出 OFFBOARD
- 已知 `RC_MAP_FLTMODE` 已占用一个通道；[`params-analysis.md`](../../../docs/reference/params-analysis.md) §3.15 的完整占用表（含 ch5 解锁、ch8 杀车）—— ☠️ **本行原文写「实际只剩 ch7 空闲」，那是错的**（未映射通道有 9 个：ch7 与 ch9…ch16；真正的约束在**遥控器侧**），已更正，见 §H.3
- **在此之前，实现一律参数化**（`start_channel` + `start_threshold` + 200 ms 去抖），不写死任何通道号

**Blocked by:** 无（可立即开工）—— 占用表已足以支撑决策。

⚠️ **但结论必须在台架上用 `/mavros/rc/in` 核对一次**（那一步在 [`09`](09-track-mission-script.md) 的台架环节）。若核对结果与决定不符，回到本张修改决定，而不是就地改代码。

- [x] 开始信号：通道 + 阈值 + 去抖参数写定 → **ch9 上升沿**；先 `<0.25` 再 `>0.75`（归一化，与 PX4 `*_TH` 同一把尺）；**去抖 200 ms**
- [x] 急停信号：通道写定，**或**明确说明为何与开始信号复用同一通道 → **不复用**：急停 = **ch8 高值 = PX4 硬件杀车**（沿用 `RC_MAP_KILL_SW = 8`），**不新增软急停通道**、程序不读它
- [x] 解锁方式（遥控解锁 vs 程序解锁）写定 → **程序解锁**（`/mavros/cmd/arming`），触发 = **ch9 第 1 次上升沿**；`RC_MAP_ARM_SW = 5` 保留为冗余路径
- [x] 显式确认与 `RC_MAP_FLTMODE` 不冲突 → ✅ ch9 **不在任何 `RC_MAP_*` 里**（非 0 的只有 ch1–4 / ch5 / **ch6 = FLTMODE** / ch8）
- [x] 结论写入文档（[`params-changes.md`](../../../docs/reference/params-changes.md) 新增一节，或 [`CONTEXT.md`](../../../CONTEXT.md)），并从本文件回链 → ✅ 写进 **`params-changes.md` §H**（新增一节），本文末「决定记录」回链

### ⚠️ 过程中被打回的三件事（含两条是我自己的错，必须留着）

1. **D2 的原话与固件硬冲突，没有照写** —— 「急停复用开始通道 / 软急停」与
   `RC_MAP_KILL_SW = 8` 不能共存：ch8 高值走 `ACTION_KILL → manual_lockdown`（**立即停桨**），
   而"停发 setpoint 让 PX4 接管"是**另一条**路径。把证据链摆出来后用户裁定 **D2 = 沿用杀车**，
   于是"软急停通道"这个设想**被取消**（连带 §H.7 写清了停任务只剩两条既有路径）。
2. **§3.15(a)「只剩 ch7 空闲」是错的** —— 未映射通道有 **9 个**（ch7 与 ch9…ch16）。
   已更正，并说明真正的约束在**遥控器侧**（§H.3）。旧话说得太硬，本条是它的反例。
3. **我判过「PX4 报 RC 健康却收不到数据 ⟹ 飞控谎报」，撤回** —— 实测 `SYS_STATUS` 的
   `RC_RECEIVER` 位 `present/enabled/health` **全 0**，PX4 的读数是对的，是我读错。
   同期真正的缺陷是**另一个**：`wait_heartbeat()` 不筛来源，会把链路上**另一台地面站**
   （`255/190/6/8`，与飞控心跳各 1 Hz）当成飞控 → 指令发错对象、状态读错对象。**已修 + 补自检**
   （[`tools/prereq-evidence/README.md`](../../../tools/prereq-evidence/README.md)）。

### 实测（只采到"环境"这一层，没采到"开关↔通道"那层）

- **16 通道的实测读数在 §H.3**（那次采集时 RC 链路**还活着**，751 条 `RC_CHANNELS`）；
  **`RC_CHANNELS` 0 条 + `SET_MESSAGE_INTERVAL` 被 ACCEPTED、`RC_RECEIVER` 三位全 0、
  心跳双来源各 25 条/25 s 在 §H.9**（那次链路**已经断了**）。**两个窗口同日但先后不同，别混读。**
- **没做成**：遥控器**物理开关 ↔ 通道**的对照。本轮两个窗口都废了：第一次操作者未在窗口内拨动，
  第二次是我自己的脚本缺陷；等修好时 **RC 链路已经断了**（本机当前收不到任何 RC 数据）。
  ⟹ 但**这不影响本张**：结论全部来自固件源码与参数表，与链路是否在线无关。

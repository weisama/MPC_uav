**What to build:** 飞机第一次真正**自主离地并稳定悬停**。

解锁 → 以 **≤0.5 m/s** 爬到 **1 m** → 保持；"稳定"是**程序可判定的量化条件**，不是主观感觉：

```
位置误差 < 0.10 m  ∧  |v| < 0.10 m/s     持续 2 s
```

稳定那一刻**记录轨迹原点**。任务结束自动走 `AUTO.LAND` 并上锁，不需要手动接管降落。

**两个来源，都在 EKF2 的 local NED 里，与 setpoint 同坐标系，不需要额外转换：**
- 位置误差相对**轨迹原点**，来源 `/mavros/local_position/pose`
- 速度来源 `/mavros/local_position/velocity_local`（EKF2 融合，比动捕差分干净）

★ **轨迹原点 ≠ 动捕原点。** 轨迹原点取「HOVER 判定稳定那一刻 EKF2 报的位置」，这样 EKF2 的局部原点与我们的原点之间的常值偏移被**自动吸收** —— 我们是在同一个坐标系里"以当前点为 0"发指令。**这条设计让 Phase 1 与 Phase 2 的原点问题彻底解耦**，是降低 Phase 1 风险的关键一步。

### 五处实现时才定下来的事（工单原文没说清或说反了）

1. ★★ **到高判据的基准是「起飞原点 + 高度」，不是 `|z − 1.0|`、更不是当帧的 `target_z`。**
   飞机不一定从 `z = 0` 起飞（EKF2 的局部原点是它自己的那几个数），所以 `|z − 1.0|` 不能照抄成代码；
   而写成 `target_z` 的后果更隐蔽：斜坡还没走完时目标就在飞机当前位置上 ⟹ 判据**发出去的那一瞬间**就成立，
   斜坡形同虚设（飞机在 0.5 m 处被判"到高"）。`test_fsm.cpp::到高判据看的是原点加高度而不是当前目标值`
   专门钉它，场面取"飞机严格跟着斜坡走"（此时两个基准只差一个原点高度，一眼看出用的是哪个）。
2. ★★ **"稳定判据的位置误差相对轨迹原点"是循环定义，落地时改成相对"悬停点"。**
   轨迹原点恰恰是**判稳那一刻**才记下来的 ⟹ 拿它当基准是"先有鸡还是先有蛋"。
   落地口径：**判据比悬停点**（= 起飞原点正上方 `takeoff_altitude_m`，起飞那一刻就锁定了），
   **记下来的轨迹原点是判稳那一刻 EKF 报的位置**（工单的 ★ 核心设计不变）。
   两者相差不超过 `hover_pos_tol_m`（判据保证）⟹ 记下来的那一刻目标跳变 ≤ 10 cm。
   已就地更正 `phase1-implementation.md` §5.1。
3. ★ **`velocity_valid` 是判据的必需品，不是防御性代码。** 速度话题一帧都没到过时 `vz` 恰好是 0
   （"看起来静止"）⟹ 判稳会**立刻**通过。`Odometry` 因此把 `position_valid` 与 `velocity_valid` 分列
   （它们是两条独立订阅，启动时可能只到了一条）。
4. ★ **"持续"是连续的、不是累计的** —— 一帧不合格就重新计时。到高与判稳两级**共用**一个
   `settle_started_at_s_`（它们互斥：同一帧只可能在一个任务态里），每次进新的一级都重置。
   ⚠️ 哨兵值必须是**负数**：夹具/单测的 `now_s` 从 ~0 起算，用 `0.0` 当哨兵会把"还没计时"
   与"从 0 秒起就在计时"混为一谈。
5. ★ **解锁前置多了一条"遥控在线"**（§H.7.1 的人肉清单 ⟹ 机器判据）。理由具体：遥控静默时解锁，
   紧接着的 `rc_timeout` 降级（**只在已解锁时算失效**）就会请求降落 ⟹ 飞机**起飞后立刻降落**，
   比一开始就不解锁难查得多。代价是台上没接遥控接收机时**永远解不了锁** —— 刻意如此。

### 第一手核实（推翻了两条既有结论）

- ☠️ **`MAV_RESULT` 的枚举值，旧注释是错的。** 原代码注释写"4 = `TEMPORARILY_REJECTED`"，
  第一手（`/opt/ros/humble/include/mavlink/v2.0/common/common.h:1135-1136`）：
  `ACCEPTED = 0`、`TEMPORARILY_REJECTED = 1`、`DENIED = 2`、`UNSUPPORTED = 3`、`FAILED = 4`。
  ⟹ `4` 是 `FAILED`。同时把日志从 `result=<n>` 改成固定形状的 **`MAV_RESULT=<n>`**
  （与 `degrade=` / `traj_origin=` 同一惯例：现场要的是"能搜到并直接喂脚本"）。
- ☠️ **ticket 05 的 `yaw` 参数被删掉。** 那个参数默认 0，而 0 在 ROS/ENU 口径下经 mavros 换算后
  是 PX4 的 **+90°（机头朝东）**（`setpoint_raw.cpp:231/235`）⟹ 一旦在 OFFBOARD 里解锁，
  PX4 会**真的去转机头**。新规则：`STANDBY`/`INIT` ⟹ **当前机头**（不转向）；
  进入 `TAKEOFF` 那一刻**锁一次** ⟹ 全程用锁定值（§3.4"起飞不转向"）。
  ⚠️ 连带："飞机原地不动"只在 yaw 也被固定时才成立 —— 一架会转向的飞机不算悬停成功。
- ☠️ **ticket 06 的 `own_arming` 参数被删掉**，且**删掉它本身是必要的**：它把任何 `armed` 上升沿
  都当作"本节点发起的解锁"，正好会**打掉** §H.6 的"外部解锁 ⟹ 停发 + 告警"。
  归属改由 `Px4Interface::request_arming()` **真实追踪**：只有拿到肯定应答之后观察到的**第一个**
  `armed` 上升沿才算我们的。⚠️ 中间可能夹几帧 `armed == false`（`/mavros/state` 只有 1 Hz，
  而应答是即时的）⟹ "看到 false 就清掉请求标记"会把**我们自己的**解锁误报成外部解锁。

### 测试侧的三处结构性变化

1. **`test_control_failsafe.py` 的基线从 `AUTO/STANDBY` 变成 `AUTO/TAKEOFF`。** 因为 armed 的注入面
   从"翻一个参数"换成了"**走真实的起飞路径**"（调 `/control/takeoff` → 等解锁）。夹具的假飞机
   不会自己动 ⟹ 状态稳定停在 `TAKEOFF`，用例的断言面没变。那条"外部解锁"用例现在是"**不调**服务"。
2. **新加 `test_control_takeoff.py`（seam 1，8 例）**，覆盖整条链：受理 ≠ 起飞 ⟹ 解锁 ⟹ 爬升 ⟹ 判稳 ⟹
   记轨迹原点 ⟹ `WAIT_START` ⟹ `MANUAL/LAND` + 请求 `AUTO.LAND` ⟹ 外部上锁 ⟹ 自动复位、能再起飞。
   两个刻意的断言方式：**爬升速率断言两侧**（`≤0.55` **且** `≥0.40` m/s —— 只断上界的话"根本没爬"也会通过）；
   **"命令超时作废"用外部可观测的方式测**（命令在飞时第二次起飞回 `already_flying`，作废后回 `accepted`）。
3. **"假飞机" `_Plant` 放在测试文件里，不放进 `bench`。** 它是**场景**逻辑（"这一轮飞机该怎么飞"，
   与 `Timeline` 的编排同类），不是接口保真度问题，且只用了已被自检过的注入面。
   一条纪律值得记下：它**只在收到新 setpoint 时才走一步** —— 否则探针的轮询快过 DUT 的 50 Hz 时，
   会观测到 0 与 2× 交替的假速度抖动（`bench/README.md` 纪律 2 的同族坑）。
   ⚠️ **ticket 09/10 若要复用，那时再把它提升进 `bench` 并补自检。**

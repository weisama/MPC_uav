# 21: 电调报「无信号」—— 上电一段时间后开始滴滴响

Status: needs-info
Type: task

**为什么单开一张：** [ticket 20](20-fcu-hardfault-i2c1-crash-dump.md) 的硬故障有一个肉眼可见的症状候选：
**飞控重启的窗口里 DShot 停发，电调就会连续滴滴报「无信号」** —— 而 20 号票已实测出**飞控约每 11 分钟自己重启一次**。
但**症状 ≠ 机理**：同一句「滴滴响」还可能是驱动没起来、信号排线、供电、协议不匹配。
20 号票管机理（转储解读 + 重启的周期），本票管症状，负责把现象钉死并给出判别实验。

## 一、现象（用户报告 + 2026-09-22 四问四答）

| # | 问 | 答 |

| 4 | 四个电调一起响，还是某一个？ | **不清楚** |

### 2.2 ★ 源码结论：**驱动只要活着就在发帧，解锁与否都发**

| 结论 | 一手证据 |
|---|---|
| 「干脆不发」只有一个分支：`if (!_outputs_on) return false;` | px4-z0 @ `5ba2e91f` `src/drivers/dshot/DShot.cpp:417` |
| 而 `_outputs_on` 在 `Run()` 里**恒被置为 true** | 同上 `:533` `bool outputs_on = true;`（无任何条件）；**官方 v1.14.3 @ `1dacb4c` `:458` 写法一字不差** |
| **未解锁时发的是命令帧，不是静默** | 同上 `:436-448`：`stop_motors` 为真时逐个输出 `up_dshot_motor_command(i, DShot_cmd_motor_stop, …)`（`:445`） |
| `stop_motors` 何时为真 | `src/lib/mixer_module/mixer_module.cpp:475` `bool stop_motors = !_throttle_armed && !_actuator_test.inTestMode();`（`_throttle_armed` 在 `:417` 由 `armed && !lockdown` 得出） |
| ★ **另一条"静默"分支**：若**所有输出都没分配功能**，驱动会**一个字节都不发** | `mixer_module.cpp:437-442` 算 `all_disabled`（任一 `_functions[i]` 非空即为 false）→ `:458-459` `if (!all_disabled \|\| !_was_all_disabled)` 才往下走。**本机 `PWM_MAIN_FUNC1..4 = 101..104` 已分配 ⟹ 按源码应当发帧** ⟹ 要落到"实机 `dshot` 驱动到底起没起"（§四 T3） |

⟹ **「电调报无信号」等价于「帧真的没到」**：要么**发端停了**（驱动没起来 / FMU 重启或挂死），
要么**链路断了**（信号线 / 地线 / 连接器），要么**电调自己掉电重启**。
**不是**「PX4 在未解锁时故意不发」—— 这条可以直接从候选里划掉。

### 2.3 ★ 与 ticket 20 的接口（含一处**撤回**）

本票初版写过一条"反向判据"：*「当前 mavros 至今没有 `Lost connection` ⟹ 飞控没重启 ⟹ 候选 A 当场排除」*。
**这条是错的，现予撤回。** 20 号票随后用两条独立证据把**飞控反复重启**钉死了：
`sess251…sess258` 共 **8 次开机**（06:31:26 → 07:54:17，间隔 10.7–15.3 min），
且每个 ulog 文件头都显示**开机后 <1 s 开始记录**（`sess253/254/255` = 0.780 / 0.756 / 0.780 s）⟹ 每个 session 就是一次开机。

**我那条推断为什么会错**（机制，已核 mavros 源码）：mavros 不是"连续 N 秒收不到 HEARTBEAT 就报"，而是
`conn_timeout`（**默认 10.0 s**，`mavros/src/plugins/sys_status.cpp:512`）到点就跑一次
`timeout_cb()`（`:1311-1313`）**无条件**置 `connected=false` 并打印（`mavros/src/lib/mavros_uas.cpp:462`）。
⟹ **短于一个周期的重启会被整个漏掉**（两次点火之间只要来一帧 HEARTBEAT 就恢复）
⟹ **mavros 日志是差劲的重启探测器，不能拿它当反证。**
（★ 附带更正：20 号票 §二 把这个阈值写成"连续 5 s"，与源码不符 —— 是 **10 s 周期定时器**，不是静默判据。已在其 Comments 里注明。）

### 2.4 ★ 修正后仍存在的一处张力：「一直响」⟷「每 11 分钟重启一次」

重启窗口只有几秒（20 号票实测多数停机 < 5 s），**重启完 PX4 的 `dshot` 驱动会重新起来发帧**
⟹ 电调本该安静下来。用户答的是「**一直响**」⟹ 这要求 **DShot 在重启之后也没有恢复**。
两种可能：

- **A′**：重启窗口的确会响，但**某个时刻之后 DShot 再没恢复**（那么"响"是从那次起一直持续）——
  指向"驱动起不来"这一层（C），而**重启是它的诱因**；
- **A 不成立**（响与重启无关），落回 C/E/D/F。

**这条张力就是 §四 T1/T7 要判的东西** —— 判完这张票的候选表就能砍掉一半。

## 三、候选成因与判别

| # | 候选 | 它会让电调怎么响 | 判别手段 |
|---|---|---|---|
| **A** | **飞控硬故障 / 重启窗口**（= [ticket 20](20-fcu-hardfault-i2c1-crash-dump.md)）**★ 现居第一位** | 响几秒后自己停（重启完就恢复） | 把"开始/停止滴滴"的墙上时刻与 `sessNNN` 列表对齐（T7） |
| **A′** | **重启之后 DShot 再没恢复**（驱动起不来 / 卡在故障态） | **从某一次重启起一直响** | 与 A 同一次对齐即可分辨：响的**结束**时刻有没有对上"PX4 重新起来" |
| **B** | 飞控根本没起来（卡在启动 / 反复 boot） | 一直响 | 排除：用户答"能连飞控" |
| **C** | `dshot` 驱动没起来 / 中途退出（飞控本身正常） | 一直响 | ★ **QGC MAVLink Console：`dshot status`**（T3）；ulog 里 `actuator_outputs` 在不在更新（T4） |
| **D** | 供电 / 接地（ESC 由电池供电而 FC 由 USB 供电、BEC 掉压、**低电量**） | 低电量/掉压时出现 | `/mavros/battery` 曲线 ↔ 滴滴时刻；**换满电包复现** |
| **E** | 信号排线 / 连接器（MAIN1–4 ↔ 4-in-1，尤其**地线**） | 可能只响某几个 | T3 点转单电机；T5 量信号脚 |
| **F** | 协议不匹配（DShot300 vs 电调实际固件） | **从一上电就响**，不会「过一会儿」 | 与用户所答「上电一分钟以上才开始」不符 ⟹ 基本可排除；仍可 T6 对照 |

★ 20 号票 §六.3 已把**供电**列为"~11 min 周期性"的待排除项；若 A/A′ 与重启对得上，
则 D 与 A 可能**同源**（掉压 ⟹ 硬故障 ⟹ 重启），不要当成两条独立的线。

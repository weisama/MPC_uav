# 02: 入口层裁剪与状态订正（`CLAUDE.md` / `README.md` / `PROJECT.md` / `CONTEXT.md`）

Status: ready-for-agent
Type: task

**What's wrong（一句话）：** 入口层**读不完、也说不清"现在到哪"** —— 一个上下文是空的人/agent
读完 `CLAUDE.md` → `README.md` → `docs/PROJECT.md` → `CONTEXT.md` 之后，**仍然不知道该读哪份 spec、
哪些票还没结**；而且里面有一批**状态词与写死的读数**早就过期了，读起来像"已完成"，其实不是。

**为什么它排在这一阶段的最前面**：入口层是"该读什么"的那张地图。地图不准，把正文裁得再干净
也没人找得到 —— 所以本阶段**先做这一票，再做 [03](03-docs-index-status-and-obsolete-block-compression.md)**。

## 要做的三件事

### ① 阅读路径：从入口层能一次落到"当前在哪"

- 入口层四份要能回答三问：**项目在哪一步 · 下一步做什么 · 该读哪份文档**；
- 落到的东西：当前阶段的 `spec.md` + **未结票清单**（`.scratch/*/issues/` 里 `Status ≠ done` 的那些）；
- **路径全部是活的**：从入口层点到任何一份东西，不能有断链。

### ② 状态订正：状态词与读数一律换成**可核的锚**

- 「未 build」「已收口」「余量 6.4×」这类说法，要么**删掉**，要么换成**指向票号 / 命令 / 文件**的锚；
- ★ **状态词比写死的数更毒**（数至少能看出是旧的；"已收口"看起来永远成立）；
- 已经在本阶段落地前订正过一次的（`README.md` 的版本块 + Phase 2 状态格）**不要改回去** ——
  那一次的取舍是"**不在这格抄读数**，进度以各票 `Status:` 行为准"，本票延续这条。

### ③ 三处索引互相对得上

`README.md` 的目录树 / `docs/PROJECT.md` 的总纲 / `CONTEXT.md` 的术语表，三者指向的
spec 与文档**必须是同一批**，且都指到**顺延后**的路径（`phase4/`，不是 `phase3/`）。

## Comments

### #1 为什么它 `ready-for-agent`

纯文档整理：不碰飞机、不碰飞行代码、不需要现场。判据也是文档级的（断链 + 锚 + 守卫用例），
一个 AFK agent 能自己判绿。**唯一要人看一眼的是「状态订正」**：把某个状态词换成什么锚，
涉及"这句话现在还算不算数"的判断 —— 所以验收第 2 条写的是"**不再出现写死的读数**"，
而不是"改成了我认为对的说法"。

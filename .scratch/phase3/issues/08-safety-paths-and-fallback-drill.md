## 逐条实测

- [ ] **打杆接管**：遥控器任意打杆 → 程序**立刻停止发布 setpoint**，**不自己切模式**；落点由 PX4 按 `COM_OBL_RC_ACT` 决定 —— 这是一个**参数化的、可预演的**行为，不是我藏在代码里的逻辑
- [ ] **急停 / 开始通道**实测读数与通道分配的决定一致，且**不与 PX4 模式开关（`RC_MAP_FLTMODE`）共用通道** —— 两者不得互相触发
- [ ] **offboard 心跳丢失** → PX4 按预配置动作执行（`COM_OF_LOSS_T` → `COM_OBL_RC_ACT`），机载节点崩溃不会导致飞机飞走
- [ ] **节点崩溃注入**：主动杀掉 MPC（模型预测控制）节点，确认这条路径在**我需要它之前**就已经被走通过
- [ ] **求解失败注入**：在实机链路上让求解失败发生一次，确认行为与 SITL 里一致（保持安全悬停，**不发错指令**）
- [ ] **回退 (A) 级**：一次确定的、演练过的操作 —— 确认 Phase 1 整条链仍在、随时可用，且**切换动作本身演练到位**
- [ ] 每条实测留下证据（读数 / 日志 / 现象），不是"试过了没问题"

## FSM 审计（**只审计，不新写代码** —— 实现归 Phase 2 的安全工作）

- [ ] 逐条对照 [`xi35-fsm.md`](../../../docs/reference/xi35-fsm.md) 的转换表，确认控制权 × 任务态两个维度**确实是显式分开**的，且转换条件与语义**逐条对得上**（对齐的是**条件与语义，不是代码行**）
- [ ] 显式确认那三处死代码**没有被照搬进来**：恒假的 `emergency_hover`（紧急悬停功能实际不存在）、`kf_fusion_fail` 的**单向 latch**（一旦置位只能手动着陆）、无法清除的 `search_hover`（只能重启才能退出）。z0 需要的是**可判定、可复位**的失效降级路径
- [ ] 每处相对参考实现的改动**在代码注释里带编号与出处**（形如 `// ported from XI35 PX4CtrlFSM.cpp:183`），使审查能逐条核对而不必重新推导 —— **不另建映射文档**
- [ ] 审计结论写进文档；若发现语义对不上，**记进本文件的 Comments 并回链**，而不是就地改代码

## Problem Statement

Phase 2 干了很久，产出摊得很开：27 张票、20 来份 `docs/`、几套工具与证据。它的**结论大多是对的**，问题是**读不动了**：

- **入口层说不清"现在到哪"**。`README.md` 的版本块与三阶段表长期停在 Phase 1 收口那一刻（★ 已在本阶段落地前订正过一次），`docs/PROJECT.md` / `CONTEXT.md` 的索引与状态词各写各的。
- **作废的东西和活着的东西长得一样**。`docs/` 里 `☠️` 的作废块**保留了被划掉的原文**，一处作废动辄占掉几十行；一个新上线的 agent 得先读完整段划线文字，才知道结论已经翻掉了。
- **状态词与写死的读数会过期**。散文里散着一批"未 build""已收口""余量 6.4×"之类的说法，**没有一个带可核的锚**，读的人无法判断它还成不成立。

同时，Phase 2 有 **9 张票没结**（10 / 11 / 16 / 20 / 21 / 24 / 25 / 26 / 27），而它们是 **Phase 4 上实机的前置**：被控对象还差 3.92 倍、seam 3 的判据没跑满、有两条通道的权威问题悬着。**不收掉它们就上机，等于带着已知的未知量起飞。**

**从我的角度**：Phase 3 要交出来的不是"更漂亮的文档"，而是**一个能读得完、且读到的每句都还成立**的仓库 —— 以及**一张把 Phase 2 的账结清的清单**。

## Solution

### 甲 —— 整理：先裁"阅读路径"，再裁"文档正文"

**顺序是有意的**：先让入口层能一次说清，再动正文。理由是入口层就是"该读什么"的那张地图 —— 地图不准，把正文裁得再干净也没人找得到。

1. **入口层裁剪与状态订正**（`CLAUDE.md` / `README.md` / `docs/PROJECT.md` / `CONTEXT.md` 四份）：
   - 状态词与读数一律换成**可核的锚**（指向票号 / 命令 / 文件），**不写死数字**；
   - 三处索引（spec、票、docs）互相对得上：从入口层点到任何一份东西，路径都得是活的。
2. **`docs/` 里 `☠️` 作废块的压缩**：
   - **形式**：**保留节首的结论行**（含逐项点名"被推翻的是哪几项"）→ **删掉被划掉的正文**；
   - 判据：压缩后**只看节首那几行**，读者就能知道"这里原来写的什么、被谁推翻了、现在该看哪"。
3. **每一处删掉或搬走的东西必须标去向**：
   - 被推翻的 → 「**已被 X 推翻**（指向推翻处）」；
   - 换个地方放的 → 「**已搬进 §N**」。
   ★ **没有去向标记的删除一律算没做完** —— 这与"作废标记要放被作废那一节的**节首**并**逐项点名**"是同一条纪律。

⚠️ **`.scratch/**` 的票面内容不动**（Q4 / Q19）：票是当时的记录，☠️ 块在票里**保持原样**。
唯一的例外是 2026-10-08 那次**编号顺延**（见 Further Notes ①）—— 那次动的是**路径与指向将来的说法**，
票面的结论与 `Status:` 一个字没改。

### 乙 —— 收尾：把 Phase 2 那 9 张票结掉

逐票的来历、必要性、可行性与处置见 Further Notes ② 的**收尾清单**（操作者 2026-10-08 逐张裁定）。
总的口径三条：

1. **能 AFK 做完的现在就做**（`21` 重搭被控对象：纯离线，它的前置已经满足）；
2. **做不完的要把"做不了"写清**：写成**已知风险 + 重开条件**，不许留一句"待办"了事；
3. **只有人能做的（起链 / 起录 / 解锁 / 真机飞）不由 agent 执行** —— agent 只报时机与读数。

## User Stories

### 甲 —— 整理

1. 作为一个**刚上线、上下文是空**的 agent，我要能只读入口层（`CLAUDE.md` → `README.md` → `docs/PROJECT.md` → `CONTEXT.md`）就回答出"这个项目在哪一步、下一步该做什么、该读哪份文档"，**而不用先读完 `docs/control/` 一整片**。
2. 作为**操作者**，我要 `docs/` 里每一处作废都能**只看节首**就判断出"这里作废了什么、现在信哪个"，不必读完划掉的原文。
3. 作为**读文档的人**，我要任何一句状态判断都**带着可核的锚**（票号 / 命令 / 文件路径），这样它过期时我**看得见**，而不是被一句"已收口"骗过去。
4. 作为**要动这块代码的人**，我要"某段话被推翻了吗"能顺着"已被 X 推翻"的指针**一次跳到推翻处**，而不是在仓库里搜关键词。

### 乙 —— 收尾

5. 作为**要上实机的人**，我要 SITL 被控对象的推力满量程**与真机实测一致**（现在差 3.92 倍），否则 A/B 两档的全部读数都带一个已知偏差。
6. 作为**要判 Phase 2 能不能收口的人**，我要 seam 3 的判据**跑满**（不是"看着还行"），并且判据②飞的是**当前规格**那条轨迹（1 m 八字）。
7. 作为**要上实机的人**，我要每一条"暂时不修"的问题都写成**已知风险**、并**写明什么条件下必须重开**，这样它不会在实机上静默地咬人。
8. 作为**操作者**，我要这次收尾**不夹带**任何需要我亲手做的事（起链 / 起录 / 解锁 / 真机飞）被 agent 代跑。

## Implementation Decisions

### 整理的边界

| 决定 | 理由 |
|---|---|
| **只改 `docs/` 与入口层四份**；`.scratch/**` 票面不动 | 票是记录（Q4 / Q19）。改票面 = 改历史 |
| `☠️` 压缩**只保留节首结论行**，删划线正文 | 见 Solution 甲·2；这是"作废标记放节首"那条纪律的落地形式 |
| **不新增文档层**（不加新的 `docs/xx.md`） | 本阶段的目标是**减**，加了就自相矛盾 |
| 状态词换成**锚**，不写死数字 | 散文里写死的数会过期；"未 build""已收口"这类**状态词比数更毒** |

### 收尾的边界

| 决定 | 理由 |
|---|---|
| `21`（重搭 SITL 同构机）**现在做** | 纯离线；前置（20 的两场飞完并归档）**2026-09-30 已满足** |
| `11` 只差**一场 `T0`** | 判据① 已双过；②③④ 的现状见票面 |
| `16` **并入 `25`** | 两票是同一族的两半（镜像井 = **符号**，死通道 = **幅值**） |
| `24` / `25` **标签不动**（`needs-triage`） | 「归谁 / 按哪个落点」是**操作者保留的裁定**，不是 agent 能 promote 的 |
| `10` 降级为"**从已归档的飞控日志读**" | 不必新开台架日：`bag/*/fcu/*.ulg` 里就有 |

### 术语纪律

- 光写「MPC」不算数：一律写 **MPC（模型预测控制）** 或带完整参数名（同 `README.md` / `CONTEXT.md`）。
- 「Phase 3」在 **2026-10-08 之前**写的文档里指的是**实机飞行**，也就是**现在的 Phase 4** ——
  对照表与清扫口径见 [`phase4/README.md`](../phase4/README.md)。

## Testing Decisions

**甲乙各自的验收判据分开算**（Q16）—— 甲的绿不能顶乙的账，反之亦然。

### 甲 —— 整理的判据（三条，缺一不可）

1. **入口层自足**：只按入口层的指针走，能落到"当前阶段 spec + 未结票列表"，**路径全部是活的**（没有断链）。
2. **每一处删除都有去向**：抽检 `☠️` 压缩过的每一节，节首必须能回答"被谁推翻 / 搬到哪"（Solution 甲·3）。
3. **文档守卫全绿**：`python3 -m pytest run/tests/test_operation_manual.py -q` 等按文件跑（★ **别一次跑 `run/tests/` 整个目录** —— `test_z0_check_live.py` 的模块级 `importorskip` 会让其余文件一条都不收集而退出码仍是 0，见 [ticket 26](../phase2/issues/26-recording-six-scenes-and-the-rewrite-path.md) 的同名记录）。

### 乙 —— 收尾的判据

**逐票判**，判据在**各票自己的验收节**里（本 spec 不重抄）。本阶段的收口条件是：

1. Further Notes ② 那张清单里**每一行**都有终态 —— 要么 `done`、要么 `wontfix`、要么"已知风险 + 重开条件"；
2. 涉及代码/工具的（`21` 重搭、`T0` 接线）要留下**可复跑的判据**（`run_matrix.sh` 一次批量跑完 A/B 两档 + 判据②）；
3. ★ **不许把 `needs-triage` 自己 promote 成 `done`** —— 那两条的终态由操作者给。

### 好的测试是什么（沿用 Phase 1/2 的纪律）

- **能区分对错的那一列**才算判据（只比均值会漏掉 27 倍差那种）；
- ★ **新断言要主动弄坏一次**，确认它真的会红；红不了就是没有鉴别力；
- 求解器的输出用**容差断言**（QP 解出来的是 `8e-18` 不是 `0`）；
- **离线自证替代不了实跑** —— 它只能证伪红线与量级。

### 被"整理"的模块

没有代码模块被整理。被整理的是 `docs/**` 与四份入口层文档，守卫是上面那几条文档用例。

### ④ 几个必须提前知道的坑

- **`/tmp` 过不了重启**（根盘 ext4 + tmpfiles 里一条 `D /tmp`）。同一次开机内持久，但**一手证据必须当场落仓库**。
- **归档证据不就地改**：`tools/px4-sitl/evidence/` 下的 JSON 是"那一趟跑出来的那份"，改了就不是它了。
- **`run/tests/` 不能一次跑整个目录**（见 Testing Decisions 甲·3）。
- **`colcon build` 有原子性**，同仓库可能有并行会话 ⟹ 提交前重看 `git status`，只 `add` 自己的路径。

## Problem Statement

Phase 2 结束时，我有一条**在 SITL 里闭环验证过**的 (C) 级 MPC 路径：符号映射被逐条验过、推力归一化有量纲依据、求解失败的兜底路径被主动注入过、最坏求解耗时是实测的。**算法层面的疑问基本清空了。**

但"仿真能飞"和"真机能飞"之间隔着一堆**仿真里不存在的量**：真实的动捕→飞控端到端延迟（实测 ~50 ms）、真实的推力标定（电池受限的 `T_max` 与悬停油门）、真实的动捕↔IMU 外参、真实电池在负载下的电压跌落，以及一批**只能上机才读得出来**的参数。这些量在 SITL 里都是我给的——我给的值对不对，SITL 不会告诉我。

而 **(C) 级的容错空间和 Phase 1 完全不同**。Phase 1 我把位置发错了，PX4 的位置环会把它拉回来，飞机顶多飘一下；(C) 级我把符号发反了或者推力算错了，**飞机直接朝错的方向加速**。更糟的是这些错误**全都不报错**——PX4 收到一条语法完全合法的消息，然后照做，我只有从飞行日志里才能分辨是哪一环错了。

**从我的角度**：Phase 3 的核心不是"再写代码"，而是**把每一个能在天上摔机的未知量，在离地之前逐个变成已知量**；剩下的真不确定性，用一套**每级只有一个新变量**的阶梯去逼近。

**不改控制律，改的是它脚下的地基。**

1. **四项前置测量**（全部在装桨之前完成）：电机实际位置、`MPC_THR_HOVER` 悬停油门、动捕↔IMU 外参、延迟 `τ`。
2. **一次固件重编重刷**：~~把 ADC 电流采样的一行修复（`CH(5)`→`CH(8)`）打在 z0 固件真身 `5ba2e91f` 上~~
   —— ☠️ **2026-09-23 更正：这一条整句作废。** ① **对象错**：`5ba2e91f` 是**与 z0 无关**的 fork，真身是 `Minderring/PX4-Autopilot` @ `4a0e65f2`（v1.14.3 系的 MicoAir 厂商构建）；② **修法错**：那个 `CH(5)`→`CH(8)` 修的是 `boards/hkust/nxt-dual`，而**真身树里没有 `hkust/`**，`boards/micoair/h743-aio` 写的是 `/* PC1 */ ADC1_CH(11)`，**与引脚相符、本来就没有这个缺陷**（2026-09-21 上电实测亦判「未中招」，见 [`params-changes.md`](../../docs/reference/params-changes.md) §A4）。
   **⟹ 仍要做的是**：确认**该编哪块板级目标**（板名 `NxtPX4v2` 与真身树里的 `micoair/{h743, h743-v2, h743-aio}` 对不上，见 [`refs-manifest.md`](../../docs/reference/refs-manifest.md) §2.5(d)④），重编后**重新记录飞控实际报出的版本号** `flight_sw_version` / `flight_custom_version`。（"为什么还要重编" → 见 Further Notes。）
3. **参数落地**：按 [`params-changes.md`](../../docs/reference/params-changes.md) 执行首飞阻塞项（尤其 `NAV_RCL_ACT = 1` Hold），并导出 z0 自己的参数与参考表 diff。
4. **四级实机阶梯**：拆桨看方向 → 系绳离地 20 cm → 系绳闭环悬停 → 自由飞三条轨迹。**每级停下来看日志，不通过不进下一级。**
5. **保留 Phase 1 回退**：任何时刻可退回 (A) 级控制。

## User Stories

### 前置测量（全部在装桨之前）

1. 作为操作者，我想先**实测四个电机的实际位置**，再决定要不要动 `CA_ROTOR0..3_PX/PY`，这样我改的是一个测出来的数，而不是一个猜出来的数。
2. 作为开发者，我想在实测后**先判断几何偏差是否只是均匀缩放**（`PX == PY` 整体等比），这样我能知道 `MC_*RATE_*` 到底要不要重调 —— 因为均匀缩放会被分配器的归一化**完全约掉**（第一手证据见 [`params-analysis.md`](../../docs/reference/params-analysis.md) §3.1）。
3. 作为开发者，我想在几何**不是**均匀缩放时才改 `CA_ROTOR*_PX/PY` 并**同时重调** `MC_*RATE_*`，这样我不会只改一半而留下一个配错的角速率环。
4. 作为操作者，我想**实测悬停油门**并从 Phase 1 的悬停日志反推它，这样 MPC 模型的**工作点**匹配这台飞机而不是参考机架。
5. 作为开发者，我想让实测的悬停油门**同时回填 PX4 与 MPC 两处**（`MPC_THR_HOVER` 与 MPC 模型里的 hover thrust），因为 PX4 对 `thrust_body` 不做任何重标定 —— **只改一处就是一个静默的推力增益错误**。
6. 作为操作者，我想**实测动捕刚体原点↔IMU 中心的偏移**并回填 `EKF2_EV_POS_X/Y/Z`，这样位置估计里不带一个常值偏移。
7. 作为开发者，我想在动捕刚体原点**刻意定义在 IMU 上**时确认 `EKF2_EV_POS_* = 0` 是**正确**的（而非遗漏），这样我不会把"对"当成"没做"。

### 固件与参数

8. 作为操作者，我想在首飞前**导出 z0 自己的飞控参数**并与参考表 diff，因为参考参数文件是**另一台机器**导出的，差异才是真正要改的东西。
9. 作为操作者，我想把 `NAV_RCL_ACT` 从 `2`（Return）改成 **`1`（Hold）**，因为在室内无 GPS、home 点不可靠的环境里，遥控一掉 PX4 会尝试**返航**。
10. 作为开发者，我想在固件重刷后**在 QGC 重新记录飞控实际报出的版本号**，因为这是版本问题的**唯一终审**，也是 `px4_msgs` 选版的依据。
11. 作为操作者，我想确认 `MC_BAT_SCALE_EN` **保持 0**，这样电池测量的噪声不会被升级成"控制环里的乘性干扰"。（☠️ **2026-09-23**：原先的理由"ADC 那个已知缺陷"已不成立 —— 那条缺陷不在 z0 的固件里；**结论不变**，理由收窄为上面这条一般性原则。）
12. 作为操作者，我想在**明确保留、不要动**的那批参数（`COM_RC_OVERRIDE`、`COM_RC_STICK_OV`、`EKF2_EV_DELAY`、`PWM_MAIN_FUNC*` 等）上不做"照默认值改回去"的动作，因为那批值是**刻意配过**的。

### 延迟标定

13. 作为开发者，我想把延迟 `τ` **从 Phase 1 的飞行日志里量出来**（交叉相关飞控 IMU 与动捕两条序列），而不是照抄一个文献值。
14. 作为开发者，我想让 `τ` **从 0 开始**逐次加，因为在这个环节**过补偿比不补偿更危险** —— 多外推一点就是在用错误的状态喂控制器。
15. 作为操作者，我想在实飞中**改变 `τ` 并对比**，这样我是用一个可观测的差异来定它，而不是相信一次测量的结果。

### 安全与回退

16. 作为操作者，我想让遥控器**任意打杆**时程序**立刻停止发布 setpoint**，而不是自己去做模式切换，这样接管走的是 PX4 自己的、已被验证的路径。
17. 作为操作者，我想让打杆后的落点由 PX4 按 `COM_OBL_RC_ACT` 决定，这样这个行为是**参数化的、可预演的**，不是我藏在代码里的逻辑。
18. 作为操作者，我想有一个**不与 PX4 模式开关共用频道**的急停/开始通道，这样两者不会互相触发。
19. 作为操作者，我想让 offboard 心跳丢失时 PX4 按预配置动作执行，这样机载节点崩溃不会导致飞机飞走。
20. 作为操作者，我想让**返回 Phase 1 的 (A) 级**是一次确定的、演练过的操作，而不是出事时才想起来的应急手段。
21. 作为操作者，我想让 MPC 节点崩溃这条路径在实飞前**被主动注入验证过**，而不是等它在天上第一次发生。

### 实机阶梯

22. 作为操作者，我想让第一级**拆掉桨叶**只做地面验证，这样符号错误不会造成伤害。
23. 作为操作者，我想让第一级只给 **±小角速率**并目视电机转速差方向，这样符号错误在离地之前就暴露。
24. 作为操作者，我想让第二级**系绳并只离地 20 cm**、只给悬停推力，这样即使控制发散也不造成损坏。
25. 作为操作者，我想让第三级**系绳闭环悬停 30 s**，这样我在完全自由之前拿到一次真实的闭环稳定性证据。
26. 作为操作者，我想在第四级自由飞时**按 Phase 1 的同一套三条轨迹**（1 m 悬停 / 1 m 正方形 / 0.5 m 八字）验证，这样 MPC 与 (A) 级有一个**同口径的对比**。
27. 作为操作者，我想让每一级的**判据在起飞前就写定**，这样"这级算不算过"不是事后看感觉定的。
28. 作为操作者，我想让 MPC 频率**以 Phase 2 实测的最坏耗时为准降档**，而不是沿用仿真里的数字。

### 可解释性

29. 作为未来的协作者，我想让每一处相对参考实现的改动**在代码注释里带编号与出处**（如 `// ported from XI35 PX4CtrlFSM.cpp:183`），这样审查时能逐条核对而不必重新推导。
30. 作为开发者，我想让**哪些结论是第一手读源码得来的、哪些是推断**在文档里继续被区分，这样后来者知道哪些能信、哪些要复核。
31. 作为研究者，我想让 MPC 内部状态、求解耗时、约束饱和标志、实际指令与实际状态被完整记录，这样飞行后我能复盘而不只依赖记忆。
32. 作为研究者，我想让`τ` 的取值与它的来源（哪次飞行、哪个相关峰）被记录，这样这个数字不是从一个我没法追溯的地方来的。

## Implementation Decisions

### 控制层级与复用

- **控制层级仍是 `(C)` 级**（总推力 + 机体三轴角速率），**MPC 节点与 Phase 2 是同一份代码**，本阶段不重写控制律。理由：Phase 2 已在 SITL 里逐条验过符号、量纲与兜底路径，**在实机阶段引入新代码 = 引入无法归因的变量**。
- **`(A)` 级整条链保持可用**，随时可退回。Phase 1 的 `control` 与 `mocap` 包不做破坏性改动。
- **回退演练属于本阶段范围**，不是可选项：没演练过的回退路径不算回退路径。

### ★ 四项前置测量（全部在装桨之前）

| # | 量什么 | 为什么 | 落到哪 |
|---|---|---|---|
| P1 | **四个电机的实际位置** | `CA_ROTOR0..3_PX/PY` 现值是 PX4 Generic Quad X 的默认半展，比 z0 实际几何**大 2.79×** | 先判是否**均匀缩放** → 是则**不动**（被分配器归一化约掉）；不是才改几何**并**重调 `MC_*RATE_*` |
| P2 | **悬停油门** | 它是 MPC 模型的工作点；`MPC_THR_HOVER = 0.5` 恰是 PX4 默认值，看不出被改过 | **同时**回填 PX4 `MPC_THR_HOVER` 与 MPC 模型 —— **只改一处 = 静默推力增益错误** |
| P3 | **动捕刚体原点 ↔ IMU 中心外参** | `EKF2_EV_POS_X/Y/Z = 0/0/0`；若刚体原点**刻意定义在 IMU 上**则 `0` 是对的，否则位置估计带常值偏移 | `EKF2_EV_POS_X/Y/Z` |
| P4 | **端到端延迟 `τ`** | 外部状态输入的固有延迟，控制器无法消除，只能补偿 | Phase 2 已实现的一行状态外推的 `τ` 参数 |

### 延迟 `τ` 的标定

- **量法**：交叉相关**飞控 IMU** 与**动捕**两条序列（来自 Phase 1 的同一段飞行日志），取相关峰。
- **从 0 开始**，逐次加。**过补偿比不补偿更危险** —— 那等于用错误的状态喂控制器。
- 补偿形式沿用 Phase 2 的**一行状态外推**（`x + v·τ`），不做完整延迟补偿。

### 安全与回退

- **遥控打杆接管**：程序**立刻停止发布 setpoint**，不自己切模式；接管后的落点由 PX4 按 `COM_OBL_RC_ACT` 决定。这个方案的真实参数基础是 z0 已**刻意配强**过的 `COM_RC_OVERRIDE = 3` 与 `COM_RC_STICK_OV = 20`。
- **急停/开始通道**：不与 PX4 模式开关（`RC_MAP_FLTMODE`）共用通道。
- **offboard 心跳丢失**：由 PX4 的失效保护处理，程序侧不试图自己兜。
- **回退 (A) 级**：一次确定的、演练过的操作。

### 状态机

**两个正交维度**显式分开（控制权 × 任务态），转换条件逐条对齐 `Fast-Drone-XI35` 的 `PX4CtrlFSM`
（其超时/电压/RC 接管判据经过实机验证）—— **转换条件表见 [`xi35-fsm.md`](../../docs/reference/xi35-fsm.md)**。
**对齐的是条件与语义，不是代码行**（Q1=a：设计移植，不抄行）。

### 溯源纪律

- **出处写在代码注释里**（`// ported from XI35 PX4CtrlFSM.cpp:183`），**不另建映射文档**（Q8=b）。
- 新增/改动的每一处都带编号与理由，便于逐条审查。

## Testing Decisions

> ★ **本 spec 不新增任何 seam**（2026-09-20 确认）。全项目一共只有 **2 种自动化 seam 形态**
> （形态 A：喂脚本输入 + 断言发出话题 + 假 peer；形态 B：在话题边界没有诊断分辨率处开更细的 seam）
> —— 定义与实例盘点见 [`phase1/spec.md`](../phase1/spec.md) 与 [`phase2/spec.md`](../phase2/spec.md)。
>
> 本阶段**复用 phase2 的 seam 1**（重跑一次，换实机参数），实机阶梯则是**已有的人工关卡形态**，
> 不算新 seam。**这是刻意的：seam 越少越好，而实机阶段本来就不该靠自动化覆盖。**

### 好的测试是什么

**在实机阶段，"测试"的主体是阶梯判据，不是自动化测试。** 沿用 Phase 1 / Phase 2 已确立的形态：
自动化测试只在**能注入故障**的地方开，实机阶梯则靠**起飞前写死的量化判据**。

### 沿用：Phase 2 的 seam 1 在实机前**重跑一次**

MPC 节点的 ROS 话题边界测试（喂脚本输入 + 断言发出话题 + 假 PX4）**在实机前重跑**，
用实机参数而不是仿真参数。它挡住的是"搬到真机后参数/话题改错了"这一类错误，成本≈0。

### 实机阶梯（本阶段的主要判据）

| 级 | 做什么 | 判据 |
|---|---|---|
| 1 | **拆桨**，只给 ±小角速率 | 电机转速差方向与预期一致；**方向错就停，不进下一级** |
| 2 | **系绳 + 离地 20 cm**，只给悬停推力 | 推力方向正确、无异常振荡；能稳定悬停在该高度附近 |
| 3 | **系绳闭环悬停 30 s** | 悬停期间不发散、不持续漂移；日志里求解器无持续退化 |
| 4 | **自由飞**三条轨迹 | 与 Phase 1 同口径的稳态误差对比；三条轨迹都能完成 |

**每级的量化阈值在起飞前写定**，不事后调。

### 被测试的模块

MPC 节点（复用 Phase 2 的 seam 1，重跑）、实机阶梯（手动，但有写死的判据）。
**控制律本身不测** —— 它已在 Phase 2 的 SITL 里验过，重测等于重复劳动。

### 先例

Phase 1 / Phase 2 的 seam 1 形态；Phase 1 的实机验证顺序（拆桨 → 系绳 20 cm → 系绳闭环 → 自由飞）
是本阶段阶梯的**直接先例**，本 spec 只是把它从 (A) 级搬到 (C) 级并补齐了前置测量。

### ⚠️ 依赖关系（发布为 issue 时应建立阻塞边）

**Phase 3 被三件事硬阻塞：**

| 阻塞 | 性质 | 说明 |
|---|---|---|
| **Phase 2 的 SITL 达标** | 流程性 | 包括它的 seam 3 量化判据与实测最坏求解耗时。**没有这个数字就定不了实机 MPC 频率** |
| **`hover_thrust` 的实机测量** | ★ **技术上硬阻塞** | 唯一"测不准就飞不起来"的参数，**只能从 Phase 1 的悬停日志反推**。Phase 2 的验收也被它阻塞 —— 所以它其实是 **Phase 1 → Phase 2 验收 → Phase 3** 这条链上的公共依赖 |
| **固件重编重刷**（☠️ ~~ADC 一行修复~~ —— **修法已作废**） | ★ **阻塞，不阻塞 Phase 1/2** | 排在实机飞行之前（Q37=a）。它依赖 Phase 2 建立的那棵树的构建环境，所以**顺序上必须在 Phase 2 之后**。⚠️ **动手前必须先定板级目标**（见 §固件：一次、且只有一次重编重刷） |

**→ 这意味着 Phase 3 不能与 Phase 1/2 并行开工**，它的每一步都以"飞机已被验证过"为前提。

### ⚠️ 几个必须提前知道的坑

1. **`thrust_body` 是 `[-1, 1]`，不是 `[0,1]`、不是牛顿** —— 符号写反会**全速砸地**。
2. **`thrust_body` 不受 `MPC_THR_HOVER` 影响** —— 模型里的悬停油门与推力换算常数必须自洽（P2 就是为此）。
3. **求解失败必须活着** —— 节点一崩，offboard 心跳停发。
4. **打杆接管不要自己切模式** —— 让 PX4 按 `COM_OBL_RC_ACT` 走它自己的路径。
5. **重刷固件后必须重新导出参数做 diff** —— 是否会被重置**本轮未核实**，不假设任一方向，只按"必做"执行。

### 术语纪律

**禁止在输出中单独使用裸词 `MPC`**。本项目里 `MPC`（模型预测控制）与 PX4 的 `MPC_*` 参数前缀
（Multicopter Position Controller，级联 PID）**是两个毫不相关的东西**。详见 [`../../CONTEXT.md`](../../CONTEXT.md) 开头。

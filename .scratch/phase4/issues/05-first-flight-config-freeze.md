# 05: 首飞配置冻结 —— PX4 参数集 + MPC（模型预测控制）节点参数

Status: ready-for-human
Type: task

**What to build:** 一份**冻结的**首飞配置，两个半边：飞控参数，和机载 MPC（模型预测控制）节点的参数。

**冻结的意思是**：从本票之后到阶梯 4 结束，**每一级只有一个新变量**（阶梯本身引入的那一个除外）。任何"顺手调的"参数都是无法归因的变量。

**Blocked by:** [01](01-geometry-and-extrinsics.md)（几何判定结果）、[02](02-hover-thrust-backfill.md)（悬停油门实测值）、[03](03-latency-tau-from-logs.md)（τ），以及跨 feature 的 [`phase2/issues/09-sitl-tier-a-closed-loop.md`](../../phase2/issues/09-sitl-tier-a-closed-loop.md) —— **实测最坏求解耗时**，没有这个数字就定不了实机 MPC（模型预测控制）频率。

## 飞控参数

- [ ] `NAV_RCL_ACT` 从 `2`（Return）改成 **`1`（Hold）** —— 室内无 GPS、home 点不可靠，遥控一掉 PX4 会尝试**返航**。⚠️ 该参数**没有 `0`**（合法值仅 `1/2/3/5/6`）；**`5 Terminate` / `6 Disarm` 绝对不要用**
- [ ] `MC_BAT_SCALE_EN` 确认为 **0**
- [ ] 几何那一半按 [01](01-geometry-and-extrinsics.md) 的判定结果落地 —— **改或不改都要写明**，不改的也要写"为什么正确地不改"
- [ ] ★ **「明确保留、不要动」那批参数逐条确认保持原值**（`params-changes.md` D 节）—— 它们是**刻意配过**的：`COM_RC_OVERRIDE = 3` 与 `COM_RC_STICK_OV = 20` 是**打杆接管方案的真实参数基础**，`EKF2_EV_DELAY = 50.0` 与用户实测的 50 ms 完全一致。**不要做"照默认值改回去"的动作**

## 节点参数

- [ ] MPC（模型预测控制）频率**按 Phase 2 实测的最坏耗时降档**，而不是沿用仿真里的数字；降档依据（哪个数字、哪个验收线）一并记录
- [ ] τ 的起始值 = **0**（[03](03-latency-tau-from-logs.md)）；实飞中的加档安排在 [10](10-ladder-closed-loop-and-free-flight.md)
- [ ] 延迟补偿的形式确认仍是**一行状态外推**，**没有夹带完整延迟补偿**
- [ ] 推重比复核：地面拉力台或 Phase 1 悬停时的油门裕度，验证 `T_max` 的依据（电池受限时真实可用推重比只有 1.60–2.54）

## 冻结本身

- [ ] 全部改动**逐条带编号与理由**（沿用 Phase 2 的 M 编号体系）**与出处**，使审查时能逐条核对而不必重新推导
- [ ] 改动清单写入 [`params-changes.md`](../../../docs/reference/params-changes.md)（或另立一节）并从本文件回链
- [ ] 冻结之后到阶梯 4 结束，任何新的参数改动都要能被追溯到**某一级的判据**，而不是"顺手调的"
- [ ] 明确区分：本票里哪些结论是**第一手读源码/实测**得来的、哪些是**推断** —— 后来者要知道哪些能信、哪些要复核

# 01: 装桨前台架几何测量 —— 电机实际位置 + 动捕刚体↔IMU 外参

Status: ready-for-human
Type: task

**What to build:** 两个只能拿卡尺在飞机上手量、且**必须在装桨之前量完**的几何量：四个电机的实际位置，和动捕刚体原点相对 IMU 中心的偏移。

两半都是「测量 + 一个判定」，**都不是「改一个数」** —— 各自的判定逻辑不同，"没做对"长什么样也不一样，见下面两组判据。

**Blocked by:** 无（本 feature 内可立即开工）。但**外参那一半**依赖动捕链路已通 —— 跨 feature 依赖 [`.scratch/phase1/issues/04-mocap-relative-pose.md`](../../phase1/issues/04-mocap-relative-pose.md)；几何那一半不受它阻塞。

## 几何（P1 / `params-changes.md` A2–A3）

⚠️ **关键不是「改」，是「先判断」。** `CA_ROTOR0..3_PX/PY` 的现值是 PX4 Generic Quad X 的默认半展，比 z0 实际几何**大 2.79×** —— 但多旋翼分配器按几何**自身范数**归一化，**均匀缩放会被完全约掉**。所以"改了会不会有效果"取决于实测结果，不取决于几何是否写错。

- [x] 四个电机的实际位置实测（机体系 x 前 / y 右 / z 下），并算出实际轴距 —— ★ **2026-10-09 以「机架规格 + 操作者现场复认」取得，不是卡尺读数**（证据等级见下表）
- [x] **先判断是否只是均匀缩放**（`PX == PY` 整体等比），而不是先改数
- [x] 若是均匀缩放 → **不动** `CA_ROTOR*_PX/PY`，并把「为什么不改」写进文档（否则后来者会以为这是遗漏）
- [x]（**分支未触发** —— 判定为均匀缩放，见下）若不是均匀缩放（`PX ≠ PY` 或非正 X 布局）→ 改几何 **并同时重调** `MC_ROLLRATE_*` / `MC_PITCHRATE_*` / `MC_YAWRATE_*`；★ 重调后角速率环**必须重新验证**，不能只改一半留下一个配错的角速率环
- [x] 实测值与判定写进文档，并从本文件回链

### ★ 判定（2026-10-09，操作者现场确认）

| 项 | 值 | 证据等级 |
|---|---|---|
| 电机位置（机体系 x 前 / y 右） | **`(±0.0537401, ±0.0537401)` m**（= `±53.7401 mm`） | **推得**，不是卡尺读数（见下） |
| 轴距（电机对电机对角线） | **152 mm** | 机架规格（[`hardware.md`](../../../docs/reference/hardware.md) §1）+ 操作者 2026-10-09 确认「实测也一样」 ⟹ **两来源一致** |
| 单轴投影 `a` | `76 mm / √2 = 53.7401 mm` | 由对角线 + 「正方形」推得 |
| 布局形状 | **正方形**、正 X（`PX == PY`，四个象限各一） | 操作者 2026-10-09 直接确认 |

⚠️ **证据等级如实标注**：轴距**不是卡尺读数** —— 是「机架规格 152 mm」+ 操作者目视复认，两来源一致；
「正方形」是操作者确认的**定性**结论。全票**没有**逐轴卡尺数字，故 `a` 是**推得**而非**量得**。
（`z` 不需要量：竖直推力轴下 `PZ` 项在效能矩阵里整个消失。第一手：
`ActuatorEffectivenessRotors.cpp:208` 的 `moment = ct * position.cross(axis) - ct * km * axis`，
`axis = (0,0,±1)` 时 `position.cross(axis)` 与 `position.z` 无关、`km*axis` 项也只在 z 上。）

**与参数现值的关系 —— 是纯均匀缩放**：`±0.15 → ±0.0537401`，缩放因子
`0.0537401 / 0.15 = 0.35827`（即现值偏大 `1/0.35827 = 2.79×`）。
要判「是否只是均匀缩放」需要**两件独立的事**，本票两件都拿到了：
① **形状**是正方形（`PX == PY`）—— 操作者确认；
② **`a` 的值**—— 对角线 152 mm 已把它钉死（`2a² = 76²` ⟹ 唯一解）。
★ 单靠对角线**不够**：一条对角线分不出正方形与长方形，所以 ① 那一步不能省。

**结论：`CA_ROTOR0..3_PX/PY` 不动；`MC_ROLLRATE_*` / `MC_PITCHRATE_*` / `MC_YAWRATE_*` 也不重调。**

理由（第一手推导见 [`params-analysis.md`](../../../docs/reference/params-analysis.md) §3.1「★★ 2026-09-20 更正」）：
多旋翼分配器 `ControlAllocationPseudoInverse` 按**每一列自身的范数**归一化
（`ControlAllocation/ControlAllocationPseudoInverse.cpp:73-105`），roll 列的元素正比于 `CA_ROTOR*_PY`
⟹ 均匀缩放**在分配矩阵里被完全约掉**，改与不改对分配结果**无影响**；而角速率增益
（`0.15 / 0.15 / 0.2`）本来就是 PX4 出厂默认值（同上 §3.1）⟹ **没有"调好的"可弄坏**，也就无从重调。

**⛔ 别把这条读成「这里少做了一步」** —— 这是**判定结果**，不是遗漏。同一结论在
[`params-changes.md`](../../../docs/reference/params-changes.md) §A2/§A3、§I 表第 3 行各记了一次。

**这条读数真正的用途**（从来不是"改参数"）：`(D)` 方案（MPC（模型预测控制）直接出电机指令）
与**力矩饱和估计**必须在模型里用**真实几何** —— 本票给出的就是那个真值。落点：
[`params-changes.md`](../../../docs/reference/params-changes.md) §A2 / §A3 / §I 表第 3 行、
[`params-analysis.md`](../../../docs/reference/params-analysis.md) §3.1 与 §3.15(e)、
[`hardware.md`](../../../docs/reference/hardware.md) §1。
（`tools/px4-sitl/z0-plant/plant_spec.py` 里 `LEVER = 0.0537403…` 已经是这个值，与本节一致。）

## 电机序 / 物理口 ↔ 机臂角 / 桨转向（2026-09-28 由 [phase2/08](../../phase2/issues/08-sitl-z0-airframe.md) 交来）

**为什么加在票 01**：ticket 08 收口时发现"电机序 `3-2-1-4` / 物理口 ↔ 机体角 / 桨转向"这三件事
**没有任何票认领**。操作者 2026-09-28 裁定：**在当前 tickets 里加一项，且这些数据要读飞控参数得到**（不新开票）。
它们与上面"几何"同属"四个电机到底装在哪、朝哪转"，故并入本节。

**关键**：这三件事**都能从飞控参数导出**（不是猜、不是只有拆机才知道），
但参数说明的是**飞控以为的**接线 —— 与实物是否一致仍需一次物理确认。链条是：

```
物理输出口 k  --PWM_MAIN_FUNCk-->  功能码(101..104 = Motor 1..4)  -->  逻辑电机号 n
              --CA_ROTORn_PX/PY-->  机臂上的位置（机体系 x 前 / y 右）
              --CA_ROTORn_KM 符号--> 桨转向约定（PX4 里 KM 正 = CCW）
```

**用现有参数推出来的表**（第一手读自 `docs/assets/z0.params`；⚠️ 这是**参数推出的结论**，
本票要做的正是"从**飞控**读回来核对 + 实物核对"，不是抄这份文档）：

| 物理口 | `PWM_MAIN_FUNC` | 逻辑电机 | `CA_ROTORn` | 机臂位置（机体系 x 前 / y 右） | KM 符号 → 桨转向 |
|---|---|---|---|---|---|
| MAIN1 | `103` | Motor 3 | `CA_ROTOR2` | 前左（`PX +0.15`, `PY −0.15`） | `−0.05` → **CW** |
| MAIN2 | `102` | Motor 2 | `CA_ROTOR1` | 后左（`PX −0.15`, `PY −0.15`） | `+0.05` → **CCW** |
| MAIN3 | `101` | Motor 1 | `CA_ROTOR0` | 前右（`PX +0.15`, `PY +0.15`） | `+0.05` → **CCW** |
| MAIN4 | `104` | Motor 4 | `CA_ROTOR3` | 后右（`PX −0.15`, `PY +0.15`） | `−0.05` → **CW** |

"物理口 1/2/3/4 对应逻辑电机 3/2/1/4"就是从 `PWM_MAIN_FUNC1..4 = 103/102/101/104` 来的。
对角线同向（前右 & 后左 CCW，前左 & 后右 CW）—— 是标准 quad-X，**看着对，但仍是"参数说的"**。

**三条链各自的第一手依据**（免得后来者以为这是惯例、没人验过）：

- 口→功能：`PWM_MAIN_FUNCk` 的取值就是函数号，`101..104 = Motor 1..4`；
- 功能→逻辑电机：⚠️ **PX4 里 `Motor n` 与 `CA_ROTOR(n−1)` 是硬绑定的，没有重排** ——
  `ActuatorEffectivenessRotors.cpp:52-73` 按 rotor 序号 `i` 读 `CA_ROTORi_*`，`:154-212` 的 `computeEffectivenessMatrix()` 又按同一序号把 rotor `i` 填进效能矩阵第 `i + actuator_start_index` 列（纯多旋翼无伺服前置时 `actuator_start_index = 0`）；
  `ControlAllocator.cpp:658-661` 按 `actuator_idx` 顺序写 `actuator_motors.control[motors_idx]`（无重排）；
  `FunctionMotors.hpp:46` 的 `static_assert` 钉住 `NUM_CONTROLS == MotorMax − Motor1 + 1`、
  `:49` 那条钉住 `ACTUATOR_FUNCTION_MOTOR1 == OutputFunction::Motor1`，
  `:69` 的 `value(func)` 直接取 `control[(int)func − Motor1]` ⟹ **Motor n = `actuator_motors.control[n−1]`**；
- KM 符号：`src/modules/control_allocator/module.yaml:207-220`（v1.14.3）原文
  *"Use a positive value for a rotor with CCW rotation. Use a negative value for a rotor with CW rotation."*

### ★ 2026-10-09：动捕原始 z 法量外参（操作者给定方法）—— **z 分量已定，xy 仍未做**

操作者 2026-10-09 给的方法（原话）：

> 「imu 在飞控上和螺旋桨应该是同一个平面，读取录制的内容里停在地面上的场景，那个场景无人机放在地面，
>   飞控距离地面 20 mm 左右，此时读取到的动捕原始数据 z 应该非 0，这就是动捕里无人机刚体和实物的 z 偏移量」

#### 一手读数（`bag/1_static`，2026-09-29「静止基线」，飞机在地面、全程未解锁）

| 量 | 读数 |
|---|---|
| **`/vrpn/z0/pose` 原始 z（未减任何原点）** | **`+0.10850 m`**（std `0.058 mm`，20346 帧 / 117.3 s） |
| 同场 xy | `-1.28261, -0.13292` —— 非 0 ⟹ 动捕原点在棚里别处（与 [`phase1/04`](../../phase1/issues/04-mocap-relative-pose.md) 的记录同族） |
| 刚体姿态 | 近单位四元数（roll `−0.17°` / pitch `+0.75°` / yaw `+2.23°`）⟹ 飞机是**平的** |
| 飞机状态 | ulog `vehicle_status.arming_state = 1`（全程未解锁）、`z` 波动 ±2 mm ⟹ 确实静置在地面 |

**刚体原点 = 5 颗球的（无权）质心** —— 本场自证：`/vrpn/z0_Marker1..5/pose` 的均值逐轴等于
`/vrpn/z0/pose` 的读数（`x -1.28261 / y -0.13292 / z 0.10850`，小数第 5 位内相同）⟹ 报告的"刚体位置"
就是标记点质心，不是某颗球。⚠️ 顺带记一笔：这 5 颗球只铺开 **114 × 100 × 23 mm**（竖直方向只差 23 mm，
`z ∈ [0.0987, 0.1215]`）—— 是**偏平的一片**，与 [`mocap-setup.md`](../../../docs/reference/mocap-setup.md) §4
写的"金字塔五个顶点"那种高瘦构型**不是一回事**。以后别按金字塔去估高度。

**复现配方**（bag 已入库，脚本没入库 ⟹ 记命令；`/tmp` 开机即清）：
`unzstd bag/1_static/1_static_0.db3.zstd -o /tmp/x.db3` →
`sqlite3` 查 `topics(id,name,type)` 拿 `topic_id` → 从 `messages(topic_id, timestamp, data)` 取 blob →
`rclpy.serialization.deserialize_message(blob, geometry_msgs/msg/PoseStamped)`。

#### 这条读数**推翻了**「刚体原点刻意定义在 IMU 上 ⟹ `0` 正确」那一支

飞机平整地停在地面上、IMU 就在机架平面附近（离地 ~20 mm），而刚体读数在**地面上方 108.5 mm** ——
两个点差一个量级，**不可能是同一点**。⟹ `EKF2_EV_POS_X/Y/Z = 0/0/0` 是「没做」，不是「对」。

#### 但 `EKF2_EV_POS_Z` **不等于**这 108.5 mm —— 两步换算

1. **参考点是 IMU，不是地面、也不是 CG。** 第一手：EKF2 的每一个外部位置源都按
   `pos_offset_body = <源>_pos_body − imu_pos_body` 修正
   （`src/modules/ekf2/EKF/ev_pos_control.cpp:57`，同一条模式还在 `ev_vel_control.cpp:55`、
   `ev_height_control.cpp:51`、`gps_control.cpp:56`、`range_height_control.cpp:61`、`optflow_fusion.cpp:172`），
   而 z0 飞控上 **`EKF2_IMU_POS_X/Y/Z = 0/0/0`**（`docs/assets/z0.params:379-381`）
   ⟹ 该参数的参考点**就是 IMU**（参数说明里的 "relative to vehicle centre of gravity" 在 `IMU_POS = 0` 时同一回事）。
2. **机体系 z 向下为正** —— 参数原文 "Z position of VI sensor focal point in body frame (**down axis**…)"
   （`ekf2_params.c:1080`）。刚体在 IMU **上方** ⟹ 值必须是**负数**。

⟹ **`EKF2_EV_POS_Z = h_IMU − h_刚体 = 0.020 − 0.10850 = −0.0885 m`（≈ `−88.5 mm`）**。
⚠️ **敏感度**：操作者给的 "20 mm 左右" 是**估计**不是卡尺 ⟹ `h_IMU` 每差 5 mm，这个值就差 5 mm。
⚠️ **照抄原始 z（`+0.1085`）会同时错两处**：参考点错（地面 vs IMU）+ 符号反。

#### ⚠️ 承载前提（**还没证**）：动捕的 z=0 平面就是地面

上面把 `0.10850` 当"离地高度"用，前提是动捕标定时 L 型架摆在地面上、z 原点落在地面平面。
**仓库里没有任何一手证据**证明这一点 —— [`mocap-setup.md`](../../../docs/reference/mocap-setup.md) §10「2026-09-21 ticket 12 复测」那张表里的同一句话也只是**默认**了它。
👉 **最省事的验法**：拿一颗反光球**平放在飞机当前位置的地上**，读它的 pose z —— 球心离地 = 球半径（已知），
该读数应当 ≈ 球半径；读到别的值就是原点平面的偏移，直接减掉。**这一步做完，这条外参才有资格写进飞控。**

#### ⚠️ 这是个**每场次**的数，不是常量

同一台机、更早一次（2026-09-21）读到的原始 z 是 **`+0.0883`**、xy 是 `-1.2804, -0.1397`
（[`mocap-setup.md`](../../../docs/reference/mocap-setup.md) §10「2026-09-21 ticket 12 复测」那张表）；本场（2026-09-29）是 `+0.10850`、xy `-1.28261, -0.13292`。
**z 差 20.2 mm，xy 只差 2–7 mm** ⟹ 不是"换了个位置"，而是**标记点/垫高变了**（或那天的读数不是同一装态）。
⟹ 值必须**按当天装态现读现填**；`−0.0885` 只是**本次装态**的值，不许当常量抄。

#### ✂️ xy 这一半，这条路取不到

原始 z 只给**竖直**分量。刚体原点的**水平**位置相对 IMU 在这条读数里**没有参照物**
（原点是 5 颗球的质心，其水平位置由贴球位置决定，与 IMU 无从比较）。
xy 只能靠**尺子**（量 IMU 到质心的水平投影）或**倾斜飞行反解**。

#### ★ 顺带纠正判据的用法（免得白等信号）

纯常值偏移在**静止 / 水平飞行**里**看不见** —— EKF 的原点在初始化/解锁那一瞬定下，参考点与测量点同时平移，
差值被吸收。本场实测：飞机静止在地面时 `/mavros/local_position/pose` 的 z = `−0.00022 m`（std 0.7 mm），
**这与 `EKF2_EV_POS_Z` 填 `0` 还是填 `−0.0885` 无关**。
真正会露头的是**姿态变化时杠杆臂的水平投影**：修正式就是 `pos_offset_earth = R_to_earth · pos_offset_body`
（同一处代码），误差 ≈ `|d| · sin θ`（θ = 相对解锁时刻的倾角）⟹ 用 88.5 mm 估：
**10° 倾角 ≈ 15 mm 水平误差、20° ≈ 30 mm**。
⟹ **别把"地面静止时没看到偏移"当成"`0` 是对的"。**
（另：z0 上 `EKF2_HGT_REF = 3` = **Vision**、`EKF2_EV_CTRL = 11` = HPOS+VPOS+Yaw 都开 ——
`docs/assets/z0.params:349,377` ⟹ 高度参考本身就是这条视觉链，这个 z 偏移是**直接进高度环**的，不是装饰项。）

### 2026-10-09：从已归档 ulog 读悬停段的推力分布（在「按质量均匀处理」前提下）

**为什么记这一笔**：几何那一节的判据只写了 `PX == PY`，**盖不住「推力质心平移」这一类**。
操作者 2026-10-09 给定前提：**质量分布差别不大 ⟹ 按质量均匀处理**，并要这一前提下的结果。
⚠️ 本节是**读数 + 方法 + 不能归因的部分**，**不是**几何那一节的定案。

**方法与第一手依据**

- 读 `actuator_motors.control[0..3]`；`control[i]` = Motor (i+1) = `CA_ROTOR{i}`（链条见本票上文）。
- ⚠️ **`control[]` 是 `rel_thrust`，不是电机信号** —— 第一手：`mixer_module/functions/FunctionMotors.hpp:78-99`
  把 `THR_MDL_FAC` 的二次式**反解**掉了（`x = −tmp1 + √(tmp2 + control/a)`）⟹ `control` 与推力**线性**，
  **不需要**再按 `THR_MDL_FAC = 0.45` 做二次修正。
- 自证：`mean(control[0..3]) ≡ |vehicle_thrust_setpoint.xyz[2]|`，四份日志 max|Δ| = 8.6e-6 … 2.4e-3，corr ≥ 0.99996；
  `control[4..11]` 全 NaN（本机 4 电机）。
- 稳态悬停窗判据与 [`tools/hover-thrust/`](../../../tools/hover-thrust/) 同：
  `flag_armed ∧ ¬landed`、`|v| ≤ 0.30 m/s`、倾角 ≤ 10°、`|thrust_z| ∈ [0.15, 0.98]`、离地 > 0.15 m。
- 位置用**实际几何** `a = 152 mm / 2 / √2 = 0.0537401 m`；换成参数现值 `0.15` 只是把质心读数**等比放大 2.79×**，
  **不改变任何结论**（这正是「均匀缩放会被归一化约掉」的同一个道理）。

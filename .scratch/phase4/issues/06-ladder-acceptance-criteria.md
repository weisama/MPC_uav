# 06: 起飞前写定四级阶梯的量化判据

Status: ready-for-human
Type: task

**What to build:** 一张**在任何一次转桨之前**定稿的判据表：每一级的过线阈值是多少、过不了归因到哪一环。

**为什么必须先写定**：「这级算不算过」不能事后看感觉定 —— 一台刚飞完的机器 + 一个想继续往下走的我，是最不适合做这个判断的组合。

**Blocked by:** [05](05-first-flight-config-freeze.md)（阈值要用冻结后的实测参数算，例如频率与 τ），以及跨 feature 的 [`phase2/issues/11-sitl-tier-b-seam3.md`](../../phase2/issues/11-sitl-tier-b-seam3.md)（SITL 达标 —— 阶梯是它之后的关卡，没有它的量化结论就没有可对照的基线）。

- [ ] 四级各自的**过线阈值**写定，且**每一级都是量化值** —— 不用"稳定"、"正常"、"看着还行"这类词
- [ ] 四级各自的**过不了怎么办**写定：归因到哪一环（符号映射 / 推力标定 / 角速率增益 / 延迟 / 求解退化），而不是笼统的"再调调参数"
- [ ] **与 Phase 1 同口径**的对比量写定 —— 阶梯 4 的三条轨迹要与 (A) 级的同一套判据**可比**，否则"MPC 比 PID 如何"这个问题没有答案
- [ ] 阶梯 4 的判据与 Phase 2 的 SITL 判据（稳态误差 / 三条轨迹 / 注入延迟 / 注入失败）**逐条对应**，使「仿真能飞」与「真机能飞」的差是**可量化的差**而不是印象
- [ ] **何时停飞**写定：哪一级不过就不进下一级；什么情况下**直接回退 (A) 级**而不是再试一次
- [ ] 判据表定稿后**不再事后修改**；若必须改，改动本身留痕并说明是**哪一级的哪个数据**促成的

---

**为什么是 `ready-for-human`**：阈值是操作者的取舍（多保守算够保守），必须与飞手的风险承受度一致，不是给定条件下的推导。

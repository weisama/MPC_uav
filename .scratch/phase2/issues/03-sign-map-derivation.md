# 03: 符号映射表 —— 独立推导并落成唯一权威

Status: done
Type: research

**What to build:** 一张**推导出来（不是抄出来）**的符号映射表，且它是全项目唯一的权威来源。

★ 这是 Phase 2 **最容易摔机的一步**，而它的结论是 [04](04-offline-ocp.md) / [05](05-sitl-offboard-smoke.md) / [06](06-mpc-node-fake-px4-fixture.md) 三张的**共用前置**。它错了，三张会**一起错并且互相印证** —— 这正是它值得单独成张的理由。

**Blocked by:** 无（可立即开工）

**要推的两件事**（不许靠记忆、不许拿"参考实现是这么写的"当推导）：

1. 世界系 **ENU**、机体系 **FLU** 下，**要往 +x（东）飞，机体需要绕哪个轴、朝哪个方向倾斜**。
2. MPC（模型预测控制）内部 FLU 的 `[ω_x, ω_y, ω_z]` 与推力 `F`，映射到 PX4 `VehicleRatesSetpoint` 的 `roll` / `pitch` / `yaw` / `thrust_body[2]`（FRD）时，**各项是否变号**。

**方法**：从 FRD 与 FLU 的定义直接推（两者关系是"x 不变、y 与 z 取反"），或用已知正确的仿真器交叉验证。**推导过程要能读**，不是只贴一个结论。

**★ 交叉核对（承重的一步）**：推完之后，与 [`phase2-implementation.md`](../../../docs/control/phase2-implementation.md) §2.3c 的现表**逐条对照**。

- **一致** → 结论成立，把这组数落成权威。
- **不一致** → ★ **立即停下，交人裁决**，不要自行选一个继续。这是本张**唯一的失败模式**，且它恰是"静默错"的类型 —— 两个来源都自称对，代码不会报错。

- [x] 两件事都给出**推导过程**（不是结论），过程可被第三方逐行复核 → [`sign-map.md`](../../../docs/control/sign-map.md) §3 / §5
- [x] 与 §2.3c 逐条对照的结论留档：一致 / 不一致 + 分歧点具体在哪一项 → 同上 §4，**一致，无分歧点**（另见本文件 `## Comments`）
- [x] 权威位置落在文档里**唯一一处**；代码注释**回链它，不复写数值**（避免代码与文档各自漂移）→ 同上 §2（唯一权威）/ §8（代码侧契约）；原有副本已全部改成回链
- [x] 推力那一项显式包含**量纲**：`−F / T_max`，且注明 `T_max` **按电池取值而非按电机**（其数值由 [10](10-param-measure-backfill.md) 定稿）→ 同上 §2 + §6
- [x] 选 ENU/FLU 而非 NED/FRD 的**理由**（两种方案转换总数相同，但把误差风险放在"纯符号翻转"那一侧而不是"四元数变换"那一侧）与结论记录在同一处 —— 这样这个决定不会被后人无意间推翻 → 同上 §7（就在权威表同一份文件里）
- [x] ⚠️ 若与 §2.3c 不一致：本张**不进入 04 / 05 / 06**，并在本文件下追加 `## Comments` 记录分歧，等裁决 → **不适用：一致**，故 04 / 05 / 06 可开工

---

**本张不是"确认参考实现没错"** —— 参考实现是别人为 x500 写的，它的符号自洽**不等于**与真 PX4 一致。这个区别是 [11](11-sitl-tier-b-seam3.md) 存在的理由：本张只能给出"我们认为对"的约定，**只有闭环能验证它与真实飞控一致**。

## Comments

### 2026-09-28 收口 —— 推导完成，与 §2.3c **逐条一致，无分歧点**

**两件事的结论**（推导过程在权威文件 §3 / §5，此处只放结论）：

1. **要往 +x（东）飞**：绕机体 **+y 轴**（FLU 下指向**左**）**正向**倾斜 → 机头下俯 → `ω_y > 0`。
   与航向无关的一般形式：`ω = κ·(ẑ × d̂)`，`d̂` 是期望加速度方向在机体系里的单位矢量。
2. **FLU → FRD**：`roll` **不变号**、`pitch` **取反**、`yaw` **取反**、`thrust_body[2] = −F / T_max`。
   （FLU↔FRD 是"x 同向、y 与 z 取反"，`det = +1`，即**绕机体系 x 轴转 180° 的真旋转，不是镜像** ——
   所以角速度按普通矢量变换，**不引入伪矢量的额外符号**。这一步单独写在 §5.1，别被"取反"两个字带偏。）

**★ 与 §2.3c 的对照结论：一致，无分歧点**（六项逐条表见权威文件 §4）。
六项里五项完全相同；第 6 项是**补白**——§2.3c 本来没写"绕哪个轴"，
`phase2-implementation.md` §4 的 S3 表里还留着一个"绕 −y 还是 +y"的待定项，现在有了答案（绕 **+y**），
**与原表不冲突**。⟹ **本张唯一的失败模式未触发，[04](04-offline-ocp.md) / [05](05-sitl-offboard-smoke.md) / [06](06-mpc-node-fake-px4-fixture.md) 可以开工。**

**过程中的两条自我更正**（都是自检抓出来的，不是事后补记）：

- 「往 +y（北）侧飞要 `ω_x > 0`」—— **写反了**。`R_x(θ)·e_z = (0, −sinθ, cosθ)`，θ>0 把推力拽向 **−y**，
  即往北飞要**左滚**（`ω_x < 0`）。已改成一般规则 `ω = κ·(ẑ × d̂)` 并钉成用例
  （`test_general_rule_omega_is_z_cross_d`），免得只记住一个轴的特例。
- 权威块最初写成 `thrust_body_2 = -F / T_max`（省略了系数），对账脚本解析不出来 —— 改成 `-1 * F / T_max`，
  四行**同形**，机器可解析。这是"口号式一致"和"被机器盯着的一致"的差别。

# 03: 符号映射表 —— 独立推导并落成唯一权威

Status: ready-for-agent
Type: research

**What to build:** 一张**推导出来（不是抄出来）**的符号映射表，且它是全项目唯一的权威来源。

★ 这是 Phase 2 **最容易摔机的一步**，而它的结论是 [04](04-offline-ocp.md) / [05](05-sitl-offboard-smoke.md) / [06](06-mpc-node-fake-px4-fixture.md) 三张的**共用前置**。它错了，三张会**一起错并且互相印证** —— 这正是它值得单独成张的理由。

**Blocked by:** 无（可立即开工）

**要推的两件事**（不许靠记忆、不许拿"参考实现是这么写的"当推导）：

1. 世界系 **ENU**、机体系 **FLU** 下，**要往 +x（东）飞，机体需要绕哪个轴、朝哪个方向倾斜**。
2. MPC（模型预测控制）内部 FLU 的 `[ω_x, ω_y, ω_z]` 与推力 `F`，映射到 PX4 `VehicleRatesSetpoint` 的 `roll` / `pitch` / `yaw` / `thrust_body[2]`（FRD）时，**各项是否变号**。

**方法**：从 FRD 与 FLU 的定义直接推（两者关系是"x 不变、y 与 z 取反"），或用已知正确的仿真器交叉验证。**推导过程要能读**，不是只贴一个结论。

**★ 交叉核对（承重的一步）**：推完之后，与 [`phase2-implementation.md`](../../../docs/control/phase2-implementation.md) §2.3c 的现表**逐条对照**。

- **一致** → 结论成立，把这组数落成权威。
- **不一致** → ★ **立即停下，交人裁决**，不要自行选一个继续。这是本张**唯一的失败模式**，且它恰是"静默错"的类型 —— 两个来源都自称对，代码不会报错。

- [ ] 两件事都给出**推导过程**（不是结论），过程可被第三方逐行复核
- [ ] 与 §2.3c 逐条对照的结论留档：一致 / 不一致 + 分歧点具体在哪一项
- [ ] 权威位置落在文档里**唯一一处**；代码注释**回链它，不复写数值**（避免代码与文档各自漂移）
- [ ] 推力那一项显式包含**量纲**：`−F / T_max`，且注明 `T_max` **按电池取值而非按电机**（其数值由 [10](10-param-measure-backfill.md) 定稿）
- [ ] 选 ENU/FLU 而非 NED/FRD 的**理由**（两种方案转换总数相同，但把误差风险放在"纯符号翻转"那一侧而不是"四元数变换"那一侧）与结论记录在同一处 —— 这样这个决定不会被后人无意间推翻
- [ ] ⚠️ 若与 §2.3c 不一致：本张**不进入 04 / 05 / 06**，并在本文件下追加 `## Comments` 记录分歧，等裁决

---

**本张不是"确认参考实现没错"** —— 参考实现是别人为 x500 写的，它的符号自洽**不等于**与真 PX4 一致。这个区别是 [11](11-sitl-tier-b-seam3.md) 存在的理由：本张只能给出"我们认为对"的约定，**只有闭环能验证它与真实飞控一致**。

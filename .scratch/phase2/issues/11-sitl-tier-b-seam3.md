# 11: SITL B 档闭环 + seam 3 量化验收 ★

Status: ready-for-agent
Type: task

**What to build:** 状态源换成 `/mocap/pose_enu`（输入为 **Phase 1 实飞录下的真实动捕 rosbag 回放**），并**跑满** seam 3 的全部量化判据。

**Blocked by:** [09](09-sitl-tier-a-closed-loop.md), [10](10-param-measure-backfill.md)，以及 Phase 1 实飞录下的动捕 rosbag 与 [`/mocap/pose_enu`](../../phase1/issues/04-mocap-relative-pose.md) 这条话题（跨 feature）

**为什么 B 档的输入必须是真实 rosbag**：理想轨迹是一个"我已替它美化过的世界"。用真 rosbag 才让 MPC（模型预测控制）面对**真实噪声与真实延迟**，也才让"注入延迟后仍稳定"这一条有意义。

**要建的夹具**：把真实 rosbag 变成 `/mocap/pose_enu` 的脚本化回放源（[06](06-mpc-node-fake-px4-fixture.md) 的脚本化输入在这里换成真实数据），并能**在回放流上叠加人为延迟**。

⚠️ **本张是 Phase 2 的最高关卡，没有上一层兜底** —— 过了这里就直接交 Phase 3 上机。所以判据**必须真的跑满**，不能"看着还行"就过。

- [ ] 状态源切到 `/mocap/pose_enu`，输入为 Phase 1 实飞的动捕 rosbag 回放
- [ ] **判据 1**：起飞到 1 m 悬停，**稳态位置误差 < 0.15 m**，无持续振荡
- [ ] **判据 2**：走完 Phase 1 的三条轨迹（悬停 / 1 m 正方形 / r = 0.5 m 八字），**不撞地、不失控**
- [ ] **判据 3**：人为注入 **50 ms** 动捕延迟后**仍稳定**（可以变差，但不能发散）
- [ ] **判据 4**：主动让求解失败，飞机保持**安全悬停**而不是崩（验证 M5 兜底在真闭环里成立）
- [ ] 被控对象是 [08](08-sitl-z0-airframe.md) 那版**参数刻意与 z0 不匹配 ±30%** 的 —— ★ **"错参数也能飞稳"本身是判据的一部分**
- [ ] 量化的稳态误差上限、三条轨迹、注入延迟、注入失败**逐条留档**（数值 + 条件），不依赖记忆
- [ ] 每条判据若未达线：记录"**未达标 + 实际数值**"，**不写"基本通过"**
- [ ] 为 Phase 3 交接两样副产品：① fork 的完整构建环境 ② **实测最坏求解耗时**（Phase 3 没有这个数字就定不了实机频率）

---

**一个被考虑并否决的方案**（记在这里以免后人重新发明）：在 Python 里写一个与控制器同构的轻量被控模型来自动化闭环符号验证。**否决理由**：它与控制器**共享同一套约定** —— 如果整条约定都错了，这个测试会**一起错并且通过**。它只能抓"控制器与模型不一致"，抓不到"模型与 PX4 不一致"。换来的自动化覆盖**不值得**一个会给出虚假安全感的测试。

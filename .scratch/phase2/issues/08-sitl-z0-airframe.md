# 08: z0 同构 SITL 被控对象（含参数失配开关）

Status: done
Type: task

**What to build:** 一个**动力学与 z0 同构**的 SITL 被控对象。

`gz_x500` 的动力学与 z0 差得远，**"在 x500 上能飞"证明不了"在 z0 上能飞"**。所以 SITL 要重新生成一份符合 z0 的模型，而不是拿现成机型凑。

**Blocked by:** [01](01-sitl-px4-msgs-baseline.md)

- [x] 在**上游 v1.14.3（tag `1dacb4c`）**构建出的 SITL 上新增一份 z0 同构机型（构型、推力方向、机体几何按 z0）—— ☠️ 原写"在 fork `5ba2e91f` 构建出的 SITL 上"，**该 fork 与 z0 无关**
- [x] 质量 / 推力系数 / 转动惯量 / 内环时间常数等参数按 z0 取值，且**单参数 ±30% 失配可切换**（供 [12](12-mismatch-sweep.md) 用 —— 开关是刻意留的，不是顺手加的）
      ★ 实际交付的是**五个**旋钮：质量 / 推力系数 / 转动惯量 / **作动器滞后 `tau`** / **内环闭环带宽 `rate`**。
      原写"内环时间常数"指代不明 —— 它在本仓库里被用来指过两个量（`SIH_T_TAU` 是**被控对象**的电机滞后，
      `phase2-implementation.md` §5 的 P4 `k_ω` 才是**闭环**的），2026-09-28 操作者裁定"两者都做"，故 `tau` 只作动被控对象、
      `rate`（`MC_*RATE_P` ±30 %）动控制器。见文档 §5.4
- [x] 另留**一套参数一致的对照组变体**
- [x] SITL 侧的 PX4 参数与 z0 一致，含倾角（`MPC_TILTMAX_AIR = 45`，**两侧同值**）
      ⚠️ 注意这是 **PX4 的位置控制器参数**（Multicopter Position Controller），与模型预测控制**毫无关系**
      —— ☠️ 本行原写"含 `MPC_TILTMAX_AIR` 收到 **30°**"，与前半句"与 z0 一致"**自相矛盾**（z0 现值就是 45）：
      那个 30° 是当时想靠收小倾角给被控对象留推力裕度（30° 需 8.5 N = 电池可用推力的 72 %，45° 需 10.4 N = 88 %）。
      **2026-09-28 操作者裁定「两边都回 45」**，故按实际交付改正（细节见下方 Comments 与文档 §5.3）
- [x] 参数变更记入 [`params-changes.md`](../../../docs/reference/params-changes.md)
- [x] 机型与参数写入文档，使 12 的扫描**可复现**（参数值、切换方式、如何复原）
- [x] `gz_x500` 在文档里被明确标注为**仅最早期冒烟目标**，**不得用于 SITL 验收**

---

**为什么失配是交付物而不是副作用**：若这个 MPC（模型预测控制）只在参数精确匹配时不发散，那它在 z0 上就**没有裕度**。**"错参数也能飞稳"本身是 [11](11-sitl-tier-b-seam3.md) 判据的一部分** —— 所以失配开关必须在本张就建好，不能等到 12 才现搭。

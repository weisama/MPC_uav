# 08: z0 同构 SITL 被控对象（含参数失配开关）

Status: done
Type: task

**What to build:** 一个**动力学与 z0 同构**的 SITL 被控对象。

`gz_x500` 的动力学与 z0 差得远，**"在 x500 上能飞"证明不了"在 z0 上能飞"**。所以 SITL 要重新生成一份符合 z0 的模型，而不是拿现成机型凑。

**Blocked by:** [01](01-sitl-px4-msgs-baseline.md)

- [x] 在**上游 v1.14.3（tag `1dacb4c`）**构建出的 SITL 上新增一份 z0 同构机型（构型、推力方向、机体几何按 z0）—— ☠️ 原写"在 fork `5ba2e91f` 构建出的 SITL 上"，**该 fork 与 z0 无关**
- [x] 质量 / 推力系数 / 转动惯量 / 内环时间常数等参数按 z0 取值，且**单参数 ±30% 失配可切换**（供 [12](12-mismatch-sweep.md) 用 —— 开关是刻意留的，不是顺手加的）
- [x] 另留**一套参数一致的对照组变体**
- [x] SITL 侧的 PX4 参数与 z0 一致，含 `MPC_TILTMAX_AIR` 收到 **30°**
      ⚠️ 注意这是 **PX4 的位置控制器参数**（Multicopter Position Controller），与模型预测控制**毫无关系** —— 收它的理由是电池限制下的推力裕度，不是 MPC（模型预测控制）的需要
- [x] 参数变更记入 [`params-changes.md`](../../../docs/reference/params-changes.md)
- [x] 机型与参数写入文档，使 12 的扫描**可复现**（参数值、切换方式、如何复原）
- [x] `gz_x500` 在文档里被明确标注为**仅最早期冒烟目标**，**不得用于 SITL 验收**

---

**为什么失配是交付物而不是副作用**：若这个 MPC（模型预测控制）只在参数精确匹配时不发散，那它在 z0 上就**没有裕度**。**"错参数也能飞稳"本身是 [11](11-sitl-tier-b-seam3.md) 判据的一部分** —— 所以失配开关必须在本张就建好，不能等到 12 才现搭。

**交付物**（单一真源 `tools/px4-sitl/z0-plant/plant_spec.py`，机型与 10 份覆盖层全由它生成）：

**验收证据**（2026-09-28，`verify_z0_plant.py --variants-all`，**退出码 0**）：
**10 个变体 × 50 项检查 = 500 项全过**（每变体 45 项静态参数比对 + 5 项动态测量）。

动态那 5 项是**真机式**地给电机下指令再量推力（读 SIH 无噪真值话题
`vehicle_local_position_groundtruth` / `vehicle_attitude_groundtruth`，
不用被加了高斯噪声的 `sensor_accel`）。10 个变体逐条实测量见交付文档 §6.2；
基准 `z0`：读回电机信号 `[0.722, 0.722, 0.722, 0.722]`（期望 0.7227）、
离地 0.860 m、倾斜 3.2°、**推力实测 8.521 N vs 期望 8.528 N（−0.08 %）**；
失配变体同样贴合（最大偏差 0.16 %），⟹ **"参数改了 → 被控对象真的按新参数出力"这条链逐变体是通的**，
不只是"参数文件写进去了"。

**三个当场踩出来的坑（都写进文档 §7 与脚本 docstring 了）**：
① `param show SIH_` 什么都返回不了（过滤串必须带尾部 `*`，且输出有**两列**状态）；
② 四条 `actuator_test` 连发会丢前面的 —— 最终那次 10 个变体**首读 10/10 都没到位**，
所以"逐条读回确认 + 补发"是**主路径**不是保险；
③ **★ 推力曲线的方向是反的**：`FunctionMotors::updateValues` 收的是**推力**、
吐的是**反解出的电机信号**（`FunctionMotors.hpp` 的注释看着像反过来）。
`THR_MDL_FAC = 0` 时曲线是恒等映射、**方向搞反也看不出来**，所以只有 `z0-thrcurve`
能暴露它 —— 本张第一版脚本正是这么中招的（读回 0.852 而非 0.7227）。
那次的"错"反倒独立证明了 SIH 对电机信号严格线性（`4×2.95×0.852 = 10.054 N` vs 实测 10.056 N）。

**★ 三处我取了默认、但**没有用户单独表态**的决定**（都可在几分钟内改）：
1. **`THR_MDL_FAC` 取 `0`，而 z0 固件是 `0.45`**。取 0 的理由是 SIH 被控对象对电机信号线性、
   曲线会夹进一段**不在 12 的四个旋钮里**的非线性；代价是**偏离 z0 固件配置**。
   想要"以 z0 固件为准"：改 `plant_spec.ROWS` 里那条再 `--emit`。
   两种口径都留了变体（`z0-thrcurve` 只动这一条），12 可以并排比。
2. **转动惯量 / `SIH_T_TAU` 是占位值**（点质量上界 `m·l²` = 0.002166、`IZZ = 2·IXX`、
   τ = SIH 默认 0.05）—— **不是辨识值**。⚠️ 这直接影响 12 的 `tau` 旋钮：
   它扫的是"相对 0.05 的 ±30 %"。真值待 ticket 10。
3. **`MPC_TILTMAX_AIR = 30` 收在 SITL 侧，飞机侧仍是 45**（§E3/E4 未动）。
   理由（电池推力裕度）出自 phase2-implementation §3.3，但"收到 30"本身是**项目决定**。

**另外两处诚实交代**（不靠"跑通了"掩盖，明细见文档 §8）：
- **偏航力矩比没有动态量过**。`SIH_Q_MAX = KM × SIH_T_MAX` 只是让被控对象的偏航/推力比
  与分配器以为的 `CA_ROTOR_KM` **代数一致**；验收量的是**推力通道**。要量偏航得构造纯偏航不平衡
  （`u0=u1`、`u2=u3`），本张没做。
- **PX4 侧只镜像了文档 §2 表里那几条**（`MC_*RATE_MAX` / `MPC_TILTMAX_AIR` / `MC_BAT_SCALE_EN` /
  `MC_AIRMODE` / 检查位），滤波器、EKF、`MPC_*` 位置环增益等**全是 SITL 默认值**，
  没有逐条对齐 z0 的 915 条 —— `plant_spec.ROWS` 就是"镜像了哪些"的完整清单。

**与本张清单的两处差异**（都已在文档里写明）：
- 清单写"另留**一套参数一致的对照组变体**" ⟹ 交付形态是**变体 `z0` 本身**（覆盖层全量 `param set`），
  而不是另装一份机型 —— 因为机型一分为二会让"对照组"与"被控对象"漂移。**若坚持要独立机型，说一声。**
- 清单只点名"单参数 ±30 %"，实际另加了 `z0-thrcurve`（非扫描项），用来量化推力曲线失配；
  它不属 12 的四个旋钮。

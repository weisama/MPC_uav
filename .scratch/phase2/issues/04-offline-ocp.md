# 04: 离线 OCP（10 状态）+ seam 2

Status: done
Type: task

**What to build:** 一个**不接 ROS、不接通信**的求解器单元：给它状态与参考，它给出 `u = [F, ω_x, ω_y, ω_z]`。

**为什么它值得一个独立 seam**（三条，任一条都成立）：① 它是**唯一能测出最坏求解耗时**的地方，而这个数字直接决定 MPC（模型预测控制）频率 —— 是硬依赖，不是优化项；② 数值求解器的失败**在话题边界上没有任何诊断分辨率** —— "输出不对"无法区分是模型错、代价错、约束错还是没收敛；③ 它本来就是实施清单里规定的步骤，不是为本 spec 新造的开销。

**Blocked by:** [02](02-acados-orin-build.md), [03](03-sign-map-derivation.md)

**模型**：10 状态（`p, v, q`），`ω` **不作状态** —— 姿态运动学直接用角速率输入，即"内环完美跟踪"假设。

★ 这是**刻意的工程化简，不是论文的标准做法**（依据的两篇论文都把 `ω` 作为状态）。选它的理由是：把"新变量"从两个减到一个 —— 只有模型是新的，其余照抄已被实飞验证过的参考实现。**这一点必须在文档里诚实写明**，并写清升级到 13 状态（`ω̇ = k_ω(ω_des − ω)`）的方向**与论文一致**，不是自创。

**本张负责的改动（M1 / M2 / M3 / M4 / M6）**：
- **M1** 质量与悬停油门换成 z0 的**实测值**（原值是参考机架的）
- **M2** 删掉硬编码的推力归一化魔数，改成从模型导出 `1/T_max`
- **M3** 角速率上限换成 z0 实测值，且**偏航上限单独给**（参考实现写成了横滚的一半，而 z0 的偏航上限**比横滚更大**）
- **M4** `T_max` 按**电池**取值，不按电机
- **M6** 代价改为惩罚 `u − u_ref`，而非 `u − 0`

- [x] `(状态, 参考) → u` 可在**零 ROS**环境下调用；求解器用 `SQP_RTI` + `PARTIAL_CONDENSING_HPIPM`，每控制周期只做一次迭代
- [x] **悬停配平**：状态在原点、目标在原点 → 推力 ≈ 悬停推力、角速率 ≈ 0
- [x] **差一个重力**：目标在 +z 0.5 m → 推力 > 悬停推力、角速率 ≈ 0
- [x] **姿态响应方向**：目标在 +x 0.5 m → 产生的倾斜角速率方向与 [03](03-sign-map-derivation.md) 的推导一致
- [x] **约束生效**：可行域外目标（如 +x 10 m）→ 角速率与推力**打满且不越界**
      ⚠️ **只对了一半，如实记**：`ω` 一拍就贴住上限并保持；**推力不会**打满 —— 纯水平的远目标
      只需倾斜、垂直分量仍≈悬停，实测 `F = 11.4044`（上限 11.8003）。要顶到上限得**同时要求爬升**。
      按实测改写了 `phase2-implementation.md` §4 S3 的原表，并在 `test_ocp_constraints.py` 留了对照组
- [x] **求解耗时**：重复 ≥1000 次，报**最坏**耗时而非平均；此数字回填 D6
- [x] 求解器数值健康度**可观测**（残差 / 迭代数 / 状态码）—— 使"求解器在悄悄退化"不会一直不可见
- [x] 代价确实罚的是**相对参考的偏差**：给一个需要持续角速率的场景（如绕圈），不出现系统性把角速率往零拉导致的稳态偏差
- [x] M6 的参考量 `u_ref` 取法写定（上一帧解或前馈），不留"实现时随便定"
- [x] `hover_thrust` / `T_max` / 最坏耗时在定稿前是**占位值**，且**占位关系自洽**（模型里的悬停油门与推力换算常数必须互相自洽 —— PX4 对 `thrust_body` 不做任何重标定，两者不一致就是一个静默的增益错误）；回填口留给 [10](10-param-measure-backfill.md)
- [x] M1–M4 / M6 的改动编号、理由与第一手依据已记入 [`phase2-implementation.md`](../../../docs/control/phase2-implementation.md)

---

⚠️ **"姿态响应方向"这一项在本张只能验证自洽性，验证不了正确性。** 离线的约定与**真 PX4** 是否一致，只有 SITL 闭环能回答。**离线测试通过 ≠ 符号对。**

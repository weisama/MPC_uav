## 这次改了什么

### ① 重录这条路（现场主诉的正面修法）

- 已入账的 `bag/<场景>/` **一个字节都不碰**（不删、不挪、不覆盖）—— 这条纪律没松；
- 目录已被占时**先诊断再问一句**：`metadata.yaml` 在 ⟹ "已入账的包"，不在 ⟹ "上次没收干净的"，
  两种都在屏幕上说清；
- 答 **y** ⟹ 录进 **`bag/<场景>__<UTC 时间戳>/`**（`unique_dir`；同一秒再来一次就 `-2`/`-3`）；
  答 **n**（空回车也是 n、非交互 EOF 也是 n）⟹ 老行为，这一趟不起录、返回码 1；
- **日志名跟着包目录名走**（`bag/<包目录名>.log`，原先是写死的 `<slug>.log`）——
  否则第二次起录会把第一份的日志盖掉，而那正是排障时要看的东西。
  连带 `adopt_state` 找日志也改成按**包目录名**找。

## Comments

**2026-10-08 · 顺带发现一个"静默假绿"（**本票没修**，与本次改动无关，先记下来）**

本机 `pytest 6.2.5`：**只要把 `test_z0_check_live.py` 与别的用例文件写进同一条命令**，
其余那些用例**一条都不收集**，而退出码是 0、屏幕上是 `collected 0 items / 1 skipped`
—— 一条 `rec.py` 的用例都没跑，看起来却像"通过"。

- 触发条件就是那一句 `pytest.importorskip("rclpy"/"bench")`（**模块级**，环境没 source 时会抛
  `Skipped`）；**与命令行里文件先后顺序无关**。
- 已在本仓库之外的最小复现里确认（一个 `importorskip` 的假模块 + 一个普通模块，两个文件，
  `collected 0 items / 1 skipped`）⟹ **不是本次改出来的**，是这条 pytest 版本的老毛病。
- 现状下**按文件跑**是安全的（`run/README.md` 记的就是这个跑法）。⚠️ 谁要是写个
  "一次跑完 `run/tests/`" 的脚本，会得到一份**全绿但没有跑过**的报告。

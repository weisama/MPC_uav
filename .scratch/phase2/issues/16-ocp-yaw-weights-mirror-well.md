# 16: OCP 代价里的偏航权重（`qw = 0` 的镜像井）—— 待裁定

Status: ready-for-human
Type: task

**议题**：`ocp.py` 的 `q_diag` 姿态四元数段是**照抄参考实现**的 `(0.0, 0.1, 0.1, 0.1)`，那个
**`qw = 0`** 使代价**分不出**参考机头 `ψ` 与它的镜像 `2π − ψ`（两者只差 `w = 2cos(ψ/2)`，
而 `w` 不被罚）。后果实测是：**偏航通道在参考附近是一条死通道**。

**谁提出**：ticket 09（A 档 SITL 闭环，2026-09-28）。**为什么本票没改**：`q_diag` / `r_diag`
是 **ticket 04 的交付物**，`offline-ocp.md` §2 明说"本票没有改它（不在 M1–M9 里）"，
按项目规矩改别的票的约定要先问操作者。

**第一手读数**（全部可复算）：

- 代价对两个朝向**都不区分**：参考朝向与镜像朝向的代价**都恰好 = `0.000000`**
  （`test_ocp_cost_ref.py::test_the_cost_cannot_tell_the_reference_heading_from_its_mirror`，
  该测试同时守住前提 `q_diag[6:10] == (0.0, 0.1, 0.1, 0.1)`）。
- **收敛解下偏航是死的**：0.40 rad（23°）的机头误差只换来 `−1.9e-5 rad/s`，0.15 rad 只有
  `−7e-6 rad/s` ⟹ 按这个速度要 **20000 s** 才转回来。
- **单次 RTI 迭代**（在线口径）另有一点**依赖热启动**的倾斜→偏航泄漏：roll 0.08 rad ⟹
  `−0.018378 rad/s`（收敛后是 0）。**这正是 ticket 09 那场自转 runaway 的原料**：
  棘轮（`u_ref = 上一帧解`，已在 ticket 09 修掉）把它放大成 `u[3] → +4.696 rad/s`。

**候选修法与实测**（离线闭环，从 +0.4 rad 机头误差起步跑 12 s；表在
[`tier-a-sitl-hover.md`](../../../docs/control/tier-a-sitl-hover.md) §4.4）：

| 组 | 权重改动 | 镜像代价 | 末段误差 | 倾斜泄漏 `ω_z` |
|---|---|---|---|---|
| **A（现状）** | `qw=0, qatt=0.1, R_yaw=500` | `0.00000` | `+0.3548` | `+0.00211` |
| B | `qw=0.1` | **9.53** | `+0.2699` | `+0.00163` |
| C | `qatt=2.0` | `0.00000` | `−0.2028`（过冲） | `−0.00113` |
| D | `qatt=2.0, R_yaw=50` | `0.00000` | `+0.0152` | `+0.00019` |
| E | `qw=0.1, qatt=2.0, R_yaw=50` | **9.53** | `−0.0064` | `+0.00005` |

读法：**只有 `qw` 那一项能消掉镜像井**（9.53 vs 0.00000）；只有 E 既收敛（−0.0064）又把泄漏
压了 40 倍。

**要裁定的事**：维持 **A**（现状，接受"机头被扰动之后回不来"），还是上 **E**？
⚠️ 两条都**不只是调参**：`qw` 一改，"朝向"进代价的方式就变了，M6 的持续角速率用例
（`offline-ocp.md` §3.3）、`test_ocp_cost_ref.py` 与 `test_ocp_trim.py` 的期望值都要跟着重算。

**验收（若上 E）**：

# 05: SITL 最小 offboard 冒烟 —— 在真 PX4 上一次验六件事

Status: ready-for-agent
Type: task

**What to build:** PX4 在 SITL 里**第一次真的照着我们发的指令动起来**。

用一个**不含任何 MPC（模型预测控制）数学**的最小节点，刻意把"中间件"与"模型/控制律"隔开。本张要排除的是四个**静默失败** —— 它们全都不报错、不崩溃，只表现为"没反应"，或更糟：飞机朝错的方向加速。

**Blocked by:** [01](01-sitl-px4-msgs-baseline.md), [03](03-sign-map-derivation.md)

**验哪六件事**（全部在**真 PX4** 上，不是假件）：

1. `px4_msgs` 与固件**真的对得上** —— 判据不是"话题在"，而是"**PX4 真的照做**"
2. **QoS 双向可通**（订阅 `fmu/out/*` 必须显式声明 `BEST_EFFORT`，否则话题列出来了但**一个回调都不进**）
3. 时间戳用**微秒**
4. offboard 心跳频率远高于最低要求（≥2 Hz，实做 50 Hz）
5. `thrust_body[2]` 的**符号与归一化** —— 只给悬停推力时飞机**不掉高**
6. 手写的小角速率步进的**倾斜方向**与 [03](03-sign-map-derivation.md) 的推导一致

- [ ] 最小节点把 PX4 拉进 offboard（在此之前 setpoint 已以 ≥2 Hz 持续发布 **≥1 s**）
- [ ] **只给悬停推力** → 飞机在 SITL 里**维持高度**（不掉高、不缓升）—— 这一条同时验了**符号**与**归一化常数**两件事
- [ ] **给 ±ω 步进** → 机体倾斜 / 偏航方向与 03 一致
- [ ] **断流实验**：杀掉节点 → PX4 在 `COM_OF_LOSS_T` 之后**自行退出 offboard**（证明心跳是唯一的维持机制）
- [ ] 四个静默失败每一项都有**独立的一次观测**（不是"跑起来没报错"就算过）
- [ ] 本张的指令是**参数化的 stub**，不引入任何模型 / 代价 / 约束代码
- [ ] stub 与后续节点**共用同一份符号映射实现**（03 权威位置的代码侧），不是两处各写一遍

---

**为什么这一张不能并进 [06](06-mpc-node-fake-px4-fixture.md)**：如果把真 MPC（模型预测控制）和中间件一起第一次接上真 PX4，出问题时你分不清是"消息没送到"、"符号反了"还是"模型错了"。**每次只引入一个新变量**是本项目的指导思想。

**为什么不能并进 [09](09-sitl-tier-a-closed-loop.md)**：09 是**闭环**判据，本张是**开环单项**判据。09 失败时，本张已排除掉的四项正是它的归因基线。

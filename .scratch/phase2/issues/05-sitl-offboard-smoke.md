# 05: SITL 最小 offboard 冒烟 —— 在真 PX4 上一次验六件事

Status: done
Type: task

**What to build:** PX4 在 SITL 里**第一次真的照着我们发的指令动起来**。

用一个**不含任何 MPC（模型预测控制）数学**的最小节点，刻意把"中间件"与"模型/控制律"隔开。本张要排除的是四个**静默失败** —— 它们全都不报错、不崩溃，只表现为"没反应"，或更糟：飞机朝错的方向加速。

**Blocked by:** [01](01-sitl-px4-msgs-baseline.md), [03](03-sign-map-derivation.md)

**验哪六件事**（全部在**真 PX4** 上，不是假件）：

1. `px4_msgs` 与固件**真的对得上** —— 判据不是"话题在"，而是"**PX4 真的照做**"
2. **QoS 双向可通**（订阅 `fmu/out/*` 必须显式声明 `BEST_EFFORT`，否则话题列出来了但**一个回调都不进**）
3. 时间戳用**微秒**
4. offboard 心跳频率远高于最低要求（≥2 Hz，实做 50 Hz）
5. `thrust_body[2]` 的**符号与归一化** —— 只给悬停推力时飞机**不掉高**
6. 手写的小角速率步进的**倾斜方向**与 [03](03-sign-map-derivation.md) 的推导一致

- [x] 最小节点把 PX4 拉进 offboard（在此之前 setpoint 已以 ≥2 Hz 持续发布 **≥1 s**）
      ☠️ 原写"≥1 s"这条**一度是空话**：闸门开在进程年龄上、`--pre-stream` 是个没人读的旋钮，
      实测首帧后 **0.78 s** 就进了 OFFBOARD 而报告全绿。已改成量**已发布时长**（`streamed_s`），
      并加判据把秒数写进报告：baseline **2.06 s / 103 帧 @ 50.0 Hz**。见文档 §5.6
- [x] **只给悬停推力** → 飞机在 SITL 里**维持高度**（不掉高、不缓升）—— 这一条同时验了**符号**与**归一化常数**两件事
- [x] **给 ±ω 步进** → 机体倾斜 / 偏航方向与 03 一致
- [x] **断流实验**：杀掉节点 → PX4 在 `COM_OF_LOSS_T` 之后**自行退出 offboard**（证明心跳是唯一的维持机制）
- [x] 四个静默失败每一项都有**独立的一次观测**（不是"跑起来没报错"就算过）
- [x] 本张的指令是**参数化的 stub**，不引入任何模型 / 代价 / 约束代码
- [x] stub 与后续节点**共用同一份符号映射实现**（03 权威位置的代码侧），不是两处各写一遍

**三处代码/夹具上的实质发现（都不在票的清单里，是踩出来的）**：

1. **`--pre-stream` 是个没接线的旋钮**（见上面勾选项）：修法是闸门开在**已发布时长**上。
   这条差点以"全绿"收口 —— 判据本身没被满足，而报告看不出来。
2. **`px4_console` 的文本偏移游标会漏掉新打印的行**：pxh 的 `ESC[2K\r` 会跨两次 `read()` 到达，
   使"当时的渲染长度"这个游标切到半截序列里，`^TOPIC:` 这类锚行首的正则**永远等不到**
   （症状是"超时、重试才成功"）。改为**字节游标** `mark()` / `text_since()`；
   `wait_for(since=)` 保留但加了 ⚠️ 说明。这是**改夹具的取证工具**，不是改本张的判据。
3. **`vehicle_rates_setpoint` 是共享话题**：切 OFFBOARD **之前**，它上面是 `mc_att_control`
   每周期发的（≈0）帧 —— 所以"话题上有数"不能当"我们的指令到了"的证据（`mc_att_control_main.cpp:319-324`）。

**一处文档订正**：[`phase2-implementation.md`](phase2-implementation.md) §6.5 写"传成纳秒……PX4 可能直接丢弃"，
**实测不成立**：反序列化只做 `min(ts − time_offset, hrt)`，单位错只会静默变味（§6 有代码块与三支静默无害分支）。

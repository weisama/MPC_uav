# `sign-map` —— 符号映射表的**独立复核**

服务于 ticket [`../../.scratch/phase2/issues/03-sign-map-derivation.md`](../../.scratch/phase2/issues/03-sign-map-derivation.md)。

**权威在 [`docs/control/sign-map.md`](../../docs/control/sign-map.md)，不在本目录。**
本目录只做一件事：**用一条与那份文档互不相干的路径把同一张表再推一遍，然后对账。**

> ★ 为什么要有它：那张表是 **Phase 2 最容易摔机的一步**，而它错了**不会有任何东西报错** ——
> PX4 收到一条语法完全合法的消息然后照做。所以"推导写对了"这句话必须能被**跑一遍**检验，
> 不能只靠"读着挺有道理"。

## 快速开始

```bash
python3 tools/sign-map/test_sign_map_core.py --self-test     # 不需要飞机 / 飞控 / ROS / 通电
python3 -m pytest tools/sign-map/test_sign_map_core.py -q    # 仓库惯例的另一种跑法
```

自检**只读**本地文件与 `~/refs/` 下的两个外部仓库；不 import `rclpy`、不碰网络、不发任何消息。

⚠️ 两个文件名容易敲混：复核用例在 **`test_sign_map_core.py`**，`sign_map_core.py` 是被导入的库。
直接跑库文件**不会**跑任何用例 —— 它现在会打印指路并**退出码 2**（早先是静默退出 0，像"通过了"，
对一个专防静默错的工具来说太讽刺）。

## 它判什么（三类，缺一不可）

| 类 | 判什么 | 为什么这一类还不够 |
|---|---|---|
| **推导 vs 文档** | 独立推导出的符号 == 权威文档里的 `sign-map:canonical` 块 | 抓"文档被人改成另一个口径"；但**两张表一起错**时它抓不到 |
| **物理闭环** | ★ 同一条指令走 **ENU/FLU** 与 **NED/FRD** 两条约定，世界系加速度必须相同 | 抓"符号表自洽、但物理方向相反"—— 上一类**抓不到**这种 |
| **反例钉死** | 故意写反某个符号 ⟹ 断言飞机真的朝反方向 / 砸地 | 证明这些错法**真的会摔机**，而不是"看着别扭" |

外加两条「**非空转**」用例：故意改反文档 / 故意改错映射，断言对账判据**确实会红**。
没有它们就分不清"对账通过"与"对账根本没在看"。

## 怎么做到"互不相干"

1. **符号是算出来的，不是抄的。** `rates_flu_to_frd` 用的是"FRD 的 y/z 是 FLU 的 y/z 的反向"这一定义：
   把角速度当**物理矢量**逐轴投影（`sign_map_core.py` 里那三行 `_FLU_TO_FRD @ omega`），
   得到的 `[+1, −1, −1]` 是**结果**。推力同理（喂 1 N，看它在 FRD 的 z 分量上还剩多少）。
2. **文档里的数是唯一的。** 权威块由 `parse_canonical_block()` **解析**出来，不在代码里复写一遍；
   文档改了、推导没改（或反过来）⟹ 立刻红。
3. **物理闭环用两套独立积分。** ① 在 ENU/FLU 里直接积分姿态；② 把四个字段按 **PX4 自己的语义**
   （机体 FRD、世界 NED）积分再换算回 ENU。两条路径都只吃"指令"，断言输出相同
   —— 其中 ② 的重力、姿态右乘、`NED → ENU` 换算全都写在代码里可逐行读。

## 一个例子：它抓到过真东西

第一版把"往 +y（北）侧飞"写成了 `ω_x > 0`。自检的**侧飞用例**直接红了 ——
`R_x(θ)·e_z = (0, −sinθ, cosθ)`，θ>0 是把推力拽向 **−y**，所以往北飞要**左滚**（`ω_x < 0`）。
这个直觉陷阱现在被钉成一条一般性用例：**`ω = κ·(ẑ × d̂)`**（`d̂` = 期望加速度在机体系里的方向）。

## 它**证明不了**什么

- ❌ **证明不了「这套约定与真 PX4 一致」。** 推导、自检、以及将来的假 PX4 夹具，
  三者都只在**我们自己这一侧**闭环。唯一能回答这个问题的是 SITL 闭环
  （[ticket 05](../../.scratch/phase2/issues/05-sitl-offboard-smoke.md) 的开环单项、
  [ticket 09](../../.scratch/phase2/issues/09-sitl-tier-a-closed-loop.md) 的闭环判据）。
- ❌ 也**不要**为此去造一个"与被控对象同构"的 Python 闭环 —— 它与控制器共享同一套约定，
  整条约定错了它会**一起错并且通过**。该方案已被考虑并否决（理由见
  [`.scratch/phase2/spec.md`](../../.scratch/phase2/spec.md) Testing Decisions 的 seam 3 一节）。

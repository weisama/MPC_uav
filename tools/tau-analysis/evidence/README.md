# τ 实测的原始证据

**为什么有这个目录**：ticket 03 的交付物只有一句话 —— 一个**有出处**的 τ
（[`.scratch/phase4/issues/03-latency-tau-from-logs.md`](../../../.scratch/phase4/issues/03-latency-tau-from-logs.md)）。
原话是要求它**可追溯，「而不是从一个我没法回查的地方来的」**。
而跑出这个数的**日志在飞控 SD 卡上、中间产物在 `/tmp`** —— 两者都会没。
所以把关键几件**放进 git**，让出处链不依赖任何一台机器的临时目录。

结论本身（τ ≈ 50 ms）写在 [`docs/reference/mocap-setup.md`](../../../docs/reference/mocap-setup.md) **§6.3**。

**怎么读这三组数**（别只看一个数）：

- **悬停给 +45.9…+47.0 ms，r = 0.984…0.998**，且 **对照 −2.7/−2.8 ms** ⟹ 方法零点没问题，
  这条读数是 **0.05 s 这个取值的可追溯来源**。
- **八字给 +68.4…+69.4 ms，r = 0.969…0.994**，也干净，但**比悬停大 22–23 ms**。
  ⟹ **延迟不是常数**；不能拿悬停那一条去代表整轮飞行。差在哪一环**没有定论**
  （动捕机体解算的延迟可能随平移/遮挡变化，但没有第一手证据把它钉死）。
- **正方形给 +84…+87 ms，但 r 只有 0.864–0.869**，且该段 VO 最大间隔 **244 ms** ⟹
  **这条读数不可信**，只作为「计划外的 VO 丢帧会污染 τ」的例子保留。
  `--fc` 从 0.5 扫到 10 Hz 时正方形给 **+129 / +144 / +84 / +51 / +51 ms**（0.5/1/2/5/10 Hz），
  不是一条纯延迟该有的样子。
- **B 口径（加速度计 × `quat_body_down`）在这三趟上全部无效**：动捕 `body_down` 的激励σ
  只有 **0.033–0.043**，相关 r 在 **−0.04…−0.35**，τ 贴搜索窗边缘 ⟹ 记为「**未量出**」，
  不是「τ = −300 ms」。要验 B 仍需一段**近乎悬停、带倾角激励**的日志 —— 现有日志给不出来，
  **未做**（操作者 2026-10-17 裁定不再补做）。

## 这份证据**不能**替代什么（诚实交代）

1. **不含 ulog 本身。** 18.6 MB 的前缀不进 git。所以这里能回查的是
   「**那一次跑的是什么样的数据、用什么方法、得到什么数**」，
   而不是「**数据本身**」。要真正复跑，得**再从飞控拉一次 log 210**，
   并先核对 `sha256 = cd9bf4ec4ce61abef9adeb4a3a2b82d4bf3dd3e5e0eaa079af8eef6c02feaeed`
   （工具每次运行都会自己打印这个值，不用另找工具）。
2. **`id ↔ SD 路径` 没有建立。** MAVLink 日志协议只给 id。§6.3.2 里
   「SD 路径未建立」那一行就是这个意思，别在这里补一个猜出来的路径。
3. **log 210 本身只有一次机动。** 跨飞行复现已由上面 2026-10-17 那组补上，
   结论与不确定性表更新在 §6.3.5 / §6.3.6；**本目录仍只是原始读数**，读法以 §6.3.6 为准。
4. **`角速度` 口径的动捕字段（`angular_velocity`）全 0** —— 那是飞控侧的填充值，
   不能用；主口径走的是**四元数差分**。见 §6.3.1。

# τ 实测的原始证据

**为什么有这个目录**：ticket 03 的交付物只有一句话 —— 一个**有出处**的 τ
（[`.scratch/phase3/issues/03-latency-tau-from-logs.md`](../../../.scratch/phase3/issues/03-latency-tau-from-logs.md)）。
原话是要求它**可追溯，「而不是从一个我没法回查的地方来的」**。
而跑出这个数的**日志在飞控 SD 卡上、中间产物在 `/tmp`** —— 两者都会没。
所以把关键几件**放进 git**，让出处链不依赖任何一台机器的临时目录。

结论本身（τ ≈ 50 ms）写在 [`docs/reference/mocap-setup.md`](../../../docs/reference/mocap-setup.md) **§6.3**。

## 文件

| 文件 | 是什么 | 它支持 §6.3.2 的哪一行 |
|---|---|---|
| `fcu-log-list-2026-09-28.txt` | 飞控自报的日志列表**节选**（`LOG_REQUEST_LIST` 的原始输出） | `日志`：`id 210 / utc 2026-09-24 06:55:00 / size 49.09 MB` |
| `fcu-log-pull-2026-09-28.txt` | 三次拉取的**原始输出节选**（含停住的速率与字节数） | `本地文件`：`18,618,930 / 49,091,638 字节（37.9% 前缀）`、`⚠️ 下载未完成` |
| `tau_z0_log210_fc2.0_seg3.json` | 工具的**完整输出**（三个口径的 τ / r / N、分段、参数、以及它自己算的 sha256） | `sha256`、`分析窗口`、`窗口内样本`、`参数`、以及 §6.3.3 的全部读数 |

JSON 由**仓库里的这版代码**产出：

```bash
python3 tools/tau-analysis/tau_from_ulog.py <log.ulg> --fc 2.0 --segments 3 --json <出参>
```

## 这份证据**不能**替代什么（诚实交代）

1. **不含 ulog 本身。** 18.6 MB 的前缀不进 git。所以这里能回查的是
   「**那一次跑的是什么样的数据、用什么方法、得到什么数**」，
   而不是「**数据本身**」。要真正复跑，得**再从飞控拉一次 log 210**，
   并先核对 `sha256 = cd9bf4ec4ce61abef9adeb4a3a2b82d4bf3dd3e5e0eaa079af8eef6c02feaeed`
   （工具每次运行都会自己打印这个值，不用另找工具）。
2. **`id ↔ SD 路径` 没有建立。** MAVLink 日志协议只给 id。§6.3.2 里
   「SD 路径未建立」那一行就是这个意思，别在这里补一个猜出来的路径。
3. **只有一次机动、没有跨飞行复现。** 证据支持「τ ≈ 50 ms 这个量级」，
   不支持更细的精度。见 §6.3.5 的不确定性表。
4. **`角速度` 口径的动捕字段（`angular_velocity`）全 0** —— 那是飞控侧的填充值，
   不能用；主口径走的是**四元数差分**。见 §6.3.1。

# `battery-thrust` 的原始证据 —— 从**已归档的飞控日志**读电池能供多少

服务 ticket [phase3/08](../../../.scratch/phase3/issues/08-battery-sustainable-thrust-from-archived-ulogs.md)。

**为什么有这个目录**：本票的交付物是**三个数 + 一份"取不到什么"的清单**。
三个数要能被别人独立复算，所以工具的完整输出（含 `sha256`、口径、判据）落进 git，
而不是留在跑完就没了的地方。

> ⚠️ **`/tmp` 不算"落进 git"**：本机根盘是 ext4 且 tmpfiles 里有一条 `D /tmp`，
> 开机即清 —— 归档证据过不了重启（本仓 2026-09 踩过）。

## 文件

| 文件 | 是什么 |
|---|---|
| `<sha8>__<场景>.json` | 单份 ulog 的**工具完整输出**：内嵌参数、在飞窗口、各列统计、判据自检、锚点、外推、`missing` 清单、`sha256` |
| `<sha8>__<场景>.txt` | 同一份的**人读版**（工具标准输出原样） |
| `summary_*.txt` | 上面全部汇成的表 + 低电量端投影 + 指纹核对（由 `summarise.py` 现算） |
| `summarise.py` | 汇总脚本 —— **票面里每个数都从 JSON 现算**，不许手抄 |

一份 ulog 对应一份 JSON。文件名前缀是 ulog 的 `sha256` 前 8 位，
所以"这个数是从哪份字节算出来的"是可回查的。

## 复算命令（**只读本地文件；不碰飞控、不发 MAVLink、不起链**）

```bash
cd <仓库根>
# 单份（票面结论给的就是这一条）
python3 tools/battery-thrust/battery_from_ulog.py bag/old/3_traj1_hover/fcu/log_2_2026-9-29-15-29-26.ulg

# 全部归档（含 bag/old/）→ 重生成本目录的 JSON/TXT
for f in $(find bag -name '*.ulg' | sort); do
  d=$(dirname "$(dirname "$f")"); s=$(basename "$d"); p=$(basename "$(dirname "$d")")
  [ "$p" = old ] && t="old-$s" || t="$s"
  base="tools/battery-thrust/evidence/$(sha256sum "$f" | cut -c1-8)__$t"
  python3 tools/battery-thrust/battery_from_ulog.py "$f" --json "$base.json" > "$base.txt"
done

# 汇总表（读本目录的 JSON，不重读 ulog）
python3 tools/battery-thrust/evidence/summarise.py
```

## 它支持什么（三条，对应票面三个问题）

**① 可持续的电流。** 先说清这一格答的是什么：日志量的是**飞机当时抽了多少**（**需求**），
不是**电池还能供多少**（**能力**）—— 15 A 的预算从没被用掉过（最高只到 39%），
所以**能力上限在本目录里取不到**，下面全是需求的下界。

- **在飞后半 = 放电末端**（票面要的那一端）：**4.46 – 5.51 A**
- 在飞前半（电量较高一端）：4.86 – 5.87 A
- 全段最大（1 s 滑窗中位的最大值）：4.86 – **5.86 A**（`old/4_traj3_lemniscate`）

⚠️ **"全段最大"这一列，7 份有在飞段的日志里 5 份落在在飞窗口的起点**（解锁/起飞那一瞬）——
正是票面点名排除的那一列，**不能**当问题 ① 的答案。每份 JSON 的
`current.sustained.at_flight_start` 会标出来，文本报告里紧跟着打一条警告。

判据之所以选**滑窗中位**而不是单点最大：`4_traj2_square` 的单点最大 11.38 A
而同一段滑窗中位只有 4.91 A，差 2.3 倍。

**② 换算成推力/功率。** 以**稳态悬停**为锚（稳态时推力 ≡ `m·g`，物理给的，
与控制器里的 `hover_thrust` 无关）：悬停功耗实测 **76–84 W**（各场 3.36–4.13 A）。
按 `P ∝ T^1.5` 外推到 `f_max = 11.8 N`（= 悬停推力的 1.604 倍）⟹ **155–172 W**，
电流 **7.0–8.5 A**，占 15 A 额定的 **47–57%**（低电量那两份偏高，因为同样功率在低电压下要多抽电流）。

**③ 取不到的。** 见每份 JSON 的 `missing` 一节，以及下面"它**不能**证明什么"。

## 它**不能**证明什么（★ 比上面那节重要）

1. **`f_max = 11.8 N` 保不保守，本目录给不出答案。** 因为 `f_max` 本身就是从
   §6.2 的 15 A 反推出来的，而反推用的电机台架效率比实测**差 ~2 倍**
   （模型 164.7 W vs 实测 76–84 W）。于是有两个互相退化的解释：

   | 解释 | 悬停的真实电流 | `f_max` 处的真实电流 | 结论 |
   |---|---|---|---|
   | (a) `BAT1_A_PER_V = 17.0` 标度对 | 3.4–4.1 A（实测） | ~7–8.5 A | 保守（约 2× 余量） |
   | (b) 标度**低估**了 ~2× | ~7–8 A | ~15 A | **恰好压在额定上，不保守** |

   日志里**没有任何量能分开 (a) 与 (b)**：没有拉力台、没有钳形表、没有库仑计、
   没有第二条电流通路。要判定，只能做那条"只有人能做"的台架量 ——
   **正是本票当初被指望能免掉的那条**。
   （唯一与它相关的旁证是内阻回归：拟合出 90–200 mΩ，与数据手册 78 mΩ 同量级 ——
   但若标度低估 2×，回归出来的 R 会**缩到** 45–100 mΩ，同样"同量级"。这条**不区分**。）

2. **低电量端没被飞过。** 归档里最低的一段只到 **19.26 V**（3.21 V/节）、
   最低的悬停锚点 20.48 V；而实用截止是 **18.0 V**（3.00 V/节）。
   `summarise.py` 把悬停工作点按 `P = V·I` 投影到 18 V 得到 ~9.5 A（占 64%），
   但那是**投影**：既没含低 SOC 时内阻上升，也没含电压崩塌。**不是测量。**

3. **单节电压这一列取不到。** z0 是**模拟**电源模块，`voltage_cell_v[*]` 字段在、
   **整份日志全为 0**（PX4 只有 `batt_smbus` / smart battery / `tattu_can` / `cyphal` 会填）。
   `cell_count = 6` 是 `BAT1_N_CELLS` 这个**参数**，不是读数。

4. **电流单点不是读数。** 见工具 README §4：`current_a` 的样本级抖动
   （1.0–1.24 A）在电压上留下的印记比物理下界还小 2.6–3.4 倍 ——
   **骑在判据阈值上**，两种解释（采样噪声 / 电压通道被硬件滤波）都活着。
   所以本工具**不让这条判据做决定**：一律用窗口均值，单点永不作为判据。

5. **`current_average_a` 与 `scale` 都不是测量。** 前者是初值为 `BAT_AVRG_CURRENT = 15.0`
   的慢滤波；后者是**推力补偿系数** `v_charged / bat_v`（夹在 [1.0, 1.3]），
   电流的标定在 `BAT1_A_PER_V`。⚠️ 本票票面把 `scale` 当成了"电流标定"，**那一句是错的**。

## 与本仓其它文档的两处**对账**

- **`bag/MANIFEST.md` 的 5 份 ulog 指纹**：工具算出来的 `sha256` 与清单登记的
  **逐字节一致**（`summarise.py` 每次跑都核对，打印"全对"）。
  这也是"读的就是登记的那份字节、不是同名的另一份"的证据。
- ⚠️ **`bag/old/` 里的日志是本票的关键输入之一，而 `MANIFEST.md` 不登记它们**
  （清单只登记每个场景"当前该用的那一份"）。本票问的是**电池状态**，
  被后一次录制取代**不影响**"当时那块电池剩多少电" ⟹ 用 `old/` 是对的，
  但必须在结论里写清用的是哪一份（本票用的是 `old/3_traj1_hover`
  与 `old/4_traj3_lemniscate`，它们是归档里电量最低的两段）。

## ⚠️ 一处顺带发现（**不改**，只报）

`docs/reference/hardware.md` §6.3 结尾写着：

> ✅ **一处侧面佐证**：`z0.params` 里 `BAT_AVRG_CURRENT = 15.0` **恰好等于 VTC6 的实测持续放电能力**。
> 说明这个值被认真设过……

这条推理**不成立**：`BAT_AVRG_CURRENT` 的 `PARAM_DEFINE_FLOAT(..., 15.0f)`
就是 PX4 的默认值（`src/lib/battery/battery_params_common.c:101`），
且 `boards/` 与 `ROMFS/` 里**没有任何一处**覆盖它 —— 所以"15.0"与
"**从没人动过这个参数**"完全相容。（同族：`BAT_V_OFFS_CURR = 0.0` 也是默认值。）

数值本身没错（15 A 就是 VTC6 的 Mooch 实测持续放电），错的是"因此说明它被认真设过"。
**本票不改 `hardware.md`**（不顺手改别人的领地）；报给操作者裁定。

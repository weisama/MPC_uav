# `battery-thrust` —— 从**已归档的飞控日志**读"电池能持续供出多少推力/功率"

服务 ticket [phase3/08](../../.scratch/phase3/issues/08-battery-sustainable-thrust-from-archived-ulogs.md)。
⚠️ **只读工具**：只读本地 `.ulg`，**不碰飞控、不发任何 MAVLink、不起链、不解锁**。

同族工具：[`tools/hover-thrust`](../hover-thrust/)（从日志反推归一化常数）、
[`tools/tau-analysis`](../tau-analysis/)（从日志辨识时间常数）。
本工具与它们共用同一套读取约定（阶梯取值、在飞掩码、稳态判据）与文档习惯。

## 1. 量的是三个东西（票面三个问题，一一对应）

| 票面问题 | 本工具怎么答 | 口径落在哪一列 |
|---|---|---|
| ① 可持续的电流上限是多少 | 见下方 ★ —— 日志只能给**需求**，给不了**能力**；报**在飞后半（放电末端）**、**在飞前半**、**全段最大**三个数 | `current_a`（单点不可用，见 §4） |
| ② 换算成推力/功率是多少 | **稳态悬停锚点**（推力 ≡ `m·g`）+ `P ∝ T^1.5` 外推到 `f_max` | `voltage_v × current_a` |
| ③ 这次取不到什么 | `channel_verdicts` + `missing` 两节，逐条点名并写明为什么 | —— |

```
可持续电流 = max over windows( median( current_a in 1 s ) )
                        ↑ 不是 current_a.max()：4_traj2_square 的单点能到 11.38 A，
                          而同一段滑窗中位只有 4.91 A —— 差 2.3 倍，方向永远是"单点更大"
悬停锚点   = 在飞段里最长的稳态段（|v| ≤ 0.3 m/s ∧ 倾角 ≤ 10° ∧ 连续 ≥ 2 s）
             T = m·g（= 7.3549875 N @ 0.75 kg），P = V·I，取该窗口的 V 中位 × I 均值
外推       = P(f_max) = P_hover × (f_max / m·g)^1.5
```

★ **① 这一格答的是什么，要说清**：上面这个"全段最大"是**观测到的需求**，不是电池**能力**。
预算（15 A）从没被用掉过 ⟹ 能力上限取不到。而且"全段最大"天生往负载最高那一瞬跑 ——
归档 7 份有在飞段的日志里，**5 份就落在在飞窗口起点**（解锁/起飞那一瞬），即票面点名排除的那一列。
工具会自己把这条警告打出来（字段 `current.sustained.at_flight_start`）。
票面要的"电量低端"口径看**在飞后半（放电末端）**那一行（归档实测 4.46–5.51 A）。

## 2. 为什么悬停能当锚点

稳态悬停时**推力必须等于重力**（受力平衡）⟹ `T = m·g` 是**物理**给的，
不是从模型里抄的，也与控制器里的 `hover_thrust` 无关。
这与 `tools/hover-thrust` 的论证是同一条，只是用法相反：那边拿它反推归一化，这边拿它当"电流 ↔ 推力"的刻度。

⚠️ **`eligible`（先夹到在飞段）不是可有可无的**：地面上飞机静止、倾角为零，
**比真悬停还"稳态"** —— 不夹的话"最长稳态段"会被地面段整段赢走
（锚点落到静置电压 + 静态电流上，两个都不是我们要的量）。第一版没这一步，
归档里**八份日志一份锚点都没取到**。合成用例 `test_锚点被夹在在飞窗口内_地面段赢不走` 钉住它。

## 3. ★★ 说清 `f_max` 与 `t_max` 是两个量

`f_max = 11.8 N`（OCP 的 `F` 上限，`ocp.py` 的 `ubu[0]`，出处 `params.py` 的 `F_MAX_BATTERY`）
**按电池**设 —— 就是 §6.2 用 15 A 反推出来的那个 11.75 N。
`t_max = 46.3027 N`（归一化常数，`F` → PX4 `thrust_body`）**按电机/桨**设 —— 实测满量程。

两者之比 **3.924 倍**。**混用会把可行域整体抬高这么多倍**（历史 bug：回填 `hover_thrust` 时
顺手把 `F` 上限从 11.8 抬到 46.3，而所有测试全绿）。
本工具的换算**一律只用 `f_max`**，`t_max` 只在报告里作为提醒出现。
可证伪形态：`test_外推目标就是f_max_不是t_max` —— **换 `f_max`，外推结果必须跟着换**。

## 4. ★★ 单点不可用，但**不靠**那条判据来决定

`current_a` 的**样本级**抖动（1σ ≈ 1.0–1.24 A）在电压上留下的印记比物理下界
（`noise_I × R_min`，`R_min = 78 mΩ` = VTC6 6S1P 的整包内阻）还小 **2.6–3.4 倍**。
这个比值**骑在 3 倍的阈值上** ⟹ 两种解释都活着：

- (a) 那些抖是**采样噪声**（不是电池电流）；
- (b) 抖是真的，而**电压通道被硬件 RC 滤波**（电源模块分压线上加电容很常见）抹平了。

**日志里分不开 (a) 与 (b)。** 所以本工具**不让这条判据做决定**，而是写死一条口径：

> **一律用窗口均值；单点永不作为判据。**

理由与那条判据无关 —— 在两个世界里单点都是**错的统计量**：
(a) 下它是纯噪声；(b) 下它是个真实的**瞬时**值，而我们要的是"**持续**多少"。
均值在两个世界里都无偏。报告里 `signature` 一节的 `policy` 字段把这条钉死，
`verdict` 只描述**观察**（`visible-in-voltage` / `not-visible-in-voltage`）——
`test_单点口径不依赖那条判据` 保证观察变了口径不变。

⚠️ 另有一条纪律：`r_int_ohm` 是**回归拟合**出来的，分箱相关性不显著时它只是噪声的产物。
`fit_is_identifying = false` 时**别把那个数当测量值引用**（它会给出 90–200 mΩ 这种"很像内阻"的值）。

## 5. 怎么用

```bash
cd <仓库根>

# 单份（只读本地文件）
python3 tools/battery-thrust/battery_from_ulog.py bag/2_manual_takeoff/fcu/log_1_2026-9-29-15-25-14.ulg

# 整批（目录递归找 *.ulg，含 bag/old/）；--quiet 一份一行摘要
python3 tools/battery-thrust/battery_from_ulog.py bag/ --quiet

# 落证据（★ 落到仓库里，别落 /tmp —— 见 evidence/README.md）
python3 tools/battery-thrust/battery_from_ulog.py <log.ulg> --json tools/battery-thrust/evidence/x.json

# 汇总表 + 指纹核对
python3 tools/battery-thrust/evidence/summarise.py
```

常用开关：`--mass`（默认 0.75 kg，✅ 用户实测）、`--f-max`（默认 11.8 N）、
`--rating`（默认 15.0 A，VTC6 的 Mooch 实测持续放电）、
`--v-eps` / `--tilt-eps-deg` / `--min-duration`（稳态悬停判据）、
`--window` / `--min-n`（滑窗）、`--prop-exponent`（默认 1.5）。

**退出码**：`0` 有在飞段且有稳态悬停锚点 / `2` 有在飞段但取不到锚点（只能答问题 ①）/
`4` 没有可分析的在飞段。
⚠️ 目录模式下取**各文件中最差的那个** —— 宁可整批看起来更糟，
也不要因为有一个"好人"就让整批显示绿。

## 6. 自检（不需要飞机、不需要日志、不需要飞控通电）

```bash
python3 tools/battery-thrust/test_battery_core.py --self-test      # 23 项，纯函数
python3 tools/battery-thrust/test_battery_from_ulog.py --self-test # 21 项，假 ULog
python3 -m pytest tools/battery-thrust/ -q                          # 44 项
```

三条**刻意的变异测试**（"新断言要主动弄坏一次"）：

- `test_可持续判据忽略孤点` —— 把滑窗中位换成单点最大，`value < raw_max` 立刻红；
- `test_判据自检在电流与电压无关时不认那点耦合` —— 造一份 `I` 与 `V` **无关**的数据，
  逼工具说出"电压里看不见"，并同时要求拟合出的 `R` 被标成**不可辨识**
  （只测 `verdict` 的话，"把 `b` 当内阻用"这条会漏掉）；
- `test_全段最大落在在飞窗口起点要点名` / `test_全段最大落在起飞那一瞬要在摘要里标出来` ——
  把 `at_flight_start` 恒置 `True`/`False`、或从摘要行里去掉 `★起` 标记，立刻红。
  ★ 这两条是**被一次复核逼出来的**：复核把"全段最大"那一行直接读成了问 ① 的答案，
  而归档 7 份里有 5 份的最大值就落在起飞那一瞬 —— 正是票面点名排除的那一列。

## 8. 它能与不能证明什么

**能**：归档日志里电池**实测**供出的电流/功率是多少（口径、窗口、字段都写在报告里）；
按实测效率外推 `f_max` 需要多少电流；以及**这次哪些量取不到**。

**不能**（★ 这一节比上面重要）：

1. **`f_max = 11.8 N` 保不保守 —— 给不出答案。** `f_max` 本身是从 15 A 反推的，
   而反推用的台架效率比实测差 ~2 倍 ⟹ "实测省电 2×"与"电流标度低估 2×"
   **互相退化**，日志里分不开。详见 [`evidence/README.md`](evidence/README.md)。
2. **低电量端**。归档里最低只到 19.26 V（3.21 V/节），实用截止是 18.0 V。
   投影到 18 V 是 ~9.5 A（占 64%），但那是**投影**，不是测量。
3. **单节电压**。模拟电源模块不填 `voltage_cell_v[*]`（整份全 0）。
4. **`current_average_a` / `scale`**。前者是滤波器，后者是推力补偿系数 —— 都不是电流测量。

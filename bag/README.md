# `bag/` —— z0 的**录制产物**（ticket 19）

**这里面是数据，不是代码。** 每一份都是现场飞出来的：`ros2 bag record` 录下的功能包 + 从飞控
SD 卡拷回来的日志。**改动它们没有意义**（要重录就重飞），所以本文件只讲"哪一份是什么"，
外加一节**这一趟录到了什么**（2026-09-29 那四份的实测读数）。

## 目录长什么样

**扁平一层**：一个场景一个目录，目录名就是 `Scenario.slug`（操作者 2026-09-29 拍定，
原先那层 `<YYYY-MM-DD>/` 已经取消 —— 同一台飞机只飞这一天，多一层只让人多点一次）。

```
bag/
├── MANIFEST.md                 ← ★ 自动生成的总表：每份包多长、多大、sha256、**缺了什么**
├── README.md                   ← 本文件
├── .recorder.json              ← **只在正录着的时候才有**（那份的状态；**不入库**，见 .gitignore）
│                                  ⚠️ 本仓现在**没有**它 —— 2026-09-29 那份残留已按操作者裁定删除
├── z0-params-2026-09-29.params ← 当天从飞控导出的参数**原样存档**（见下面「参数导出」）
├── 1_static/                   ← 一个场景一个目录，由 `rosbag2` **自己建**（见下面那条 ⚠️）
│   ├── metadata.yaml           ← 收口那一刻写的索引；**它在这儿 = 这份包是干净收口的**
│   ├── 1_static_0.db3.zstd
│   ├── session.json            ← ★ 我们写的核对结果（话题/帧数/时长/sha256/缺什么）
│   └── fcu/                    ← 从飞控 SD 卡**手工拷**回来的 `.ulg` + 它的 `INDEX.md`（见下）
│       ├── INDEX.md
│       └── log_0_2026-9-29-15-22-20.ulg
├── 1_static.log                ← `ros2 bag record` 自己的输出（问"包为什么是空的"就看它）
├── 2_manual_takeoff/ …  3_traj1_hover/ …  4_traj3_lemniscate/   ← 同构
└── 2_manual_takeoff.log … 3_traj1_hover.log … 4_traj3_lemniscate.log
```

## 谁写的、怎么录

| 动作 | 入口 |
|---|---|
| 起录（选场景 1–4） | `run/z0.py rec_start N`，或菜单 **11= 开始录制（选场景 1–4）** —— ★ **它占住终端** |
| 收口 | **到点自己收**（四份统一 120 s）；想提前停就在那个终端按 **Ctrl-C** |
| 归档飞控日志 | **手工**：拔 SD 卡，把 `.ulg` `cp` 进 `bag/<场景>/fcu/` |
| 给缺 `session.json` 的包补一份 | `run/z0.py rec_adopt`（★ **事后重建**，见下） |
| 重算本目录的总表 | `run/z0.py rec_manifest` |
| 现在在录什么（只读） | `run/z0.py rec_status`（在**另一个终端**看 —— 录制那个终端被占着） |

★ **一份包的生命周期在一台终端里走完**（操作者 2026-09-29 现场拍定）：菜单 11 印完场景卡就起录，
屏幕上走倒计时，**录满 120 s 自己收口**并当场打印核对表。⚠️ 因此**没有**"停止录制"这一项了 ——
旧版把录制丢在后台、另有一项专门去停它，现场那个"录到哪了"反倒看不见。

★ **收口那十几秒里 Ctrl-C 是无效的**（写缓存 → 压 zstd → `ros2 bag info` 核对 → 写
`session.json` + 清单），屏幕上会明说。这条是 2026-09-29 用**三份包**换来的：旧版的"忽略
Ctrl-C"只包住"等它退出"那一段，操作者连按了一下，后面几秒被打断 ⟹ 包是好的，`session.json`
没写成 ⟹ 那三份包在总表里整个隐形。（`run/rec.py` 的 `_sigint_ignored` ★★ 段记着全过程。）

实现在 [`run/rec.py`](../run/rec.py) —— 文件头写着**为什么要有这一层**（B 档 ticket 11 要的
真实动捕包**从来没录过**）与全部第一手取舍。**它只订阅**：不解锁、不起飞、不切模式、不改参数、
不发任何一帧（那条边界由 `run/tests/test_rec.py` 的 AST 用例盯着）。

## 四个场景

场景定义（起哪条链、人要做什么、包里该有什么）在 [`run/rec.py`](../run/rec.py) 的 `SCENARIOS`，
**只有那一处**（改场景就改它，别来抄这张表）。目录名就是它的 `slug`：

| # | 目录 | 一句话 | 起链 |
|---|---|---|---|
| 1 | `1_static` | 动捕 + mavros 起来后**原地静止** —— 噪声基线 | 菜单 **8= 一键启动（动捕+mavros，手动遥控飞）** |
| 2 | `2_manual_takeoff` | 定点模式**缓慢推摇杆**起飞到 ~1 m，稳住再落回 | 同上（菜单 8） |
| 3 | `3_traj1_hover` | 执行**轨迹 1**（原地悬停 60 s） | 菜单 **9= 一键启动全部（选轨迹 → 按开始键）** |
| 4 | `4_traj3_lemniscate` | 执行**轨迹 3**（r = 0.5 m 八字） | 同上（菜单 9） |

★ **场景 1/2 与 3/4 不是同一次起链**：2 是手动遥控飞，`control` 不能同时在跑（它会一直流
setpoint 并请求 OFFBOARD，与手动飞行冲突）⟹ 前两个走菜单 8、后两个走菜单 9。
⚠️ **换链之前先停掉上一个会话**（`down`），否则第二段会起在别人的 setpoint 流上。

## 这一趟的数据说明了什么

（全部在 `/tmp` 的副本上量的 —— **不在 `bag/` 里就近取数**，见下「几条要知道的坑」。）

### ① 动捕输入干净得能做基线（场景 1）

飞机全程**没解锁**（`/mavros/state` 的 `armed` 一次都没真过；飞控侧 `arming_state` 也全程 = 1），
`/mocap/pose_enu` 在 **175.7 Hz** 上抖动量级 **0.05 mm**：

| 轴 | 均值 | 标准差 | 峰峰值 |
|---|---|---|---|
| x | −0.0000 m | 0.000048 m | 0.0004 m |
| y | +0.0001 m | 0.000050 m | 0.0003 m |
| z | −0.0000 m | 0.000058 m | 0.0002 m |

⟹ 后面三份的动作量（厘米～米级）**不是噪声衬托出来的**：这份包里的动捕噪声比它们低三个数量级。
飞控侧同期的 z 也稳在 ±2 mm（`1_static/fcu/INDEX.md`），两边互相印证。

### ② 手飞那一趟（场景 2）：起飞到 1.45 m，水平漂了 30 cm

解锁 57.0 s（包）/ 57.3 s（飞控日志），最高 **1.450 m**（日志 1.449 m），油门 ch3 从 989 → 1814。
水平包络 0.305 × 0.145 m —— 手飞的正常量级，**这不是控制器的指标**（人拿着摇杆）。

### ③ 悬停那一趟（场景 3）：状态机走全了，PX4 自己的位置控制器够用

`/control/state` 的迁移（t 以包起点为 0）：

```
MANUAL/STANDBY →(12.9 s) AUTO/STANDBY → AUTO/TAKEOFF →(19.7 s) AUTO/HOVER
→(21.7 s) AUTO/WAIT_START →(26.6 s) AUTO/TRACK →(86.6 s) MANUAL/LAND →(92.9 s) MANUAL/STANDBY
```

`/traj/progress` 从 0 走到 1.0 用了 **60.00 s**（26.57 → 86.57 s），正好是轨迹 1 的
`hover_duration_s: 60.0`。TRACK 那 60.04 s 里，实际位置相对**位置设定点**的偏差：

| | 均值 | 最大 |
|---|---|---|
| 水平 | **5.1 cm** | **10.7 cm** |
| 高度 | −5 mm | 19 mm |

★ 位置设定点就是 `traj` 节点那条参考（两者的 xy 包络逐位相同，时间差中位 7 ms）。
⚠️ `≤ 15 cm` 这条线是 [11 号票](../.scratch/phase2/issues/11-sitl-tier-b-seam3.md) 给
**SITL B 档（我们自己的控制器）**定的，这里是 **PX4 内置 PID** 在飞，两者不能互相印证 ——
这份数字的价值是**同一架真机的基线**：MPC（模型预测控制）接管后要拿它比，不是拿它交差。

### ④ 八字那一趟（场景 4）：**明显跟不上**（这份数据的重点）

参考轨迹的包络是 **1.000 × 0.500 m**，实际只飞出来 **0.750 × 0.265 m**；TRACK 的 6.15 s 里
（`/traj/progress` 走到了 1.0，也就是**轨迹跑完了**，不是被掐断）：

| | 均值 | 最大 |
|---|---|---|
| 水平 | **0.371 m** | **0.592 m** |
| 高度 | −9 mm | 20 mm |

水平误差的最大值 ≈ 八字 x 半幅（0.5 m）的 **1.2 倍** ⟹ 不是"差一点"，是**画不出那个形状**；
高度那一轴完全没问题（20 mm）。**结论：这份包记的是"跟不上"**，所以：

- 它**不能**用来判"控制器跟得上轨迹"（那是 11 号票判据 2 要问的）；
- 它能用来当**回归基线**：0.5 m/s 的八字对现在这套（PX4 内置 PID + 现在的参数）就是太快了，
  MPC（模型预测控制）接管后如果这个数不掉下来，说明没变好。

⚠️ 只有一趟、只有一个速度（`max_speed_ms: 0.5`），**别从这一份外推到"控制器不行"** ——
它说明的是**这一点上**跟不上。

### ⑤ 时钟：包的时间戳是真 UTC，日志的不是

`/mavros/time_reference` 里飞控自报的时刻与 ROS 时刻差 **0 s**（mavros 的 timesync 把飞控钟拨过来
了）⟹ `session.json` 里的 `started_utc` / `stopped_utc` 是**真 UTC**，能与墙上钟、能与日志文件对表。
⚠️ 但 `.ulg` **自己**的时间戳是**开机相对**的（`K: time_ref_utc = 0`），**不能直接相减** ——
包与日志的对应关系是靠内容对上的，见各 `fcu/INDEX.md`。

## 每份包"够不够用"看哪里

`session.json` 是**收口那一刻的核对结果**，`MANIFEST.md` 是它的总表。判据只有一条：
**`Scenario.expect` 里列的每条话题，包里有没有帧** —— 缺一条就会在 `missing_expected` 里点名，
并在总表的「缺了什么」一节列出来。★ 这份仓库对"静默为空"交过两次学费，所以这里
**不写"基本成功"**：要么 ✓，要么把缺的名字写出来。

| 字段 | 用途 |
|---|---|
| `started_utc` / `started_local` | 与飞控日志对表（理由见上一节 ⑤） |
| `stopped_utc` | 收口时刻。⚠️ 场景 1 起录那一刻写下的是自己的钟，2–4 是 `rosbag2` 报的写盘时刻，两者差约 2 s（起进程的开销） |
| `stop_signal` / `closed_cleanly` | 干净收口 = `SIGINT`（后面还写着**为什么收的**：到点 / 人按的 Ctrl-C / 它自己退的）+ `true`；不是的话 `metadata.yaml` 是 `ros2 bag reindex` 补的 |
| `sha256` | **包内容**的摘要（`metadata.yaml` 不算 —— 它带时间戳字段，逐次都会变）⟹ 拿同一份目录重算得对齐 |
| `git_head` / `git_dirty` | 录的时候代码是什么状态（包要能与代码对上） |
| `argv` / `include_regex` | 当时实际发出去的命令 —— 话题口径的唯一证据 |
| `reconstructed` | ★ **只在事后重建的那些里有**：写明哪几项是重建的、取自哪里、哪几项取不到 |

### 事后重建的那三份（`rec_adopt`）

2026-09-29 那次收口被打断，场景 2/3/4 的 `session.json` **没写成**（包本身是好的）。
`run/z0.py rec_adopt` 从包自己的 `metadata.yaml` 与旁边那份 `<场景>.log` **反推**补了一份：

- **只对没有 `session.json` 的包动手**：已经入账的一个字节都不碰（那是收口那一刻的实测读数，
  比事后重建可信）；
- **不改包内容**：不重命名、不重压、不动 `metadata.yaml`；`sha256` 是现在现算的；
- **取不到的字段一律 `null`，不猜**（`pid` / `git_head` / `git_dirty` / `ros_domain_id` ——
  它们只在起录那一刻存在，包里没有它们的影子）；目录名认不出场景时**只报不动**；
- 补完会重算 `MANIFEST.md`。

★ **场景 1 的 `session.json` 是原始的那一份**（当时活着写下来的）。这次搬目录只改了它里面
**四个路径字段**（`slug` / `dir` / `files` / `log`）；`argv` 与 `info_text` 是当晚**真跑过的命令与
`ros2 bag info` 的原文**，**逐字未改**（那两处里面还是老路径 —— 那是史实，不是笔误）。
包的 sha256 在搬完前后**逐字相同**（迁移脚本自己核过）。

## 飞控日志（`fcu/`）—— **手工拷**，一场景一份

从 SD 卡直接拷（**不是**走 MAVLink 拉）：mavros **独占**串口，本机没有第二条 MAVLink 通道走 FTP，
所以现场是**拔卡拷**。操作者 2026-09-29 拍定这条路**保持手工**（原先的菜单 13 连功能一起删掉）：

```bash
cp /media/chen/<卡>/…/log001.ulg  bag/<场景>/fcu/log_1_2026-9-29-15-25-14.ulg
run/z0.py rec_manifest            # 拷完重算一次，总表把新文件列出来
```

★ **一个场景一个 `fcu/` 目录**，每份里再放一个 `INDEX.md` 记它自己的来路（拷进来时的文件名、
大小、sha256、**SD 上的原始路径**、以及"为什么这一份配这个场景"的判据）。
`fcu/` 这一层**不校验、不比对**（它只上总表）—— `INDEX.md` 是拷的人手写的，没有工具生成它。

⚠️ **`SDLOG_MODE = 2`（`from boot until shutdown`）⟹ 一次上电 = 一个日志文件**。
四份日志 ⟹ 那天的日志是按**四次上电/重启**分开的（一个场景一趟）。
（这一条是从**参数**推的，不是从日志里读到的 —— 日志自己的时间戳是开机相对的，看不出上电时刻。）
⚠️ SD 原始路径**当时没有逐字记下来**，四份 `INDEX.md` 里那条是**按文件名反推**的，
并附了四条反证 —— 回查时按"推断"读，别当核实过的。

## 几条要知道的坑

- ⚠️ **`rosbag2` 拒绝往已经存在的目录里录**（`[ERROR] rosbag2: Output folder '…' already exists.`，
  它**不覆盖、也不接着录**）⟹ `run/rec.py` 的 `rec_start` **不预先建**这个目录，日志也挪到了
  包目录**旁边**；目录已存在时它**只报不动**（`rec_start` 从不替你删包）。
  ★ 扁平布局的代价：**同一个场景再录一次会撞上已有目录** —— 那正是这条 ⚠️ 生效的地方：
  要么先把旧包挪走，要么改 `SCENARIOS` 里的 slug。
- **`bag/` 是入库的**（操作者 2026-09-29 拍定），体积代价是明说过的：一份 120 s 的包压完
  大概几 MB 到几十 MB（`zstd`，在收口那一刻压）。要瘦身就改 `rec.INCLUDE_REGEX` 收窄话题 ——
  **别在这里手删**，删了 `session.json` 与包就对不上了。
- ⚠️ **量包先把包拷到 `/tmp` 再量，绝不在 `bag/` 里就地动**（ticket 19 的纪律）。
  `rosbag2_py` 也**打不开 `*.db3.zstd`**（`SQLite error (26): file is not a database`）——
  要先 `zstd -d` 并把 `metadata.yaml` 里的 `relative_file_paths` / `files[].path` 改成 `.db3`。
- **`*.db3.zstd` 用 `ros2 bag info` / `play` 读都没问题**（上面那条只针对 `rosbag2_py` 直接开）。
- 这些包**正在被谁用**：[ticket 11](../.scratch/phase2/issues/11-sitl-tier-b-seam3.md)（B 档的
  真实动捕输入 —— 它当初挂起就是因为"票面要的动捕包从来没录过"，现在四份都有了，
  够不够当它的输入**由操作者裁定**）与
  [ticket 10](../.scratch/phase2/issues/10-param-measure-backfill.md)（从真机悬停 ulog 反推
  `hover_thrust`）。
